## 修复桌面部署脚本 `k-coder-build-deploy.bat`（用户报「执行报错」）

- 症状：`[4/4] Copying runtime files...` 阶段报 `错误 2 (0x00000002) 正在访问源目录 ...\src-tauri\target\release\resources\` → `robocopy exit code 16` → BUILD/DEPLOY FAILED；控制台顶部另有 2 行乱码「不是内部或外部命令」。
- 根因一（致命）：拷贝循环 `for %%D in (skills tools ocr resources)` 里的 `resources` 是**不存在的目标目录**。`tauri.conf.json` 的 `bundle.resources` 只映射到 `skills/`、`tools/`、`ocr/`（查过全历史，从未有过 `resources/`）；robocopy 对缺失源目录返回 16，而脚本把 `errorlevel 8` 当致命错误。exe 与前三项其实已拷贝成功，只有最后这项把整个部署判失败。
- 根因二（噪音）：脚本用 UTF-8 保存中文 `rem` 注释，cmd 以 cp936 读 .bat → 注释被错误解码后泄漏成假命令报错。
- 改动（同时改了桌面副本与仓库 `scripts/` 副本，两份内容一致）：全部注释改英文保持**纯 ASCII**；拷贝循环改为「缺目录只告警不失败」；新增 `KC_REPO` 覆盖（与既有 `KC_DEST` 对称）；失败时 `exit /b 1`（原来恒返回 0）。
- 顺带发现：仓库那份的 `REPO`/`DEST` 是旧布局（`D:\code\k-coder`、`E:\Program Files\k-coder`），已统一为 `D:\code\Nick\k-coder` + `D:\apps\k-coder`。
- 验证限制：**沙箱内无法执行 .bat**（Bash 与 PowerShell 工具都拦 cmd.exe，`dangerouslyDisableSandbox` 也被拦），所以只做了静态校验（纯 ASCII/CRLF/标签-goto 闭合/括号）+ robocopy 退出码直测（存在目录=1 通过，缺失目录=16）。实际跑通需用户双击确认。
