## git pull 后本地分支引用丢失的修复（codex/robot-workflow-skills）

- 现象：`git pull --ff-only origin codex/robot-workflow-skills` 执行成功（reflog 记录了 74c88ae → 1318fa5 的 Fast-forward），但随后 `git status` 报 "No commits yet"，`refs/heads/codex/...` 与 `refs/remotes/origin/codex/...` 都不存在，索引里所有文件变成待新增（A）。
- 根因：git 自身无法在本机创建嵌套引用目录（`.git/refs/heads/codex/`、`.../origin/codex/`），`git update-ref` / `git fetch` 静默失败（退出码 0 但不落盘）。
- 修复：手动 `mkdir -p .git/refs/{heads,remotes/origin}/codex` 并写入目标 SHA 到 `robot-workflow-skills` 文件，引用即恢复；随后 `git status` 干净、`git status -sb` 显示与远端同步。
- 复核要点：恢复后 `git status --short` 为空、`git log -1` = 1318fa5（卡片布局 8px 间距）。
- 另注：最后一次 `git fetch origin` 偶发 403（GitHub 侧限流/凭据），不影响本地已恢复状态。

## 环境补充：Git Bash 下 `pnpm` 不可用的真实原因（修正前文）

- 现象：`pnpm tauri dev` 报 `Cannot find module 'D:\c\Users\mhke\AppData\Local\nodejs\...\corepack\dist\pnpm.js'`。
- 真实原因**不是 corepack 链接损坏**，而是 `pnpm` 是 POSIX sh 脚本，内部 `exec node "$basedir/node_modules/corepack/dist/pnpm.js"` 把 MSYS 风格路径 `/c/Users/...` 直接交给原生 `node.exe`，Windows 把它解析成驱动器相对路径 `D:\c\Users\...`。
- 可用写法：用 Windows 风格路径调用，例如
  `node "C:/Users/mhke/AppData/Local/nodejs/node-v22.14.0-win-x64/node_modules/corepack/dist/pnpm.js" build`（pnpm 11.18.0）。
- `pnpm tauri dev` 也可以改用 `node node_modules/@tauri-apps/cli/tauri.js dev` 启动：Tauri 的 `beforeDevCommand` 走 `cmd.exe`，`pnpm.CMD` 能被正确解析，不会踩上面的路径问题。

## P10-189 会话区「回到底部」悬浮按钮（前端展示层）

- 改动：`src/App.tsx` 新增 `scrollToBottomVisible` 状态 + `scrollConversationToBottom()`；`handleScroll` 用 `atLatestContent()`（距底 ≤48px）同时决定 `followLatestRef` 与按钮显隐；`wheel`/`pointerdown`/`touchstart` 的暂停语义、rAF 前复查一律未动。按钮渲染在 `.message-area` 末尾，`hasConversationContent && scrollToBottomVisible` 才挂载。`src/App.css` 新增 `.scroll-to-bottom-dock`（`position: sticky; bottom: 0; height: 0`）与 `.scroll-to-bottom-button`（32px 圆形，`transform: translateY(-100%)` 抬起）+ 入场关键帧。
- **关键坑（可复用）**：带 padding 的滚动容器里，`position: sticky` 的「sticky view rectangle」底边是**内容盒底边**，不是 padding box 底边 —— 实测 `.message-area--populated`（`padding: 28px 0 24px`）下 `bottom: 0` 的停靠点停在可视底边上方 **24px**（= padding-bottom）。所以「按钮离面板底边 16px」这种写法要额外减掉 padding，别按 padding box 推算。
- 零高度停靠点 + `transform` 抬起的组合可以做到「显隐完全不改变 `scrollHeight`」，避免按钮出现/消失把内容顶动；e2e 里用 `dock.getBoundingClientRect().height === 0` 把这条约束钉住。
- **e2e 坑**：想模拟「用户离开最新内容」必须派发 `WheelEvent("wheel", { deltaY: -160 })`，只改 `scrollTop` + 派发 `scroll` 事件**不够** —— `handleScroll` 只会在贴底时把 `followLatest` 置 true、从不置 false，于是 ResizeObserver 的 `scrollToLatest` 会在内容继续增长时把视口拉回底部（表现为 Playwright 报 `element is not stable` / `element was detached from the DOM`）。同文件既有跟随用例早就这么写了，照抄即可。

## 本机环境补充：跑 Playwright 全量套件会被 safe-delete shim 卡住

- 现象：`node node_modules/@playwright/test/cli.js test e2e/workbench.spec.ts` 一启动就失败，报 `[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED] {"count":72,"threshold":50,"scope":"turn","targets":["D:\\code\\k-coder\\test-results"]}`。Playwright 每次运行前会清空 `test-results/`，条目超过 50 就被本机的 safe-delete shim 拦下。
- 解法：加 `--output=.workbuddy-ai/pw-out`（指向一个新的空目录），Playwright 就不再动 `test-results/`。
- 另：`reuseExistingServer: true`，所以先自己 `node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 1420` 起开发服务更可控（`playwright.config.ts` 的 webServer 走 `pnpm dev`，本机 pnpm 在 Git Bash 下不可用）。
