# 测试执行报告

## 概述

生成当前仓库的测试执行与验证报告。本技能仅聚焦构建和测试执行状态（通过/失败/跳过/警告/错误）与日志分析；除非用户明确要求，否则不输出代码评审或静态分析建议。默认以缺陷分析为主，统计数据用于辅助说明。

## 工作流

1. **收集上下文**：定位测试项目、解决方案配置与测试说明（如 `README.md`、`AGENTS.md`）。
2. **执行构建与测试**：按合适范围执行 `dotnet test`、`npm test`、`pytest` 等命令。
3. **解析并分类失败**：提取总数/通过/失败/跳过，并按失败类型归类。
4. **输出结构化报告**：按照模板生成测试报告。

## 步骤 1：收集上下文

- 执行 `git status -sb` 与 `git diff --stat`，判断改动范围及受影响测试面。
- 定位仓库中的测试项目和测试套件。
- 选择最合适的验证范围：
  - 仅受影响模块（快速）
  - 全量测试
  - 若环境阻塞严重，则退化为仅构建验证并明确说明原因。

## 步骤 2：执行测试命令

- 根据技术栈选择命令：
  - **.NET**：`dotnet build`、`dotnet test`、`dotnet test --filter ...`
  - **Node**：`npm test`、`pnpm test`
  - **Python**：`pytest`、`unittest`
- 必须记录：
  - 实际执行命令
  - 失败详情（错误信息、堆栈）
  - 执行耗时

## 步骤 3：失败分类

将失败归入以下类别：
- **代码缺陷**：业务逻辑或断言不符合预期。
- **环境/基础设施阻塞**：端口占用、缺少环境变量、数据库或外部服务不可达。
- **测试代码问题**：测试夹具问题、Mock 失效、时序不稳定等。

并提取失败用例的类名、方法名、相关文件和行号（如果日志可得）。

## 步骤 4：输出测试报告

- 使用 [references/report-template.md](references/report-template.md) 模板。
- 优先给出失败用例、错误摘要、根因分类与处理建议；总览指标作为辅助信息。
- 对每个失败用例给出错误摘要和根因分类。
- 给出未覆盖范围、剩余风险与后续执行建议。

## 输出规则

- **默认不输出代码评审建议**（SOLID、架构重构、代码风格等），除非用户明确提出。
- **准确归因**：环境问题不得误判为代码缺陷。
- **缺陷优先**：报告核心是失败用例和根因分析；`bug数` 非必填，只有在用户明确要求时才单独输出。
- **语言规则（强制）**：
  - 报告标题、字段名、说明文字、分析结论必须使用中文。
  - 代码块、命令、路径、测试方法名、异常原文、堆栈信息保持原样，不做翻译。
