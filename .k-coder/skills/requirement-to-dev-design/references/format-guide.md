# 钉钉详细设计文档格式规范（对齐模板 1.7.2）

生成开发设计时，**正文 Markdown 必须与钉钉模板 `qnYMoO1rWxDlAnXpc3AwgNEnW47Z3je9` 渲染样式一致**。本地 `.md` 与钉钉文档使用同一套正文。

## 1. 文档标题

| 位置 | 格式 | 示例 |
|------|------|------|
| 钉钉文档名（`create_document.name`） | `<主题>开发设计` | `入职流程改进-业务流程信息变更提效开发设计` |
| **正文** | **不要**写 `# 【开发设计】...` 或任何一级标题作文档名 | 正文从保密信息块开始 |

## 2. 保密信息块（正文开头，固定顺序）

**禁止使用** `_**保密级别...**_` 等 Markdown 斜体。

必须使用钉钉 HTML 样式（红色 `rgb(216, 57, 49)`）：

```markdown
<span style="color: rgb(216, 57, 49);">***保密级别：内部资料***</span>

<span style="color: rgb(216, 57, 49);">***信息所有者：集团技术研究院***</span>

<span style="color: rgb(216, 57, 49);">***知悉范围：软通动力集团***</span>

<span style="color: rgb(216, 57, 49);">***保密期限：永久***</span>

| <span style="background-color: rgb(255, 245, 235);">**保密声明：本文件是软通动力的保密信息，仅限上面知悉范围内的个人或组织使用。非此知悉范围的任何个人或组织，请勿进行查阅、复制、扩散等任何操作，否则会根据其产生的影响追究法律责任。**</span> |
| --- |

---
```

- `信息所有者` 默认「集团技术研究院」，用户指定时替换。
- 保密声明表格第二行仅 `| --- |`，与模板一致。

## 3. 变更记录

```markdown
# 变更记录

| **序号** | **版本** | **变更说明** | **修改人/日期** | **检查人/日期** | **审批人/日期** |
|----------|----------|----------------|--------------------|--------------------|--------------------|
| 1 | 1.0 | 创建 | <姓名>/<日期> |  |  |
```

- 首版变更说明：`创建` 或 `根据《<需求标题>》需求文档创建`。
- 覆盖更新时在表末追加一行，版本递增。

## 4. 章节标题（加粗）

所有章节标题用 `**` 包裹，与模板一致：

| 级别 | 格式 | 示例 |
|------|------|------|
| 一级 | `# **N、 章节名**` | `# **1、 设计概述**` |
| 二级 | `## **N.M 章节名**` | `## **1.1 运行环境**` |
| 三级 | `### **N.M.K 章节名**` | `### **3.3.1 功能点清单**` |
| 四级 | `#### 特性设计` | 四级以下可不加粗（与模板一致） |

注意：`1.3` 与「架构」之间模板为 **两个空格**：`## **1.3  架构设计方案**`。

## 5. 提示块与占位

- 填充完成后 **删除** 所有 `:::...:::` 提示块。
- 模板中的蓝色示例文字（`<span style="color: #0071C1;">`）在正式文档中替换为真实内容，不保留蓝色 span。

## 6. 表格

钉钉模板存在 **多种表格样式**，Markdown 写法与块级填充方式不同。**禁止**用统一 `| --- | --- | --- |` 写法应付所有表格。

### 6.1 表格类型（对齐模板 1.7.2）

| 类型 | 适用章节 | 表头写法 | 分隔行写法 | 钉钉渲染 |
|------|----------|----------|------------|----------|
| **A 变更记录** | `# 变更记录` | `\| **序号** \| **版本** \| ...` | `\|----------\|----------\|...\|`（无空格，6 列） | 深色表头、全边框、全宽 |
| **B 环境清单** | `1.1 运行环境` | `\| 序号 \| 项目 \| 详细信息 \|`（**不加粗**） | `\|------\|------\|------------\|` | 浅灰表头、仅横线、全宽 |
| **C 正文表格** | 2.7、2.8、3.3.2、特性设计等 | `\| **类别** \| **分析** \|` | `\|----------\|-----------\|` | 浅灰表头、全宽 |
| **D 功能清单** | `3.3.1 功能点清单` | 表头用灰色背景 span（见下） | 同 C | 灰底表头 |
| **E 保密声明** | 正文开头 | 单列 orange span | `\| --- \|` | 橙色背景 |

**3.3.1 功能清单表头示例**：

```markdown
| <span style="background-color: rgb(225, 230, 237);">系统&模块</span> | <span style="background-color: rgb(225, 230, 237);">功能</span> | <span style="background-color: rgb(225, 230, 237);">接口/服务名称</span> | <span style="background-color: rgb(225, 230, 237);">功能描述</span> | <span style="background-color: rgb(225, 230, 237);">负责人</span> |
| --- | --- | --- | --- | --- |
```

### 6.2 分隔行规范

- **禁止**所有表格统一用 `| --- | --- | --- |`（带空格的三短横线）
- 变更记录：` |----------|----------|----------------|--------------------|--------------------|--------------------| `
- 1.1 环境：`|------|------|------------|`
- 正文双列：`|----------|-----------|`
- 列数、列名与模板保持一致，不擅自改列

### 6.3 钉钉写入与表格（重要）

Markdown 表格语法**无法**通过 MCP 原地修改原生 table 块（`update_document_block` 不支持 table）。

写入钉钉时必须：

1. `copy_document` 复制模板（保留页面宽度与未改动的原生块）
2. 段落/标题 → `update_document_block`
3. 表格 → `delete_document_block` + `update_document`(append, index=原index) 插入 **§6.1 对应类型** Markdown
4. **禁止** `overwrite` 整篇

变更记录深色表头：优先**保留** index 8 原块，提示用户钉钉 UI 手工改行。

详见 [block-fill-guide.md](block-fill-guide.md)。

## 7. 本地与钉钉双写

| 项 | 约定 |
|----|------|
| 本地路径 | `D:\1.CursorProject\文档\<项目>\02-技术文档\<主题>开发设计.md` |
| 本地编码 | UTF-8（无 BOM） |
| 钉钉新建 | `copy_document` → `rename` → 块级填充（段落 update_block；表格 delete+append） |
| 钉钉更新 | `list_document_blocks` → 同上；**禁止 overwrite** |
| 大文档 | append 单段 ≤10000 字符 |

- [ ] `# 1`～`# 7` 一级标题均为 `# **N、 ...**` 格式
- [ ] 无残留 `:::` 提示块
- [ ] 变更记录表结构正确
- [ ] 表格分隔行符合 6.1 类型（变更记录用 `|----------|`，1.1 用 `|------|`，非统一 `| --- |`）
- [ ] 1.1 运行环境表头**不加粗**
- [ ] 钉钉写入未使用整篇 overwrite；表格经 delete+append（§6.1 格式）
