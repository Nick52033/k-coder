# Bug 修复处理文档模板

保存路径：`{仓库}/docs/lessons/zentao-bugs/zentao-bug-{id}-{slug}.md`

---

```markdown
# 禅道 Bug #{id}：{标题}

| 字段 | 值 |
|------|-----|
| 状态 | 待确认 |
| 禅道链接 | https://zentao.isscloud.com/bug-view-{id}.html |
| 产品 | {product} |
| 模块 | {module} |
| 严重程度 | {severity 标签} |
| 优先级 | {pri 标签} |
| 指派人 | {assignedTo} |
| 目标仓库 | {repo 路径} |
| 创建时间 | {文档生成日期 YYYY-MM-DD} |

## Bug 描述

{从禅道 steps / 标题整理的纯文本描述}

### 重现步骤

1. {步骤1}
2. {步骤2}

### 预期 vs 实际

- **预期**：{...}
- **实际**：{...}

## 知识库检索

| 来源 | 路径 | 相关性 |
|------|------|--------|
| docs/lessons | {路径或「无」} | {说明} |
| 项目文档 | D:\1.CursorProject\文档\... | {说明} |

## 代码定位

### 疑似相关文件

| 文件 | 说明 | 置信度 |
|------|------|--------|
| `path/to/file` | {为何相关} | 高/中/低 |

### 调用链分析（简述）

{从入口到问题的链路，可用文字或 mermaid}

### 根因假设

{当前最可能的原因，区分「已验证」与「待验证」}

## 建议改动

### 改动清单

| # | 文件 | 改动类型 | 说明 |
|---|------|----------|------|
| 1 | `path/to/file` | 修改 | {改什么} |

### 伪代码 / 关键片段（可选）

```{lang}
// 建议修改方向，非最终代码
```

### 影响范围

- {受影响功能、接口、页面}
- {回归关注点}

## 测试计划

- [ ] {测试用例1}
- [ ] {测试用例2}
- [ ] 边界：{空值/权限/并发等}

## 风险与待确认项

- [ ] {需产品/业务确认的点}
- [ ] {技术不确定点}

## 修复记录（确认后填写）

| 字段 | 值 |
|------|-----|
| 状态 | 修复中 / 已修复待验证 / 已解决 |
| 实际改动 | {commit 或文件列表} |
| 测试结果 | {通过/失败及命令} |
| 备注 | {禅道备注内容摘要} |

---

**人工确认**：审阅后回复「确认修复」开始改代码；回复「修改方案」并说明意见。
```

## 填写要求

- `状态` 初始必须为 **待确认**
- 根因写不清时诚实标注「待验证」，不编造
- `建议改动` 须具体到文件级；无把握时列候选并标置信度
- 用户要求调整方案时更新本文档，状态保持待确认直至用户确认
