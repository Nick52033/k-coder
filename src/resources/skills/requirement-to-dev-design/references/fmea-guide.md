## 1. 何时必须写（几乎总是）

| 场景 | 最低行数 | 说明 |
|------|----------|------|
| 有外部接口（SAP/BPM/财务/短信等） | ≥ 外部接口数 + 1 | 每个外部依赖至少 1 行失效模式 |
| 有金额/工资/欠款计算 | ≥ 计算链路各 1 行 | 公式错误、精度、边界 |
| 有敏感数据（工资/证件/PII） | ≥ 1 行专项 | 泄露、越权、日志/落库 |
| 有定时/批处理 | ≥ 1 行 | 任务失败、积压、补偿 |
| 纯 UI 规则增强（如 ipsa-rra） | ≥ 3.3.1 每个功能点 1 行 | 校验误判、联动错误 |
| 重构/迁移 | ≥ 新旧系统各 1 行 + 流程 1 行 | 数据不一致、审批中断 |

**唯一可写「不涉及」**：纯文案/菜单改名、无任何业务规则与接口变更的极小改动——需在 3.2 说明理由。

```

[严重度/频度/探测度 5 级评估法说明 — 三句话，沿用模板]

| --- | ... |

[总结段 1：风险集中在哪几类，点名 TOP3 高风险场景]
```

## 3. 表格列填写要点

| 列 | 写法 |
|----|------|
| **系统&组件** | 与 3.3.1 模块名一致（测算引擎、对账服务、入职申请页面…） |
| **功能** | 具体功能点（Excel 导入、SAP 工资项调用、证件格式校验…） |
| **失效后果** | 业务后果（财务损失、员工投诉、无法入职、数据泄露…），勿写「报错」 |
| **失效模式** | 怎么坏的（超时、校验通过但数据错、误判跳过…） |
| **失效原因** | 根因（规则不完善、SAP 未配置、并发无锁…） |
| **风险顺序** | 严重度×频度×探测度（三数相乘，如 5×3×4=60） |
| **当前控制** | **本期设计已有**措施（校验、重试、加密、权限、日志） |
| **建议措施** | 增强项或上线前必做（抽样核对、熔断、专项测试） |
| **严重度/频度/探测度** | 1～5 整数，高风险通常 S≥4 |
| **后续规划** | 「已规划：xxx」或「本期实现：xxx」 |

## 4. 必须覆盖的风险类型（按需求勾选）

生成前从需求勾选，**每类至少 1 行**（适用则写）：

- [ ] **规则/配置错误**：导入、字典、版本、匹配逻辑
- [ ] **外部依赖不稳定**：SAP/BPM/财务/短信/钉钉 超时、限流、契约未就绪
- [ ] **敏感数据**：工资/证件/金额 — 越权、日志泄露、明文落库、页面暴露
- [ ] **计算/金额错误**：公式、边界、精度、对账匹配误判
- [ ] **人工操作差错**：误确认、误导入、二次确认缺失
- [ ] **权限/隔离**：跨部门数据、接口越权
- [ ] **定时/批处理**：任务失败、积压、无补偿
- [ ] **并发/一致性**：重复单号、版本冲突、写入失败

## 5. 总结段模板（生成时改写，勿原样复制）

**段 1 — 风险主线**

> 总结：经本次 FMEA 分析，系统风险主要集中在 {A}、{B}、{C}、{D} 四个方面。其中，{高风险场景1}、{高风险场景2}、{高风险场景3} 是本期需重点关注的高风险场景。

**段 2 — 控制策略**

> 针对上述风险，控制思路应统一覆盖「事前预防、事中探测、事后补偿」：事前通过 {校验/权限/加密…} 降低发生概率；事中通过 {日志/告警/抽检…} 提升发现能力；事后通过 {重试/补偿/人工复核…} 控制影响范围。

**段 3 — 上线复核（有敏感数据或外部依赖时必写）**

> 上线前需完成高风险项专项复核，确认 {具体检查项1}、{具体检查项2}… 可执行。

## 8. 反例（评审会打回）

| 反例 | 问题 |
