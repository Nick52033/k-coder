## 按章填充要点

### 第 1 章 设计概述

- **1.1**：从目标仓库 `CLAUDE.md`/`AGENTS.md`、启动配置、Dockerfile 读取真实技术栈
- **1.2**：需求链接 + 200 字内背景/目标摘要；多需求文档时列出全部来源
- **1.3**：沿用项目既有分层（Domain/Application/HttpApi 或 WebForms 等），不另起架构

### 第 2 章 总体方案

- **2.1**：语言、框架、本需求涉及的关联服务（SAP/BPM/PSA 等）
- **2.2～2.6**：有则详写，无则「不涉及」或文字化描述（WebForms 项目常用文字 DFD）
- **2.7**：是否灰度、对存量数据/流程的影响；规则增强类写**触发条件**（如「仅某业务条件下生效」）
- **2.8**：从需求中的触发条件、定时任务、审批节点提炼；**每行含量化触发频率**（次/日/月/cron）；≥3 行
- **2.9**：ToB 内部系统通常写「客户：不涉及」，业务线填实际部门
- **2.10 故障分析（FMEA，开发经理评审重点）** — 细则见 [fmea-guide.md](fmea-guide.md)：
  - 表体行数 ≥ max(3, 3.3.1 模块数)；每个外部依赖、金额/工资计算、敏感数据至少 1 行
  - 12 列表格填满（系统&组件、功能、失效后果/模式/原因、风险顺序、当前控制、建议措施、S/F/D、后续规划）
  - 文末 **≥2 段总结**：风险主线 + TOP3 高风险；事前/事中/事后控制；有敏感/外部依赖时加「上线前专项复核」
  - 与 2.8「风险识别」、3.3 特性设计、6.3 安全保持一致
  - **禁止**全章「不涉及」或仅 1 行笼统描述

### 第 3 章 系统详细设计

- **3.1**：需求功能编号 → 设计编号，保持可追溯；**重构类**写效益量化（处理时长、人天、成本）
- **3.2**：明确本期剪裁、Mock/桩接口、**二期内容**（评审高频：勿把二期写进 7.2 本期接口）
- **3.3.1**：一行一接口/服务，与 7.2 接口名一致；**外部依赖**列负责人/预计就绪时间；代码已有标「已实现/沿用」
- **3.3.2**：跨库表汇总（含只读的外部库）
- **3.3.3+**：每个功能点独立一节；**设计细节首段**写「现状 → 目标 → 影响范围」；含特性设计九项、设计细节、库表 DDL（新增表时给完整 CREATE）

**特性设计九项默认策略（ABP/.NET 项目）：**

| 特性 | 常见写法 |
|------|----------|
| 性能设计 | 分页、索引、异步任务、批量上限 |
| 安全设计 | PSA JWT、菜单+数据权限、参数校验 |
| 隐私设计 | 最小收集、脱敏、加密存储（IStringEncryptionHelper） |
| 不中断设计 | 降级、重试、补偿 |
| 人因差错设计 | 二次确认、Excel 行列级错误提示 |
| 过载设计 | 限流、队列、单次条数上限 |
| 预防设计 | 幂等键、前置校验 |
| 冗余设计 | 多实例、备份、重试队列 |
| 配置化设计 | appsettings、字典表 |

### 第 4 章 事件分析

- 有历史数据：写 SQL 或引用统计表
- 无数据：按需求估算量级，标注「预估，待上线后校准」

### 第 5 章 日志要求

- 列出本模块关键场景（导入、外部调用、核心业务、权限失败）
- 敏感字段脱敏规则与项目一致

### 第 6 章 安全设计

- 网关地址从项目 appsettings 或既有设计文档复制
- 角色表与需求中的岗位/菜单对应
- 涉及 PII/金额：对照 6.3 四项检查

### 第 7 章 接口设计

- 每个 3.3.1 中的接口在 7.2.2 有对应条目（**含列表查询、Excel 导出、报表统计**——漏项是常见评审意见）
- 地址格式：`{网关前缀}/{Controller}/{Action}`
- 入参/出参用 JSON 示例；外部接口标注提供方、负责人、Mock 策略与预计就绪时间
- **7.2.1** 错误码按模块分子节，与 3.3.1 模块划分一致
- 定时任务入 7.3，含 ApiKey/调度表达式
