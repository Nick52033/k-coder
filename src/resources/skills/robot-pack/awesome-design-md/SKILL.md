# Interface Design Specification

Document the target users, jobs, information hierarchy, navigation, screens, component responsibilities, states, responsive behavior, accessibility, content, and acceptance criteria. Use compact tables or Mermaid only when relationships are easier to inspect visually.

Tie every element to a workflow or requirement. Specify real controls, validation, loading, empty, failure, cancellation, and recovery behavior. Reuse the repository's design system and avoid prescribing unsupported libraries. Keep Markdown under the repository documentation convention and do not create a prototype until the host workflow reaches that step.
