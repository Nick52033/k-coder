# Requirements Intake

Extract five dimensions from the request and inspected evidence: problem and goal, target users, essential capabilities, constraints and exclusions, and success criteria. Separate Fact, Assumption, Risk, Decision needed, and Out of scope.

Ask one high-value question at a time only when the answer materially changes behavior. Prefer concrete choices and explain their impact. Preserve the user's terminology while defining ambiguous terms. Record source locations for repository facts and never present an inference as confirmed behavior.

The deliverable is a concise intake record that later workflow steps can trace. Do not implement code or publish documents during intake unless the host workflow explicitly advances to such a node.
