# 机器人节点技能绑定讨论纪要

- 日期：2026-09-08
- 参与者：Nick、CodeBuddy（Claude）
- 产出物：[ADR 0055](adr/0055-robot-node-skill-binding.md)、[机器人工作流设计.md 第 10 节](机器人工作流设计.md)
- 状态：设计已定稿并落盘；实现未开始

## 1. 讨论背景

从"k-Coder 内置机器人怎么用、原理是什么"出发，逐步深入到机器人驱动力不足的问题，最终形成 ADR 0055 设计。全程以两侧代码取证为准，不凭文档印象下结论。

## 2. 问题演进与关键发现

### 2.1 k-Coder 机器人现状（起步认知）

- 内置机器人是主 `AgentRuntime` 上的受限工作流（ADR 0039），定义编译在 `advanced/workflow.rs`，节点推进只认 `complete_workflow_node` 工具，状态以追加式 JSONL 快照持久化。
- 每轮 `runtime_instructions` 真实注入 `role_prompt` + 目标 + 全部节点 + 当前节点 `instructions`/`completion_criteria`（有测试断言）。
- 初始结论：机器人**不会自动调 Skill**——`workflow.rs` 零 skill 引用，Skill 走独立的触发词通道（`extensions/mod.rs` 的 `skill_is_selected`：显式 `/名字` 或触发词子串匹配）。

### 2.2 用户质疑：cn-codex 机器人有工作流步骤 + 对应 skills，光靠 prompt 不够

对 `D:\code\Nick\cn-codex` 取证，确认：

- `codey/robots/<id>/robot.json` 的 `workflowNodes[]` 每节点显式绑定 `skills`（本地）+ `pluginSkills`（插件），如 qa-test-bot 的 7 个节点分别绑定 test-strategy-planning、test-case-design、api-testing 等。
- `robot_loader.rs` 的 `collect_robot_node_skill_contents(dir, config, node_index)` 按**节点索引**收集 SKILL.md 正文。
- `robot_orchestrator.rs` 的 `build_overlay_prompt` 每次请求注入：根目标、节点进度（[DONE]/[CURRENT]/[PENDING]）、当前节点目标、当前节点技能 ID 列表 + **SKILL.md 正文（单技能截断 8000 字符）**、严格推进约束 + `<workflow_node_done/>` 哨兵。

### 2.3 重要实锤：cn-codex 的角色 systemPrompt 存而未注入

用户贴出 robot.json 中数千字的角色提示词（三机器人各自的完整角色定义），质疑驱动机制。追加取证结果：

- `overlay_prompt_does_not_include_robot_system_prompt` 测试**明确断言** systemPrompt 不进 overlay；
- `build_system_prompt` 在 goal+robot 模式构建的是通用 Codey 提示词，`read_robot` 在 `agent.rs` 只用于 robot-modify 模式；
- 前端唯一消费点是设置页 `RobotsPanel.tsx` 的只读展示。

结论：那大段提示词是"机器人说明书"，**运行时死数据**。这正是 ADR 0039 背景"角色 prompt 可能只存储而没有实际注入"批评的实锤。k-Coder 的 `runtime_instructions` 已真实注入角色与节点指令，此点已领先 cn-codex，不需要对齐。

### 2.4 k-Coder 的真实差距

只有一项：**节点级技能正文绑定**。其他方面（结构化工具推进 vs 哨兵标记、角色真实注入）k-Coder 均为正确取舍，不回退。

## 3. 设计决策（ADR 0055 摘要）

1. `WorkflowNodeDefinition` 增加可选 `skills` 字段，经"内置 → 全局 → 项目"三层解析；绑定属编译期定义，`workflows.jsonl` 快照无需迁移。
2. 节点激活时宿主读取绑定技能 SKILL.md 正文，以 `[Workflow Skill: <name>]` 分节注入受控运行时指令；每节点最多 4 个技能、单技能 16 KiB、合计 48 KiB。
3. `risk: read` 直接注入；`write`/`external` 须已启用，未启用仅注入占位声明。缺失走跳过 + 审计降级；内置定义绑定在启动时校验，缺失则扩展运行时关闭失败（防静默退化）。
4. 技能正文只进 Provider 请求：不写 JSONL、不进界面/日志、不改 `PolicyEngine` 决策、不自动启用 MCP/Hook/子智能体。
5. 技能存放采用**方案 A**：新建 `src/resources/skills/robot-pack/` 分组目录 + `discover_skills` 扩展支持一级分组（深度 2）+ 同作用域重名检测（现状静默覆盖）。分组是必要的，因为发现逻辑只扫直接子目录，二级嵌套会被静默忽略。

## 4. 绑定表推导方法（可复用的方法论）

三步法：

1. **cn-codex robot.json** 提供"每个节点需要什么能力"的参考答案（经过实际使用打磨）；
2. **k-Coder 技能库逐个核对**：读各 SKILL.md 的 `description` 匹配，技能 ID 不照搬；
3. **对不上的标为缺口**（新建/重写候选），不硬凑。

过程中发现并修正的错配：`requirement-to-dev-design` 实为公司钉钉模板专用技能（模板 1.7.2、FMEA、开发经理评审门禁、external 风险），不适合绑到通用"方案与计划/需求澄清/详细设计"节点，全部撤回。教训：**绑定前必须核对技能正文的适用范围，不能只看名字**。此类公司业务技能（含 `third-party-interface-spec`、`zentao-bug-fix`）更适合未来做成独立机器人。

## 5. 准入判据与排除清单（均有取证）

**唯一判据：SKILL.md 正文会被宿主注入为高权重指令，正文引用的每个工具必须存在于 k-Coder 工具注册表**——注入教模型调用不存在工具的正文 = 主动制造"调用→失败→重试→再失败"死循环。

取证修正了两处早期误判：

- `api-testing`/`performance-testing`/`security-testing`：全文搜索 shell/browser_run 等零命中，**纯方法论，可直签复制**（早期误判为需改写）；
- `dingtalk-document`：走 `bash scripts/dt_helper.sh` + curl，k-Coder `run_command` 可执行，**可带脚本复制**（`risk: external`，复制前人工检查脚本无硬编码凭据）。

确认排除（5 个）：`webapp-testing`（browser_run/exec_command/write_stdin）、`control-in-app-browser`（mcp__node_repl__js + browser-client.mjs）、`dispatching-parallel-agents`（Claude Code `Task()` 模式）、`subagent-driven-development`（同目录 prompt 文件 + Claude Code 工具名）、`documents`（容器脚本链路，未验完）。

## 6. 浏览器工具面差距（webapp-testing 重写的前置发现）

- cn-codex：单复合工具 `browser_run`（28 种动作批量执行，含 `eval` 页面内 JS），输出截断 16,000 字符，外部浏览器 CDP 回退链。
- k-Coder：6 个独立工具（`browser_navigate/click/type/snapshot/screenshot/close`），**无 `eval`** → 无法复刻"注入控制台捕获脚本→回读 JS 错误"的 E2E 门控。
- 弥补：P0 前置增强——`advanced/browser.rs` 订阅 CDP `Runtime.consoleAPICalled` / `Log.entryAdded`，新增 `browser_console` 工具（有界缓冲）；就位前重写版降级为"snapshot + 截图 + 接口响应判断"门控。

## 9. 经验沉淀

- **两侧代码取证优于文档陈述**：cn-codex 文档与 robot.json 展示的机制（大段 systemPrompt）与运行时真实行为（不注入）不符，测试代码才是一锤定音的证据。
- **技能绑定不能只看名字**：必须核对正文引用的工具与适用范围，本次 `requirement-to-dev-design` 错配即由此发现。
- **存量平台的"看似缺失"先查实现再下结论**：k-Coder 的角色注入其实已领先 cn-codex，差距只在技能绑定一环。
