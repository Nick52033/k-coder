# 深色模式会话背景可读性优化验证

- 日期：2026-09-17
- 触发：用户提供深色模式截图，反馈「字体看不清，为啥是绿色」，要求按 UI skill 优化。
- 结论：不是主题色的问题，而是**会话背景模式（`.workbench--background`）把「浅色色调专用」的墨色与面板不透明度套用到了深色色调**。深色下正文被算成 `#3f4a44`（偏绿的深灰），压在约 `#475059` 的合成底上只有 **1.13:1**，等于看不见，同时整屏被内置浅绿背景图染色。

改动停留在工作区，未提交、未推送、未部署。

## 一、先确认「绿色」从哪来

对用户截图（1080×684）逐点采样，而不是凭肉眼判断：

| 检查 | 结果 |
| --- | --- |
| 全帧偏绿像素（`G−R>12` 且 `G−B>12`） | **0** / 738,720 |
| 全帧偏蓝像素（`B−R>12` 且 `B−G>12`） | 479,572（65%） |
| PNG 色彩块 | 无 `iCCP`/`gAMA`/`cHRM`/`sRGB`，不存在色彩配置导致的偏色 |
| 会话区底色主色 | `#171723`、`#141420`（靛蓝色族，`B−R` 为 +10~+19） |

即：主题本身仍是「靛蓝夜航」，没有绿色像素。真正的绿色来自**被当作正文用的那三档墨色**——把 `G ≥ R 且 G ≥ B` 的像素挑出来，命中集合恰好是 `#454E4D`、`#46514B`、`#47504F`、`#404948`，与 `App.css` 里 `.workbench--background` 写死的 `--color-ink-subtle: #46514b` 逐位吻合（±1~3）。所以「为啥是绿色」的答案是：那几行文字就是绿灰色的。

## 二、根因

`src/App.css` 的 `.workbench--background` 有三层假设，只在**浅色色调**下成立：

1. **墨色覆盖是浅色专用的。** 它把 `--color-ink-muted/-subtle/-faint` 覆盖成 `#3f4a44`/`#46514b`/`#6b756f`——三档都比任何深色中性面更暗、且色相偏绿。深色色调下沿用等于把次要文字抹掉。
2. **「白纱」方向反了。** `::before` 用 `--color-surface` 按 `--background-opacity` 铺纱；`--color-surface` 在深色主题里是暗的，而 `public/chat-background.png` 是**给浅色色调设计的浅雾绿展示图**（`scripts/make-background.cjs`：亮度约 130–250，配色为「低饱和雾绿 / 灰蓝 / 暖砂」）。深色下等于用一层薄纱去挡一张比文字亮得多的图。
3. **面板不透明度是照浅色调定的。** `.workbench--background .conversation` 为 `62%`、`.sidebar` 为 `70%`。配合上面两点，正文实际坐在约 **50% 灰**的底上，次要文字必然跌破门槛，同时整屏被雾绿染色。

`docs/阅读层级与回到底部原生验收.md`（2026-09-16）记录当时深色实测为 `会话区 alpha 0.88 / 侧栏 alpha 0.92`；现行 `62% / 70%` 是之后为「让背景真正透出来」下调的，未按深色色调重新核算对比度——这就是本轮回归的来源。

## 三、改动

按色调分流，新增 `data-tone` 作为唯一判据（与 `index.html` 首帧脚本同源，避免首屏闪一下浅色规则）。

| 文件 | 改动 |
| --- | --- |
| `src/lib/theme.ts` | 新增 `DARK_RESOLVED_THEMES`（dark / crt-green / ember / synthwave / terminal）与 `isDarkResolvedTheme()` |
| `index.html` | 首帧脚本同时写 `data-tone`（与既有 `data-boot-tone` 同值） |
| `src/App.tsx` | 主题切换副作用写入 `data-tone` |
| `src/App.css` | 墨色覆盖收窄到 `[data-tone="light"]`；新增深色色调分支：`::before` 加 45% 中性黑纱 + `saturate(.55)`，面板抬回 `conversation 88% / sidebar 92% / composer 90% / titlebar 90% / settings-dialog 92% / settings-navigation 68%`，弹窗遮罩从 24% 抬到 50% |
| `src/components/SettingsDialog.tsx` + `src/App.css` | 设置页背景预览改为只放原图、纱与黑纱交给 `.background-preview::after`，预览与工作区同源合成（此前预览按旧公式画，比真实界面更亮也更绿） |

设计取舍：深色色调不采用「把墨色压深」（深色面上压深等于抹掉文字），而是**先把图压暗、再让面板接近不透明**，这样 `--color-ink-*` 设计令牌继续成立，符合 UI skill 的「语义令牌按主题映射，不在组件里写死十六进制」。内置图在深色下被降饱和，绿色偏色一并消失。

## 四、同环境对照实测

用真实 Chromium 渲染 `tools/ui-harness/ui-harness.html`（背景模式开启、内置背景图、默认可见度 82%），「修复前」用 `theme=dark` + `data-tone=light` 复现旧合成方式。底色取会话区/侧栏空白处的众数颜色，文字色取计算样式（`getComputedStyle`），对比度按 WCAG 相对亮度计算。

| 场景 | 表面 | 有效底色 | 文字 | 对比度 | 门槛 |
| --- | --- | --- | --- | --- | --- |
| 修复前 · 正文 | 会话区 | `#475059` | `#3f4a44` | **1.13:1** ✗ | ≥4.5 |
| 修复前 · 元信息 | 会话区 | `#475059` | `#6b756f` | **1.72:1** ✗ | ≥3 |
| 修复前 · 侧栏 | 侧栏 | `#535A65` | `#46514b` | **1.19:1** ✗ | ≥3 |
| 修复后 · 正文 | 会话区 | `#232432` | `#c2c7dd` | **9.13:1** ✓ | ≥4.5 |
| 修复后 · 强调 | 会话区 | `#232432` | `#e6e8f5` | **12.57:1** ✓ | ≥4.5 |
| 修复后 · 元信息 | 会话区 | `#232432` | `#9ea4bf` | **6.22:1** ✓ | ≥3 |
| 修复后 · 侧栏 | 侧栏 | `#343546` | `#a8aec9` | **5.48:1** ✓ | ≥3 |
| 修复后 · 侧栏元信息 | 侧栏 | `#343546` | `#9ea4bf` | **4.88:1** ✓ | ≥3 |
| 浅色色调 · 正文 | 会话区 | `#E2EBE9` | `#3f4a44` | 7.60:1 ✓ | ≥4.5 |
| 浅色色调 · 元信息 | 会话区 | `#E2EBE9` | `#6b756f` | 3.93:1 ✓（次要） | ≥3 |

计算样式同时确认：`theme=dark` 下 `.workbench` 的 `--color-ink-muted/-subtle/-faint` 已回到主题自身的 `#c2c7dd`/`#a8aec9`/`#9ea4bf`，不再出现浅色调的绿灰三档；正文与输入框占位符的计算色分别为 `rgb(194,199,221)` 与 `rgb(168,174,201)`。`theme=crt-green` 同样落在 `data-tone=dark` 分支（`#78b58b`/`#55916a`），不受影响。

浅色色调的有效底色与文字色逐项与改动前一致（未改其规则），无回归。

## 五、验证

| 检查 | 结果 |
| --- | --- |
| `pnpm build` | 通过；仅保留既有大 chunk 提示 |
| `index.html` / `App.tsx` 的 `data-tone` 来源一致性 | 首帧与运行时同值（同一份深色主题清单） |
| 浏览器取证（Chromium + UI harness，`theme=dark`/`crt-green`/`light` × `data-tone`） | 见上表 |
| 深色色调对任意背景图的兜底 | 以纯白图片做最坏界估算：会话区 `ink-faint` 仍 ≥4.5:1 |

**未做原生验收**：没有启动隔离 `pnpm tauri dev` + WebView2 CDP 做桌面目视确认，因此不得声称桌面工作流已验证。上述实测来自真实 Chromium 渲染的真实组件与真实样式，不等于原生桌面验收。

## 六、已知边界与后续

- `scripts/validate-readability-native.cjs` 里背景模式的断言（`conversationBlur` 含 `blur(12px)`、`conversationAlpha` 0.85–0.91、`sidebarAlpha` 0.89–0.95）在现行 CSS 下已经过期（浅色色调现为 `62%`/`70%`、会话区 blur 为 8px），本轮未改，重跑原生验收时需要按色调重新基线。
- 其余四套深色皮肤（crt-green / ember / synthwave / terminal）的 `--color-ink-faint` 相对各自卡片面只有约 2.0–2.5:1，低于次要文字 3:1 门槛。这是既有缺陷（`docs/深色主题样式对齐验证.md` §8 已记录「其余四套深色皮肤未做同样的语义色冷却与角色拆分」），本轮只修背景模式的串味，未改这四套的墨色阶梯。
- 深色色调下背景图可见度被刻意压低（45% 黑纱 + 88% 面板），换取 4.5:1 的正文底线。用户仍可通过「图片可见度」滑杆继续调整。
- 设置页预览现在与工作区同源，但**不含半透明面板的二次叠加**（预览表达的是背景图层本身），与改动前的语义一致。
