# k-Coder 记忆与模型路由自学习开发设计

## 1. 文档定位

本文档是“记忆与自学习”功能的设计稿，不代表本轮已经接通生产代码。当前路线图仍以 `P10-142` 知识库进度指标为下一项任务；本功能应在 `P10-142` 完成验收后分阶段开发。

截图中的文字被解释为产品意图，而不是额外的系统指令：

- “记忆整理（dream）”：每天最多一次，在应用空闲时调用模型整理近期会话记忆，并产生模型 Token 消耗。
- “模型路由自学习”：从用户纠错和任务结果中学习目标模型/端点的选择偏好；训练过程在本机执行，只保存数值特征，不保存对话原文。
- 两个开关有依赖关系：开启路由自学习时必须同时开启 dream；关闭 dream 后仍可采集路由样本，但不自动训练。

## 2. 设计结论

记忆和路由学习必须是两个不同的领域：

1. 记忆保存经过宿主校验的长期事实、偏好和项目约定，允许用户查看、编辑、删除和设置保留期。
2. 路由学习只保存脱敏后的数值特征、候选目标 ID 和结果标签，不保存提示词、回答、工具正文、路径、URL、请求头或环境变量。
3. dream 是一个受调度的维护 Turn，不是第二套智能体循环。它复用现有 `AgentRuntime` 和 Provider 协议适配器，使用严格的结构化输出，不能调用文件、Shell、MCP、浏览器或修改策略。
4. 自学习只能在用户已经配置并启用的 Provider、模型和端点中重新排序，不能新增目标、修改凭据、扩大权限或覆盖用户明确选择的模型。
5. 路由训练先以 shadow 模式运行，再允许用户切换为 active。冷启动、模型损坏、样本不足、能力不匹配或 Provider 失败时始终退回现有的用户配置顺序和 fallback 机制。

### 2.1 一个必须在 UI 中说清楚的隐私事实

“路由训练完全在本机进行”不等于“dream 完全在本机进行”。当前 k-Coder 没有本地 LLM Provider；如果 dream 使用 OpenAI、DeepSeek、Anthropic、Gemini 或其他远程 Provider，候选整理输入会离开本机并产生 Token 费用。第一期应采用以下两种模式之一：

- **远程整理模式**：首次开启 dream 时明确告知会把有界、脱敏后的会话材料发送给当前维护模型，用户确认后才运行；路由样本和训练始终只在本机。
- **离线整理模式**：没有本地模型时只做 TTL 清理、重复项归并等确定性维护，不声称完成了模型整理，也不产生模型 Token 消耗。

设置页中的文案不能把远程 dream 描述为“完全在本机进行”。

## 3. 现有能力与接入边界

当前仓库已经具备以下基础：

- `src-tauri/src/advanced/memory.rs` 中的 `MemoryStore` 已支持显式启用、来源、保留期、修订、软删除、100 条活动记忆上限，以及 `remember` / `recall_memory` 工具。
- `advanced` 服务已经由 `AppState` 统一创建，工具通过 `ToolRegistry` 注册并经过 `PolicyEngine`；不能在 Tauri command 或 React 中新增智能体循环。
- `AgentRuntime` 已负责 Turn、取消、上下文预算、Compaction、Provider 调用和用量统计；dream 应在此边界内增加一种维护 Turn 来源。
- Provider 已有用户配置的主目标、备用模型/端点和瞬时失败 fallback；自学习不能另写一套 Provider 选择器来绕开它。
- `RuntimeMetrics` 和持久化事件已能记录调用、延迟、Token、工具成功率和任务终态；新增学习指标也必须脱敏且有界。
- 知识库使用工作区显式来源、FTS/BGE-M3 和 citation，解决的是文档检索，不应把知识库 chunk 直接当作用户记忆或路由训练样本。

建议的代码归属：

| 能力 | 建议模块 | 责任 |
| --- | --- | --- |
| 记忆实体、候选和保留期 | `advanced/memory.rs` 或拆分 `advanced/memory/` | 领域校验、版本兼容、列表/编辑/删除 |
| dream 调度和维护 Turn | `advanced/maintenance.rs` | 空闲判定、单实例、取消、重启恢复、预算 |
| 路由特征和学习器 | `advanced/routing_learning.rs` | 特征提取、样本、训练、模型快照、决策 |
| Provider 目标筛选 | `app_state.rs` + `providers/fallback.rs` | 只筛选用户已启用且能力匹配的目标 |
| 事实事件和投影 | `storage/` | JSONL/SQLite 追加、投影、迁移、重建 |
| IPC | `commands/` | 类型化参数校验和错误映射，不写业务循环 |
| UI | `SettingsDialog.tsx` 或独立 `MemoryLearningPage.tsx` | 开关、状态、候选审核、重置和审计摘要 |

## 4. 领域模型

### 4.1 记忆

现有 `MemoryView` 可以向 schema v2 兼容扩展。旧行缺少的字段必须按确定性默认值恢复，不能重写历史事实。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | UUID | 宿主生成，模型不能指定新 ID |
| `scope` | `global` / `project` | 第一期建议只开放全局和当前项目；项目标识使用宿主内部 ID，不进入 Provider |
| `kind` | `preference` / `constraint` / `fact` / `procedure` | 用于冲突处理和 UI 展示 |
| `content` | 有界字符串 | 记忆正文；最大 4 KiB，必须经过敏感信息扫描 |
| `source` | 有界字符串 | `user`、`user_feedback`、`dream`、`project_rule` 等来源 |
| `confidence` | `0..1` | 模型置信度只是排序信息，不能代替授权 |
| `status` | `active` / `pending` / `rejected` / `deleted` | dream 产生的删除操作只能进入 pending，不能直接删除用户记忆 |
| `retentionDays` | 1 到 365 | 到期由宿主清理，模型不能延长已有记忆的保留期 |
| `provenance` | 有界引用数组 | 指向本地 Turn/事件 ID，不保存原文快照 |
| `revision`、时间字段 | 宿主生成 | 追加修订，保留软删除和审计能力 |

dream 不直接写 `MemoryView`。模型只能返回 `MemoryProposal`：

```json
{
  "schemaVersion": 1,
  "operations": [
    {
      "operation": "upsert",
      "scope": "project",
      "kind": "constraint",
      "content": "项目测试命令使用 pnpm test",
      "sourceRefs": ["event-id-generated-by-host"],
      "confidence": 0.93,
      "retentionDays": 180
    }
  ]
}
```

宿主必须检查 schema、数量、长度、来源引用、敏感信息、相似重复项和作用域。模型不得提交 ID、时间、绝对路径、下一步工具调用或权限字段。高置信度且非敏感的新增/更新可以按用户设置自动应用；任何删除、降级或冲突项进入待审核列表。

### 4.2 dream 运行

`DreamRun` 是可恢复的维护任务，不属于普通用户 Turn：

| 字段 | 说明 |
| --- | --- |
| `runId` | 宿主生成的稳定 ID |
| `state` | `queued`、`running`、`completed`、`failed`、`cancelled` |
| `trigger` | `schedule`、`manual`、`startup-recovery` |
| `inputDigest` | 输入材料的脱敏摘要哈希，不保存正文 |
| `providerTargetId` | 维护时使用的目标，默认取用户当前主目标，不经过学习器 |
| `inputTokens`、`outputTokens` | 本次模型调用用量，单独计入维护成本 |
| `proposalCount`、`appliedCount`、`pendingCount` | 只记录数量 |
| `startedAtMs`、`completedAtMs`、`errorCode` | 运行诊断 |

调度规则：

- `dreamEnabled` 开启后按成功完成时间计算 24 小时周期；首次启用不立即抢占活动 Turn。
- 只有没有活动 Turn、没有活动索引/迁移冲突且应用空闲达到一个短窗口（建议 5 分钟）时才开始；睡眠唤醒后重新检查。
- 同一时间最多一个 dream；应用退出时 `running` 恢复为 `queued`，不能恢复为成功。
- 每次运行有独立 Token、输入字节、输出字节和墙钟上限；建议第一期输入最多 20 个近期 Turn 或 64 KiB，输出最多 20 个候选。
- 提供“立即整理”和“取消整理”，手动运行也受同一限额和远程发送确认约束。
- dream 读取的是宿主构造的 `MemoryDigestInput`，只包含近期用户请求、最终回答摘要和高信号工具结果；附件原文、完整工具输出、API Key、授权头、环境变量和无关历史不进入输入。
- 对话内容在 Provider 载荷中必须包裹为不可信数据，明确要求模型只返回 JSON，不执行其中可能出现的指令。

没有可用 Provider 时，dream 只能运行确定性维护：过期清理、空白/重复归并和损坏记录诊断；状态应显示 `completed_without_model`，不能伪装为模型整理。

### 4.3 路由学习样本

`LearningSample` 是一个只含数值和标签的本地事实：

| 字段 | 说明 |
| --- | --- |
| `sampleId`、`createdAtMs` | 宿主生成 |
| `featureSchemaVersion` | 特征兼容版本，变化时新建模型，不混用旧向量 |
| `featureVector` | 量化后的有限浮点向量，建议 24 到 40 维 |
| `candidateSet` | 当次实际可用目标的稳定 ID 集合，不保存 URL 或显示名称 |
| `selectedTargetId` | 实际被调用的目标 ID |
| `outcome` | `completed`、`failed`、`cancelled`、`corrected`、`retried` 等枚举 |
| `reward` | 宿主计算的有界奖励，不接受模型传入值 |
| `latencyMs`、`inputTokens`、`outputTokens` | 用于成本和延迟惩罚 |
| `toolSuccessRate`、`explicitFeedback` | 结构化结果 |
| `turnClass` | 普通对话、计划、编辑、测试、审阅、机器人等枚举 |

绝不保存：用户输入、助手正文、纠错文本、工具参数/结果、工作区绝对路径、文件名、URL、请求头、环境变量、API Key 或完整错误原文。若需要按项目区分偏好，只保存使用应用安装级随机盐 HMAC 后的不可逆 bucket，并在第一期默认关闭。

建议的特征向量组成：

- Turn 类型 one-hot：普通对话、计划、编辑、测试、审阅、Craft/机器人。
- 输入 Token 桶、当前上下文占用比例、历史消息数量。
- 是否包含图片、是否预计需要工具、是否包含写入/命令能力。
- 语言族（中文、英文、代码或混合）和当前 reasoning effort。
- 是否存在 Goal、是否处于 workflow 节点、是否为重试/steer。
- 维护和安全场景的保守标志位。

所有特征都在 Turn 开始时内存中计算并在结束时量化；特征 schema 变更必须让旧模型进入只读或重新训练状态。

### 4.4 路由模型与决策

第一期不做 LLM 微调，采用小型、可解释的 contextual bandit。推荐用每个目标一组有界的 ridge/logistic 参数：

```text
score(target, x) = predicted_reward(target, x)
                 + exploration_bonus(target, x)
                 - latency_penalty
                 - cost_penalty
```

- 样本不足时直接使用用户配置顺序；建议每个目标至少 30 个有效样本后才进入 shadow 评估。
- 探索比例固定上限（建议不超过 10%），不用于用户明确指定的目标、视觉能力不匹配的目标或高风险写入/删除 Turn。
- 新模型先 shadow 记录“建议目标”和实际目标的离线差异，不改变线上路由；通过固定回放集且质量不低于 baseline 后，用户才能开启 active。
- active 模式只在 Turn 开始时选一次目标；当前 Turn 中不因为新样本切换 Provider。Provider 的瞬时重试/fallback 仍由原有 `FallbackProvider` 负责。
- 分数变化设置最小提升门槛和最大步长。模型快照损坏、维度不符、目标已删除或候选为空时原子回退到 baseline。

奖励只能由宿主计算。一个可调参数的初始示例是：完成和工具成功为正，明确“需要纠正”、重试、失败、超长延迟和高 Token 消耗为负；明确纠正的权重应显著高于自然语言启发式。不要把“模型声称完成”当作成功，优先使用 Turn 终态、工具退出码、用户显式反馈和后续重试。

## 5. 端到端流程

```text
Turn 开始
   │
   ├─ 宿主构造 featureVector，过滤已启用且能力匹配的 Provider 目标
   ├─ 若 active 学习模型适用，则只对候选目标排序，否则沿用 baseline
   └─ AgentRuntime 使用选定目标完成同一 Turn
          │
          ├─ Turn 终态/工具结果/延迟/Token -> 形成 LearningSample
          └─ 用户点击“需要纠正/满意” -> 追加结构化反馈

空闲维护窗口
   │
   ├─ 读取有界的 MemoryDigestInput 和未训练样本
   ├─ 通过现有 AgentRuntime 发起一次维护 Turn（无工具、严格 JSON）
   ├─ 宿主校验 MemoryProposal，自动应用安全 upsert，删除进入待审核
   ├─ 本机训练 contextual bandit，生成新 RouteModelSnapshot
   └─ 追加 dream、候选、训练和指标事件
```

路由学习即使关闭 dream，也可以在 `routingLearningEnabled` 下采集样本；这些样本进入有界待训练队列，但不改变模型快照。重新开启 dream 后，先按保留期丢弃过期样本，再在下一次维护窗口训练。

## 6. 持久化设计

不让 React 状态或散落 JSON 成为事实来源。建议由 `storage` 提供 `MemoryRepository` 和 `RoutingLearningRepository`：

- 记忆继续兼容读取现有 `runtime-data/advanced/memories.jsonl`；新 schema 的候选、dream 状态和审计使用独立追加式事实事件，旧行按默认字段恢复。
- 路由样本、模型矩阵/向量和决策投影放入现有 SQLite 投影，事实事件放在 `runtime-data/advanced/learning/events.jsonl`。启动时按 schema 版本、截断尾行和幂等顺序重建投影。
- 样本默认保留 90 天，最多 10,000 条；模型快照最多保留当前版本和一个可回滚版本；决策诊断只保留聚合计数和最近 30 天。
- 写入使用同目录临时文件/事务和终态门闩；取消、崩溃或磁盘错误不能把半成品模型标成 active。
- “清除所有学习数据”必须删除样本、模型、决策和待训练队列，但不删除用户记忆；“清除记忆”必须删除记忆、候选和其 provenance 关联。两者在 UI 中是两个明确动作。

建议增加的事实事件：

`memory_dream_started`、`memory_dream_completed`、`memory_dream_failed`、`memory_proposal_created`、`memory_proposal_applied`、`memory_proposal_rejected`、`routing_sample_collected`、`routing_model_trained`、`routing_decision`、`routing_feedback_received`、`routing_model_activated`、`routing_model_reset`。

事件只能记录 ID、状态、数量、版本、耗时、Token、维度、错误码和有限枚举，不能记录记忆正文或路由特征之外的用户内容。结构化日志和指标复用同一脱敏边界。

## 7. 设置与 IPC 契约

建议不要继续把所有字段塞进当前只有 `enabled` 的 `MemorySettings`，而是升级为版本化视图并保留旧命令兼容：

```ts
interface MemoryLearningSettings {
  schemaVersion: number;
  memoryEnabled: boolean;
  dreamEnabled: boolean;
  dreamIntervalHours: number;
  dreamAutoApply: "safe_only" | "review_all";
  routingLearningEnabled: boolean;
  routingMode: "off" | "shadow" | "active";
  sampleRetentionDays: number;
  lastDreamAtMs: number | null;
  nextDreamAtMs: number | null;
  pendingProposalCount: number;
  sampleCount: number;
  trainedSampleCount: number;
  modelVersion: number | null;
  lastErrorCode: string | null;
}
```

建议的类型化命令：

- `get_memory_learning_settings` / `set_memory_learning_settings`
- `list_memory_proposals`、`approve_memory_proposal`、`reject_memory_proposal`
- `run_memory_dream`、`cancel_memory_dream`、`get_memory_dream_status`
- `submit_routing_feedback`：只接收枚举标签和关联的宿主 Turn/target ID，不接收纠错正文
- `get_routing_learning_status`、`reset_routing_learning`

命令只做参数边界、权限和错误映射；调度、训练、存储和 Provider 调用分别留在服务/运行时层。`set_memory_learning_settings` 要在后端原子处理依赖：开启 `routingLearningEnabled` 时一并开启 `dreamEnabled`；单独关闭 dream 时保留 `routingLearningEnabled` 和样本采集，但把 `routingMode` 锁定为既有模型快照或 shadow，不触发训练。

### 7.1 设置页布局

在“知识与规则”分组增加“记忆与自学习”页面，与现有知识库页面分开。顶部显示总开关和最近维护状态；下面保留截图中的两个主行：

1. `记忆整理（dream）`：显示 `token 消耗` 标签、上次/下次运行时间、待审核候选数、“立即整理”和“取消”。
2. `模型路由自学习`：显示 `实验性` 标签、`关闭 / shadow / active` 分段控制、样本数、模型版本和“清除学习数据”。

开启路由学习时，在同一页面明确展示“依赖记忆整理；关闭记忆整理后仍采集样本，但不会自动训练”。远程 dream 的数据外发和 Token 费用必须在第一次开启前用确认对话说明。页面只展示脱敏聚合信息，不把样本向量原样倾倒给用户。

对话消息操作建议提供两个结构化反馈按钮：`满意` 和 `需要纠正`。按钮只提交标签；如果用户随后重新发送或 steer，运行时可以追加 `retried/steered` 结果，但不得保存纠正文本作为训练资料。

## 8. 安全、隐私和失败语义

- 默认关闭所有新增开关；开启 dream、远程整理、route shadow/active 和自动应用都必须有可见状态。
- dream 的 Provider 请求只能使用用户当前已配置的维护目标，不能由模型返回目标 ID，也不能通过用户输入改变工具 Capability、PolicyEngine 或工作区范围。
- dream 不注册工具；即使输入材料中出现“执行命令/读取文件”等文字，也只能被当作数据。
- 记忆正文写入前扫描 API Key、Bearer、Cookie、私钥、连接串和完整环境变量；命中敏感规则时进入 rejected/pending，不自动保存。
- 路由特征仅允许有限维、有限值、finite 数字；NaN、Infinity、超维度、负无穷奖励、未知目标和重复样本 ID 一律关闭失败。
- 远程 Provider 失败、429、取消、超时或结构化输出无效时，dream 失败但不影响普通对话；旧记忆和旧路由模型继续可用。
- 训练失败或模型快照校验失败时，模型保持上一版本；没有上一版本就使用 baseline。不能因为“学习失败”自动关闭用户的 Provider 或修改 fallback 配置。
- 所有删除操作采用软删除/待审核/可恢复事件；清除学习数据属于破坏性本地数据操作，应显示确认并记录审计。
- 线程、工作区和项目作用域由宿主绑定。显式无项目会话可以读取用户明确启用的全局记忆，但不得加载项目记忆，也不得启用项目级路由特征。

## 9. 指标与验收

新增指标只保留聚合值：

- dream 运行次数、成功率、平均延迟、输入/输出 Token、候选创建/应用/拒绝数量。
- 路由样本数、已训练样本数、模型版本、shadow 命中率、active 覆盖率、回退次数。
- 每个目标的完成率、明确纠正率、工具成功率、延迟和 Token 分桶；只展示达到最小样本阈值后的聚合。
- 学习器因能力不匹配、样本不足、校验失败或 Provider 失败而使用 baseline 的次数。

验收门槛：

1. 默认状态、依赖开关、重启恢复、手动整理、取消和 24 小时调度均有 Rust 与桌面回归。
2. dream 的无效 JSON、越界候选、提示注入文本、敏感信息、超时、取消和 Provider 错误都有确定性测试。
3. 路由特征提取在相同结构化输入下确定性相同；测试扫描事实日志和 SQLite，断言不存在提示词、回答、工具正文、路径、URL、Header 或 API Key。
4. 冷启动、样本不足、shadow、active、明确模型选择、视觉能力筛选、目标删除、模型损坏和 baseline 回退均有测试。
5. 删除记忆、清除学习、过期清理和 JSONL 尾行损坏可以恢复；取消维护任务不会生成 active 模型或半成品记忆。
6. 普通对话、编辑、命令审批、知识库检索、子智能体和现有 Provider fallback 没有行为回退。
7. 按仓库质量门槛执行 `pnpm build`、`cargo fmt --manifest-path src-tauri/Cargo.toml -- --check`、`cargo check --manifest-path src-tauri/Cargo.toml`、`cargo test --manifest-path src-tauri/Cargo.toml`，并通过 `pnpm tauri dev` 验证桌面设置与反馈路径。

## 10. 分阶段实施顺序

当前不应跳过 `P10-142`。完成知识库进度事件和指标后，建议按以下顺序推进：

### M1：记忆 schema 与维护框架

- 升级 `MemoryView` 兼容字段，加入 scope/kind/status/confidence/provenance。
- 建立 `MemoryRepository`、dream 状态机、取消/恢复和 TTL 清理。
- 增加设置页和类型化 IPC，但先关闭模型整理，只验证开关与本地维护。

### M2：dream 候选流水线

- 构造脱敏 `MemoryDigestInput`，实现无工具、严格 JSON 的维护 Turn。
- 增加候选列表、自动应用安全 upsert、删除待审核和审计。
- 接入远程发送确认、独立 Token 指标和失败保留旧状态。

### M3：路由样本与 shadow 学习

- 从 `AgentRuntime` Turn 事实提取特征，增加满意/纠正反馈入口。
- 建立样本保留、确定性本地训练、模型版本和 shadow 决策。
- 先做离线回放评估，不改变线上目标选择。

### M4：active 路由与生产加固

- 仅允许用户已启用目标，接入能力过滤和 baseline/fallback 回退。
- 增加 active 开关、最大探索比例、最小提升门槛、模型回滚和清除数据。
- 完成威胁建模、性能预算、迁移/备份说明和真实 Tauri 工作流验收后再默认开放。

## 11. 待确认的产品选择

实现前需要产品负责人确认三点：

1. dream 是否允许把脱敏后的近期会话发送到当前远程 Provider；若不允许，第一期只能提供确定性本地维护，或先增加本地模型 Provider。
2. 记忆新增/更新的默认策略是“高置信非敏感自动应用”还是“全部进入审核”；删除建议无论如何都必须审核。
3. 路由学习的 active 模式是否只对普通对话开放，还是允许覆盖编辑/测试/机器人等高价值任务。建议第一期只对普通对话和低风险只读任务开放。
