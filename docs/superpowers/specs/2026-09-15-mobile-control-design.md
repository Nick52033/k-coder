# k-Coder 手机操作设计：局域网直连与异地访问

## 1. 目标与范围

本设计为 k-Coder 增加手机控制能力。手机作为轻量客户端，负责查看会话、发送用户消息、接收实时事件、取消运行中的 Turn、处理审批和 `request_user_input`；电脑上的 k-Coder 继续持有工作区、Provider 凭据、AgentRuntime、ToolRegistry、PolicyEngine 和 ThreadRepository。

本设计覆盖两种部署方式：

1. **方案 1：局域网直连**。手机与运行 k-Coder 的电脑位于同一局域网，手机浏览器或安装为 PWA 的网页连接电脑。
2. **方案 2：异地访问**。手机通过经过认证的中继连接访问电脑，不要求把电脑端口直接暴露到公网。

首期移动端只提供控制面，不承诺完整桌面工作台。文件浏览、终端输出、插件管理、模型供应商配置和高风险批量操作继续以桌面端为主；移动端只显示必要的有界摘要和审批入口。

## 2. 现有架构复用原则

现有 `AgentRuntime` 是唯一智能体循环。移动连接不得创建第二套运行时，也不得直接调用 Provider、SQLite、工作区文件或 Shell。移动端使用与桌面端相同的 `Thread → Turn → Item` 领域模型和版本化 `AgentEvent`。

现有 App Server 已定义 JSON-RPC 2.0 生命周期，并支持 WebSocket：连接先执行 `initialize`/`initialized`，之后才能执行 `thread/*`、`turn/*`、审批和用户输入等方法。移动网关应复用这些语义，只增加连接认证、设备配对、订阅范围和能力裁剪。

所有会改变状态的事件仍由存储层先写入，再向客户端发布；网络断开后，移动端通过历史游标和事件序号补齐，而不是依赖浏览器缓存猜测状态。

## 3. 共同逻辑架构

```text
手机 Web/PWA
  │ HTTPS/WSS + JSON-RPC 2.0
  ▼
Mobile Gateway（Tauri/Rust 进程内边界）
  ├─ ConnectionManager：连接、心跳、背压、重连
  ├─ Authenticator：配对码、设备凭据、会话令牌
  ├─ CapabilityPolicy：移动端能力裁剪与二次确认
  ├─ RpcAdapter：JSON-RPC 方法映射和版本协商
  └─ EventFanout：按 thread 订阅事件、游标补发
  │
  ▼
App Service / AgentRuntime / PolicyEngine / Storage
```

Mobile Gateway 只做协议、身份和连接管理。它不能执行智能体循环，不能绕过 `PolicyEngine`，也不能直接构造工具结果。`turn/start`、`turn/steer`、`turn/interrupt` 和审批响应最终都调用现有应用服务。

## 4. 移动协议

### 4.1 连接初始化

连接建立后，客户端发送：

```json
{"jsonrpc":"2.0","id":1,"method":"initialize","params":{
  "protocolVersion":1,
  "client":{"name":"k-coder-mobile","version":"0.1"},
  "capabilities":{"mobileUi":true,"supportsBinary":false}
}}
```

服务端返回服务器版本、会话 ID、允许的能力集合和事件协议版本。服务端不得相信客户端声明的权限；客户端能力只用于协商显示，真正授权由服务器端绑定的设备身份、会话身份和 `CapabilityPolicy` 决定。

### 4.2 推荐的移动方法集合

首期开放：

- `thread/list`：只返回用户可访问的主会话，包含 ID、标题、项目名、活动状态和更新时间。
- `thread/read`：按页返回有界历史；正文、工具摘要和错误信息遵守现有大小上限。
- `thread/subscribe` / `thread/unsubscribe`：订阅一个会话的实时事件。
- `turn/start`：发送文本消息，可携带已由桌面端创建的附件引用；移动端首期不直接上传任意本地路径。
- `turn/steer`：对当前活动 Turn 追加引导消息。
- `turn/interrupt`：按精确 `expectedTurnId` 取消活动 Turn。
- `approval/respond`：批准、拒绝或取消待处理审批；必须显示工具名、风险说明和工作区相对路径。
- `tool/requestUserInput/respond`：回答结构化用户问题。
- `events/resume`：携带 `threadId`、`afterEventId` 或历史游标补发遗漏事件。

首期关闭或只读：供应商配置、插件启停/删除、MCP 配置、工作区任意文件读取、任意 Shell、批量删除会话、密钥管理和系统级设置。

### 4.3 事件与断线恢复

每个移动订阅拥有单调递增的连接内 `deliverySeq`，领域事件仍使用原有 `eventId`、`threadId`、`turnId` 和 `itemId`。`deliverySeq` 只用于检测丢包，不进入模型历史。

客户端收到事件后先按 `eventId` 去重，再按现有前端投影规则更新状态。断线重连流程为：

1. 重新认证并重新执行 `initialize`。
2. 发送 `events/resume`，附带每个订阅的最后确认序号和历史游标。
3. 服务端先返回有界补发事件；若游标过期，返回 `resume_required`，客户端改用 `thread/read` 获取最新快照。
4. 补发完成后再切换到实时事件，避免快照和增量交错覆盖。

背压采用每连接固定容量队列。正文增量和命令输出属于可丢弃展示事件；`turn_started`、审批、用户输入请求、工具终态、Turn 终态和恢复游标不能丢失。队列满时服务端发送 `resync_required`，而不是无限缓存。

## 5. 方案 1：局域网直连

### 5.1 拓扑

```text
手机浏览器/PWA ── HTTPS/WSS ── 局域网电脑上的 k-coder Mobile Gateway
                                      │
                                      └── AgentRuntime / Storage / Workspace
```

电脑默认只监听回环地址。用户在桌面端设置中打开“局域网访问”后，服务绑定到明确选择的私有网卡地址，并显示一次性配对二维码。二维码只包含短期配对 URI 和随机挑战，不包含 API Key、工作区路径或长期令牌。

### 5.2 配对与认证

1. 桌面端生成 10 分钟有效、单次使用的配对挑战，并在屏幕上显示二维码和 6 位人工校验码。
2. 手机扫描后通过局域网 HTTPS 连接，提交挑战和人工校验码。
3. 电脑要求用户在桌面端确认设备名称；确认后为该设备生成随机设备 ID、设备密钥和刷新令牌。
4. 手机把设备密钥存入浏览器受保护存储；后续连接使用短期访问令牌，令牌过期时用刷新令牌换新。
5. 桌面端设置页展示已配对设备，可逐台撤销；撤销立即使该设备的访问令牌失效。

首期不依赖用户名密码，也不把静态 Bearer Token 放进二维码。若无法提供受信任证书，开发版可以允许用户明确接受局域网自签名证书；生产版应生成本机证书并显示指纹，移动端首次连接必须核对指纹。

### 5.3 局域网安全边界

- 只接受 RFC1918/ULA 私网来源，拒绝公网路由地址和未知转发头。
- 默认单设备最多一个活动连接、每 IP 限制握手和 RPC 频率。
- 所有写操作带 `requestId`，服务端按设备和方法做幂等去重，避免移动网络重试造成重复 Turn。
- 每个 RPC 都重新检查设备是否仍被授权、目标 thread 是否属于当前用户、目标 workspace 是否仍绑定。
- 审批响应要求客户端回传审批请求 ID、工具调用 ID 和观察到的版本；过期请求返回 `stale_request`。

### 5.4 方案 1 的优点与限制

优点是实现和运维成本最低，数据不经过第三方，适合先验证移动端交互。限制是手机必须与电脑在同一网络，电脑睡眠、网络隔离、企业 Wi‑Fi 客户端隔离都会影响连接；不能把“局域网可见”误认为安全，仍必须使用 TLS、配对和逐请求授权。

## 6. 方案 2：异地访问

### 6.1 推荐拓扑：出站中继，不开放入站端口

```text
手机 ── HTTPS/WSS ── Relay Service ── WSS 出站连接 ── 电脑上的 k-coder
                         │                    │
                         └─ 仅转发加密帧       └─ Mobile Gateway
```

电脑主动向中继服务建立长连接，因此不要求路由器端口转发或公网暴露。中继只负责设备在线状态、连接配对和加密帧转发，不保存会话正文、工具输出、文件内容、Provider 凭据或长期私钥。

### 6.2 端到端身份模型

- 每个 k-Coder 安装生成设备长期密钥对，私钥存操作系统凭据设施。
- 每部手机生成独立设备密钥对；中继只保存公钥、设备 ID、撤销状态和短期连接元数据。
- 配对通过电脑桌面端显示的一次性二维码完成，二维码包含中继地址、设备 ID、挑战和公钥指纹，不包含访问令牌。
- 手机与电脑通过挑战响应建立设备会话；中继验证两端签名后转发加密帧。应用层帧使用双方协商的会话密钥加密，服务端无法解密正文。
- 访问令牌只标识“哪个设备可以请求哪个 k-Coder 实例”，不携带模型权限；具体 thread 和能力仍由电脑端 `CapabilityPolicy` 判断。

### 6.3 中继协议与离线行为

电脑端每 20 秒发送心跳，连续三次失败后标记离线并退避重连。手机端显示在线、连接中、离线三种状态；离线期间允许编辑草稿，但不能假装发送成功。

中继为每个设备对保留有界待投递队列，只缓存控制类消息和最多一个待处理唤醒通知，不缓存正文事件。电脑重新上线后，手机通过 `events/resume` 从电脑的本地存储补齐历史。中继不可用时，局域网直连仍可作为可选回退路径。

### 6.4 异地访问的额外安全策略

- 默认只开放聊天、取消、审批和结构化用户输入；涉及文件、Shell、插件和设置的能力必须在桌面端显式开启“允许移动端”，并可设置自动过期时间。
- 每次移动端审批显示“来自异地设备”的标识；破坏性操作至少要求桌面端确认，不能只靠手机批准。
- 登录失败、配对、撤销、审批和能力变更写入既有审计事件，日志只记录设备 ID、方法、结果和时间，不记录 IP 全量环境、令牌或正文。
- 中继只接受固定帧大小和固定方法集合，拒绝任意代理 HTTP、任意 WebSocket URL 和客户端指定的转发目标。
- 手机丢失时，用户可从桌面端一键撤销；撤销事件在电脑在线时立即生效，电脑离线期间不接受新的移动会话。

### 6.5 方案 2 的优点与限制

优点是可从任意网络访问，不需要公网暴露电脑，且可以逐设备撤销。代价是需要维护中继服务、设备密钥和在线状态，必须测试移动网络切换、后台挂起、时钟漂移和重复投递。端到端加密会使中继无法替电脑做内容级审计，因此所有授权和审计必须留在电脑端完成。

## 7. 两种方案的共同数据流

```text
手机发送 turn/start
  → 网关认证设备与能力
  → 校验 thread/workspace/活动 Turn
  → 应用服务进入现有 Thread mailbox
  → AgentRuntime 持久化 turn_started
  → EventFanout 向桌面和手机分别发布同一领域事件
  → 手机按 eventId 投影 UI
```

移动端只接收面向客户端的安全载荷：正文、结构化摘要、工具名称、状态、耗时、脱敏错误、审批说明和必要的有界结果。不得下发 Provider 请求头、API Key、完整环境变量、原始命令秘密参数、私有推理、工作区绝对路径或未授权文件内容。

错误统一使用结构化错误：`unauthorized`、`forbidden`、`not_found`、`stale_request`、`rate_limited`、`server_overloaded`、`resume_required`、`unsupported_capability` 和 `internal_error`。客户端按 `retryable` 和 `retryAfterMs` 决定是否重试，不能依据错误文本猜测。

## 8. 移动端界面设计

首屏分为三个区域：

1. 会话列表：显示标题、项目名、运行状态、待审批数量和最近更新时间。
2. 对话页：显示分页历史、实时回复、工具摘要和当前 Turn 状态；工具详情默认折叠。
3. 操作栏：发送、停止、继续执行、审批和回答问题。发送按钮在网络离线或会话权限失效时明确禁用。

手机端不复制桌面三栏工作台。文件变更只显示“已修改文件数量、增删行和查看详情入口”；真正 diff 先提供只读摘要，后续再单独设计移动端 diff 浏览器。

## 9. 实施分期

### 阶段 A：协议和网关骨架

- 抽出可复用的 JSON-RPC 方法注册和事件 Fanout。
- 增加 `initialize`、订阅、恢复游标、结构化错误和幂等 `requestId`。
- 只允许本地回环连接，使用测试客户端验证 Turn 生命周期。

### 阶段 B：方案 1 局域网直连

- 桌面设置页增加启停、监听地址、证书指纹、配对二维码和设备撤销。
- 实现移动 PWA 的会话列表、对话、流式事件、取消、审批和用户输入。
- 覆盖断网重连、事件补发、过期游标、重复发送、审批竞态和局域网边界。

### 阶段 C：方案 2 出站中继

- 明确中继部署方式、域名、证书、数据保留和故障预算。
- 增加设备密钥、挑战响应、端到端帧加密、在线状态和撤销同步。
- 对移动网络切换、电脑休眠、重连、重复投递和中继不可用进行真实测试。

### 阶段 D：能力扩展

- 只读 diff 和有限文件查看。
- 可配置的移动端工具能力白名单。
- 多手机设备管理、设备名称、最后在线时间和审计查询。

## 10. 测试与验收

后端必须增加：

- JSON-RPC 初始化、版本协商和未知方法错误。
- 设备配对挑战单次使用、过期、重放和撤销。
- thread/workspace/设备权限交叉校验。
- `turn/start` 幂等、精确 `turnId` 取消、过期审批响应和重复用户输入。
- 事件队列背压、不可丢事件、可丢增量、断线补发和游标过期恢复。
- 路径、绝对路径、符号链接、代理转发和 Header 注入边界。
- 日志脱敏：API Key、Authorization、Cookie、环境变量和正文不进入审计或中继日志。

移动端至少覆盖 375px 宽度、横竖屏切换、键盘弹出、后台恢复、弱网、断网、重复点击、长回复和审批等待。验收必须分别执行仓库规定的 `pnpm build`、`cargo fmt --manifest-path src-tauri/Cargo.toml -- --check`、`cargo check --manifest-path src-tauri/Cargo.toml`、`cargo test --manifest-path src-tauri/Cargo.toml`；真实桌面流程还需启动隔离的 `pnpm tauri dev` 验证。

## 11. 推荐决策

建议先实现方案 1，把协议、能力模型、事件恢复和设备撤销做成方案 2 可复用的核心。方案 2 不应通过直接开放方案 1 的监听端口实现；应采用电脑主动出站到中继的方式，并保持电脑端最终授权。这样可以先用较低成本验证“手机操作对话”的核心体验，同时避免后续因为公网暴露、认证和权限边界重新设计协议。

本文件只定义设计和验收边界，尚未修改运行时代码，也未部署到 `D:\\apps\\k-coder\\`。
