# 多供应商故障切换设计

## 目标

对话请求遇到上游网络中断、流在产生任何可用输出前断开，或 Provider 流长时间没有事件时，按用户配置的顺序切换到另一供应商，并让新一轮请求从完整上下文重新开始。New API 作为统一 OpenAI 兼容网关，负责自身多个上游渠道的负载均衡与渠道级自动切换；k-Coder 的供应商路由作为第二层容错，在 New API 整体不可用时可以继续尝试另一套独立凭据和端点。

## 方案边界

- New API 不作为新的 Provider 协议实现。用户在模型供应商设置中按 OpenAI Chat Completions 配置其 `/v1` 地址、模型名和 New API Key。它的渠道权重、优先级、模型映射和上游自动禁用由 New API 管理。
- k-Coder 增加供应商级有序备用路由。可把 New API 配置为主供应商，把另一 New API 实例或兼容服务设为备用供应商；也可反向配置。API Key 仍按供应商 ID 分别保存在操作系统凭据存储中。
- 这是顺序故障切换，不是并发竞速或请求级负载均衡。正常请求只发给第一个可用目标，不会为分流而重复计费。
- 具体供应商兼容能力由其实际 OpenAI Chat Completions 实现决定。Responses API 专属能力不因 New API 地址而自动可用。

## 持久化配置与设置界面

每个供应商配置增加可选 `fallbackProviderIds: string[]`，作为有序的供应商 ID 引用。缺少该字段的旧配置读取为空数组，因而无需迁移旧 JSON。

- 单个配置最多引用 4 个备用供应商；拒绝空 ID、重复 ID、自引用和不存在的 ID。
- 备用目标必须是对话 Provider；图片生成专用配置不能加入对话备用路由。
- 删除被引用的供应商时，存储层同步移除相应引用，保持剩余目录有效。
- 设置页以复选框配置备用供应商顺序；展示名称与密钥状态，未配置 API Key 的项目不可选。已有的同供应商备用模型和备用端点继续保留。
- 供应商配置 JSON 只存引用和公开配置，不存密钥、请求头或上游凭据。

## 路由构建

路由按以下顺序展开：主供应商的活动模型、标记为故障切换的模型、启用的备用端点；随后按 `fallbackProviderIds` 的顺序，为每个备用供应商展开相同的活动模型、备用模型和备用端点集合。按供应商 ID、端点和模型去重。

每个实际目标使用该目标供应商自己的 API Key 和 Provider 适配器，并按供应商 ID 应用已有的限流/冷却包装。返回给 AgentRuntime 的模型归因事件仍报告实际选中的供应商名和模型名。上下文窗口按本次请求可用目标中的最小值限制，避免主供应商请求的上下文无法被较小备用模型接收。含图片的请求只保留声明支持视觉输入的目标；没有可用目标时在请求前明确失败。

若主供应商 API Key 缺失，沿用现有“供应商未配置”错误。备用供应商没有 API Key 时跳过该备用项，不影响主供应商；设置页会阻止用户保存不可选项。

## 自动切换规则

每个目标只要尚未产出回复正文、图片、安全推理摘要、工具调用或 Provider 上下文，就可以因以下临时故障转到下一个目标：网络请求错误、临时不可用、限流、HTTP 408/429/5xx、流中断，以及 295 秒没有收到任何流事件。295 秒比 AgentRuntime 现有的 300 秒流空闲上限早 5 秒，确保供应商路由先完成切换。

下列情况不切换：

- 鉴权、权限、参数或模型名错误等非瞬时客户端错误；
- 无效 Provider 响应或无效工具参数；
- 用户取消或 Turn 被 steer；
- 当前目标已经产生任何上述输出后再发生错误或静默。

切换会丢弃并取消失败目标的未完成流，以完整的原始 ProviderRequest 调用下一个目标。已产生公开或持久化输出后禁止重放，避免重复文本、重复工具执行、丢失前后文或把两个模型的半截回答拼在一起。整条配置路由失败后，既有 AgentRuntime 零输出瞬时重试仍按原有退避策略运行。

## 可观测性

- 每次目标切换都发出 `model_selected`，设置页的现有故障切换指标累计备用目标选择次数。
- Provider 的失败、延迟和 Usage 仍使用已有运行指标和持久化投影。
- 错误只保留已有脱敏、有界的原因；不得记录 API Key、Authorization 请求头、完整请求环境或凭据。

## 验收

- 配置往返、旧配置默认值、无效引用、自引用、重复引用和删除清理均由 Provider 配置测试覆盖。
- Provider 路由测试覆盖流前瞬时故障、零输出流内断开、零输出 idle 自动切换，以及有输出后禁止切换。
- 应用状态测试覆盖跨供应商目标顺序、独立密钥、视觉能力过滤和较小上下文窗口限制。
- 设置页完成 `pnpm build`；日常 Rust 验证执行 `cargo fmt --check`、`cargo check` 和直接相关的 Provider/应用状态测试。

## New API 配置建议

在 New API 管理端为上游渠道配置模型映射、渠道优先级/权重和自动禁用；在 k-Coder 中将 New API 作为普通 OpenAI Chat Completions 供应商，API 地址填写 New API 的 OpenAI 兼容 `/v1` 根地址。若希望 New API 故障后还有出口，可在同一设置页给它配置一个备用供应商。
