# k-Coder 知识库与记忆扩展详细设计

## 1. 文档目的

本文档定义在现有本地 SQLite + FTS5/BM25 + BGE-M3 混合检索方案上，增加结构化知识、用户记忆、工作记忆、经验记忆、自动整理和质量评测的目标架构。实现必须复用现有 `AgentRuntime`、`PolicyEngine`、`ToolRegistry`、`KnowledgeService` 和 `storage` 边界，不创建第二套智能体循环。

本文档与以下约束一致：

- [开发路线图](./开发路线图.md) 的阶段顺序和验收门槛。
- [架构说明](./架构.md) 的模块边界。
- [ADR 0051：硅基流动 BGE-M3 与本地 SQLite 混合检索](./adr/0051-siliconflow-embedding-hybrid-retrieval.md)。
- [ADR 0053：记忆整理与本地模型路由自学习](./adr/0053-memory-and-routing-learning.md)。

## 2. 目标与非目标

### 2.1 目标

1. 将知识库扩展为可版本化、可追溯、可评测的知识数据层。
2. 将记忆拆成用户、项目、工作和经验四类，分别管理生命周期和优先级。
3. 支持 FTS、向量、标题、路径、符号、时间和反馈的多路检索。
4. 允许模型提出记忆候选和事实候选，由宿主决定是否写入。
5. 支持离线运行、外部 embedding 失败降级和用户独立清除。
6. 为未来 PostgreSQL/pgvector 或团队共享保留 Repository 抽象。

### 2.2 非目标

- 第一阶段不替换 SQLite，不引入 PostgreSQL、Redis、Elasticsearch 或常驻向量服务。
- 不允许模型直接修改权限、Provider 配置、来源路径或记忆删除状态。
- 不保存完整对话作为训练数据。
- 不在本阶段实现通用知识图谱编辑器、插件市场或多用户同步。
- 不把知识库检索结果伪装成模型记忆，也不把低置信模型推断当作事实。

## 3. 分层架构

```text
用户/项目文件
    │
    ▼
来源与解析层 ──> revision/chunk 层 ──> FTS/embedding 索引
    │                                      │
    └────────> 实体/事实候选层              │
                                           ▼
                                   Retriever + Reranker
                                           │
                              Citation Snapshot（引用快照）

用户反馈/任务结果 ──> Memory Candidate ──> Memory Store
                                           │
                               Context Assembler（上下文编排）
                                           │
                                      AgentRuntime
```

### 3.1 模块职责

| 模块 | 职责 | 禁止事项 |
|---|---|---|
| `knowledge` | 来源、解析、chunk、索引、检索、引用 | 不读取任意路径；不决定权限 |
| `memory` | 记忆候选、审核、TTL、合并、删除 | 不直接把模型输出写成事实 |
| `entities` | 实体、事实、关系候选及来源绑定 | 不接受无来源关系 |
| `retrieval` | 多路召回、融合、重排、预算裁剪 | 不绕过 scope 和 active revision |
| `context` | 按优先级编排规则、记忆、知识和任务摘要 | 不覆盖安全策略 |
| `storage` | 事实事件、SQLite 投影、迁移、重建 | 不让界面直接访问数据库 |
| `commands` | IPC 校验、调用服务、错误映射 | 不写 SQL、不运行智能体循环 |
| `AgentRuntime` | 普通 Turn 和维护 Turn 的统一执行 | 不实现第二套循环 |

## 4. 数据模型

所有时间使用 Unix 毫秒；所有 ID 使用宿主生成的 UUID；所有正文均有长度和 UTF-8 上限。

### 4.1 知识实体和事实

```sql
CREATE TABLE knowledge_entities (
  id TEXT PRIMARY KEY,
  collection_id TEXT NOT NULL,
  entity_type TEXT NOT NULL,
  name TEXT NOT NULL,
  normalized_name TEXT NOT NULL,
  description TEXT,
  confidence REAL NOT NULL CHECK(confidence >= 0 AND confidence <= 1),
  status TEXT NOT NULL DEFAULT 'active',
  created_at_ms INTEGER NOT NULL,
  updated_at_ms INTEGER NOT NULL
);

CREATE TABLE knowledge_facts (
  id TEXT PRIMARY KEY,
  subject_entity_id TEXT NOT NULL,
  predicate TEXT NOT NULL,
  object_entity_id TEXT,
  object_text TEXT,
  source_chunk_id TEXT NOT NULL,
  source_revision_id TEXT NOT NULL,
  confidence REAL NOT NULL CHECK(confidence >= 0 AND confidence <= 1),
  valid_from_ms INTEGER,
  valid_to_ms INTEGER,
  status TEXT NOT NULL DEFAULT 'candidate',
  created_at_ms INTEGER NOT NULL,
  updated_at_ms INTEGER NOT NULL,
  CHECK (object_entity_id IS NOT NULL OR object_text IS NOT NULL)
);
```

事实状态：`candidate`、`active`、`disputed`、`expired`、`rejected`。`active` 事实必须有当前或历史 citation 来源；来源 revision 删除后事实转为 `expired`，不直接物理删除。

### 4.2 记忆

```sql
CREATE TABLE memories (
  id TEXT PRIMARY KEY,
  scope_type TEXT NOT NULL,              -- user/workspace/project/thread
  scope_id TEXT,
  memory_type TEXT NOT NULL,             -- preference/fact/instruction/constraint/work_state/experience
  normalized_key TEXT NOT NULL,
  content TEXT NOT NULL,
  source_type TEXT NOT NULL,             -- user/model/tool/system
  source_ref TEXT,
  confidence REAL NOT NULL CHECK(confidence >= 0 AND confidence <= 1),
  sensitivity TEXT NOT NULL DEFAULT 'normal', -- normal/private/secret_candidate
  status TEXT NOT NULL DEFAULT 'active',
  revision INTEGER NOT NULL DEFAULT 1,
  expires_at_ms INTEGER,
  created_at_ms INTEGER NOT NULL,
  updated_at_ms INTEGER NOT NULL,
  UNIQUE(scope_type, scope_id, normalized_key, revision)
);

CREATE TABLE memory_candidates (
  id TEXT PRIMARY KEY,
  operation TEXT NOT NULL,               -- create/update/merge/delete
  target_memory_id TEXT,
  scope_type TEXT NOT NULL,
  scope_id TEXT,
  memory_type TEXT NOT NULL,
  content TEXT NOT NULL,
  normalized_key TEXT NOT NULL,
  reason TEXT NOT NULL,
  confidence REAL NOT NULL CHECK(confidence >= 0 AND confidence <= 1),
  requires_review INTEGER NOT NULL,
  status TEXT NOT NULL DEFAULT 'pending',
  source_turn_id TEXT,
  created_at_ms INTEGER NOT NULL,
  reviewed_at_ms INTEGER
);
```

规则：`secret_candidate`、删除、冲突、跨 scope 更新必须人工审核；高置信且非敏感的新增/更新才允许自动接受。记忆和学习数据分开清除，清除操作必须写审计事件。

### 4.3 工作记忆和经验

工作记忆使用 `memory_type=work_state`，默认 TTL 14 天；经验使用 `memory_type=experience`，默认 TTL 180 天，并且必须绑定任务结果或工具事件摘要。只保存结构化摘要，不保存完整 Provider 消息和完整命令输出。

### 4.4 检索事件与反馈

```sql
CREATE TABLE knowledge_retrieval_events (
  id TEXT PRIMARY KEY,
  thread_id TEXT NOT NULL,
  turn_id TEXT NOT NULL,
  query_hash TEXT NOT NULL,
  retrieval_mode TEXT NOT NULL,
  result_count INTEGER NOT NULL,
  selected_citation_count INTEGER NOT NULL,
  latency_ms INTEGER NOT NULL,
  created_at_ms INTEGER NOT NULL
);

CREATE TABLE knowledge_feedback (
  id TEXT PRIMARY KEY,
  citation_id TEXT NOT NULL,
  feedback_type TEXT NOT NULL,            -- useful/irrelevant/outdated/wrong
  created_at_ms INTEGER NOT NULL
);
```

不写入 API Key、Authorization、完整环境变量、完整 query 原文或完整会话正文。

## 5. 记忆生命周期

```text
普通 Turn/用户操作
        ↓
提取结构化候选（受限 JSON）
        ↓
Schema、长度、敏感性、scope、来源校验
        ↓
去重/冲突检测/置信度计算
        ↓
自动接受 或 待审核
        ↓
写入 memory 事实事件和 SQLite 投影
        ↓
注入后续上下文
        ↓
TTL 降权、过期、归档或用户删除
```

### 5.1 上下文优先级

```text
安全策略
> 用户明确规则
> 项目 AGENTS.md
> 用户确认的约束记忆
> 项目事实记忆
> 当前工作记忆
> 知识库引用
> 模型推断
```

每次注入都要记录 `memoryId`、revision、scope 和是否因预算被裁剪。记忆正文进入 Provider 前必须经过敏感信息过滤和上下文预算计算。

### 5.2 Dream 维护 Turn

Dream 是复用 `AgentRuntime` 的后台维护 Turn：无工具、单实例、可取消、有独立预算。输入只包含有界任务摘要、现有记忆的结构化字段和去重键。输出只能是候选操作，不能指定真实 ID、权限、时间或路径。没有本地模型时提供离线 TTL 清理、重复键合并和确定性降权。

首次开启远程 Dream 时 UI 必须披露数据外发范围、Token 成本和关闭入口。Dream 失败不影响普通对话和已有记忆。

## 6. 检索设计

### 6.1 多路召回

1. 按线程工作区、Collection、启用状态和 active revision 过滤。
2. FTS5/BM25 召回最多 24 个候选。
3. 语义检索在 semantic 开启且凭据可用时召回最多 24 个候选；失败回退 lexical-only。
4. 标题、路径、代码符号和精确文件名作为额外召回通道。
5. 根据更新时间、用户反馈、文档状态和 revision 新旧程度进行重排。
6. 去除同一来源的重复 chunk，扩展父标题及前后各一个邻接 chunk。
7. 使用独立 knowledge budget，默认不超过工作上下文的 8%，最多返回 6 个 chunk。

### 6.2 初始评分

```text
score = 0.35 * lexical
      + 0.35 * semantic
      + 0.10 * title_or_symbol
      + 0.10 * path_match
      + 0.05 * freshness
      + 0.05 * user_feedback
```

分数仅用于宿主排序。模型不能提交权重、scope、endpoint、model 或绝对路径。

### 6.3 Query Rewrite

Query Rewrite 先使用确定性规则补充当前项目、最近实体和当前文件；可选模型改写最多产生 3 个短查询，不能增加路径范围或读取权限。改写失败直接使用原 query。

### 6.4 引用

每个结果生成绑定 `threadId + turnId + revisionId` 的 opaque `citationId`。`read_knowledge_citation` 只能读取当前 Turn 已返回的 citation；返回路径、行区间、revision 和文本，不重新读取工作区文件。

## 7. IPC 与工具契约

### 7.1 用户介导命令

```text
list_memories(scope, status, cursor, limit)
upsert_memory(memoryId?, content, type, scope, expiresAtMs?)
review_memory_candidate(candidateId, decision)
delete_memory(memoryId, confirmationToken)
clear_memories(scope, confirmationToken)
get_memory_settings()
set_memory_settings(enabled, autoAcceptHighConfidence, defaultTtlDays)
run_memory_maintenance()
```

命令只接受宿主生成的 scope 和 confirmation token；正文长度、ID、时间和枚举均由后端校验。

### 7.2 模型工具

```text
search_knowledge(query, limit?)
read_knowledge_citation(citationId, before?, after?)
propose_memory(operation, memoryType, content, reason)
propose_knowledge_fact(subject, predicate, object, citationId)
```

`propose_*` 只生成候选，不直接写入事实；模型不能提交 memory ID、collection ID、路径、scope、权限、endpoint 或删除确认令牌。

## 8. 安全和隐私

- 所有来源路径先规范化，再拒绝工作区外路径、符号链接和目录联接逃逸。
- 外部 embedding 只发送用户选择来源的有界 chunk 或当前 query，不发送绝对路径、环境变量、密钥或未选中文件。
- API Key 仅存操作系统凭据槽；日志和事件只记录 provider、状态码、脱敏 traceId。
- 记忆敏感等级由宿主检测和用户确认决定，模型字段不能降低敏感等级。
- 删除先写事实事件，再更新投影；支持重建和审计。
- Dream、索引任务和普通 Turn 使用独立取消令牌；应用退出时任务状态恢复为 queued/failed，不伪造成功。
- 任何未知 schema 版本、损坏 JSON、非法有限数值或超限输入都关闭失败。

## 9. 迁移与兼容

数据库 schema 迁移新增版本，不修改既有会话 JSONL。迁移步骤：

1. 创建实体、事实、记忆、候选、检索事件和反馈表。
2. 创建必要索引：`scope/status`、`normalized_key`、`source_chunk_id`、`created_at_ms`。
3. 保持现有 knowledge 表和 `knowledge_chunk_embeddings` 兼容。
4. 旧记忆 JSONL 只读兼容，首次写入时投影为 `memories`，不删除原文件。
5. 迁移失败时关闭新增命令，不删除会话、工作区文件或旧索引。
6. 提供从事件重建 SQLite 投影的命令和损坏恢复测试。

## 10. 测试与验收

### 10.1 单元和领域测试

- scope、TTL、版本递增、去重、冲突和敏感项分类。
- 候选 JSON 无效、超限、提示注入、非法 ID 和模型伪造删除。
- citation 跨线程、跨 Turn、过期和错误 revision 拒绝。
- FTS、语义、标题、路径、时间和反馈融合排序。
- embedding 失败、429、取消、维度错误时 lexical-only 降级。
- 事件重放、SQLite 重建、迁移失败和旧 JSONL 兼容。
- Dream 单实例、空闲判定、24 小时调度、取消、恢复和远程失败。

### 10.2 验收命令

```powershell
pnpm build
cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
cargo check --manifest-path src-tauri/Cargo.toml
```

## 11. 分阶段实施顺序

### Phase A：知识库稳定化

- 完成知识表、revision、FTS5、BGE-M3、增量索引和 citation。
- 增加检索评测夹具和 lexical-only 降级指标。

### Phase B：基础记忆

- 新增 `memories`、`memory_candidates`、事件和 IPC。
- 完成用户/项目 scope、TTL、审核、删除和旧 JSONL 兼容。

### Phase C：工作记忆与经验

- 从任务结果提取结构化摘要。
- 增加经验记忆、冲突检测和来源追踪。

### Phase D：Dream

- 复用 AgentRuntime 实现维护 Turn。
- 增加空闲调度、取消、预算、远程披露和离线维护。

### Phase E：检索增强

- 增加 Query Rewrite、父子 chunk、时间/反馈重排和多路召回。
- 用固定评测集验证权重，禁止直接根据单次反馈自动改变生产权重。

### Phase F：实体和关系

- 实体候选、事实候选、来源绑定、冲突和图查询。

### Phase G：外部来源和服务端数据库

- Git/OpenAPI 等连接器。
- 在规模和并发证据充分后，再评估 PostgreSQL/pgvector Repository 实现。

## 12. 完成定义

本设计对应的功能只有在以下条件同时满足时才算完成：

1. 所有新增事实都可由事件重建。
2. 模型不能绕过宿主 scope、策略和确认流程。
3. 无 embedding 凭据或远程失败时普通对话仍可用。
4. 记忆可查看、编辑、审核、过期和独立清除。
5. 检索结果可追溯到稳定 citation 和具体 revision。
6. 全部 Rust/前端检查通过，并完成真实 Tauri 桌面路径验证。
