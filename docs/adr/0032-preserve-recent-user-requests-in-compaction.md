# ADR 0032：Compaction 保留近期用户请求

## 状态

已接受，2026-08-15。契约版本 2 后由 ADR 0037 扩展为版本 3；近期用户请求的兼容语义保持不变。

## 背景

自动 Compaction 原本主要保留用户约束和近期工具结果。长对话中，用户最近提出的普通请求可能不包含“必须/不能”等约束词，压缩后只剩工具事实，模型会失去当前任务的直接意图。

## 决策

1. `CompactionSummary` 升级为契约版本 2，增加 `recent_user_messages`。
2. 每次压缩最多保留最近 4 条有界用户请求，每条最多 800 字节；纯图片消息保留有界的图片数量标记。
3. 压缩后的 Provider 上下文按“摘要、近期用户请求、用户约束、近期工具结果”的顺序生成。正文仍不包含私有推理、系统提示或未受控 Provider 载荷。
4. `ContextCompacted` 事件和历史 Item 只增加近期用户请求数量，不把请求正文复制到前端时间线。
5. 旧 JSONL 缺少该字段时按空列表恢复，不改变旧会话的读取和工具历史修复语义。

## 后果

- 长对话压缩后更可能保留当前用户意图，降低模型“只记得做过什么、不记得用户最后要什么”的问题。
- 每次压缩最多额外加入约 3.2 KiB 用户请求文本，仍受整体上下文预算和既有有界摘要约束。
- 时间线只展示保留数量，用户请求正文只进入下一次 Provider 上下文，不扩大审计载荷或暴露隐藏推理。

## 验证

- 压缩保留最近普通文本请求和图片请求标记。
- 旧 v1 摘要反序列化后 `recent_user_messages` 为空。
- 实时 `context_compacted` 与历史恢复的 Item 都携带相同的近期请求数量。
