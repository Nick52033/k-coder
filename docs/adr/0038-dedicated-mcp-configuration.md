# ADR 0038：MCP 专用配置与设置界面

- 状态：已接受
- 日期：2026-08-16

## 背景

Phase 7 已实现 MCP stdio、Streamable HTTP、系统凭据注入和运行时诊断，但用户只能手工编辑 `extensions.json`。设置中心只能查看状态、启停服务器和维护凭据，无法创建、修改或删除 MCP 服务器。继续让界面修改混合的 `extensions.json` 会把 MCP、Hooks 和未来扩展的写入契约耦合在一起，也难以安全处理格式错误文件、作用域覆盖和旧配置迁移。

## 决策

1. 新增全局 `runtime-data/mcp.json` 和项目 `.k-coder/mcp.json`。文件使用严格的 `{ "mcpServers": [...] }` 契约，不允许未知顶层字段。
2. 保留 `extensions.json` 中的 `mcpServers` 读取兼容，不自动迁移或重写用户文件。服务器合并优先级为“全局 `extensions.json`、全局 `mcp.json`、项目 `extensions.json`、项目 `mcp.json`”，后加载的同 ID 服务器覆盖前者。
3. MCP 设置页只提供全局/当前项目作用域的原始 JSON 编辑，不再维护一套与文件契约重复的可视化表单状态。页面提供格式化、即时结构校验、文件状态、真实运行时诊断、系统凭据编辑和 Hooks 折叠区；继承或旧配置只进入合并后的运行诊断，不隐式复制到当前文件。
4. `mcp_config(refresh)` 返回两份专用文件的路径、存在状态、原始文本、解析错误以及合并后的扩展诊断。即使运行时准备失败，也返回可修复的原始文本，并把失败原因放入诊断；无效配置不能继续提供 MCP 工具。
5. `save_mcp_config(scope, content)` 只接受 `global` 或 `project`。后端限制文件大小，要求 UTF-8 和严格 JSON，拒绝未知字段、重复 ID、无效命令、超时、URL、环境变量、Header 和凭据名称，再通过同目录临时文件替换目标文件并写入不含配置正文或密钥的审计事件。
6. 全局和项目目标路径都从受信任根目录解析。读取、创建父目录和替换文件前必须规范化已存在的根与最近父目录，拒绝绝对路径、父目录、符号链接和 Windows 目录联接逃逸。
7. `mcp.json` 只保存凭据名称映射。实际密钥继续使用 ADR 0003 定义的独立操作系统凭据账户；模型传入的字段、配置文本和诊断都不能成为授权依据或泄露密钥。

## 影响

收益：

- 用户可以在设置中心直接创建、编辑或清空标准 JSON，并完成运行诊断和凭据维护；格式错误的已有文件也使用同一个编辑面修复。
- MCP 写入契约与 Hooks 解耦，项目配置可以进入版本控制，全局配置保持用户级复用。
- 旧配置保持可用，作用域覆盖是确定性的，无效配置继续关闭失败。
- 前端校验改善即时反馈，后端校验和路径边界保持最终安全权威。

成本与限制：

- 同一服务器 ID 同时出现在多个文件时，只有最高优先级版本生效；界面不会自动删除低优先级定义。
- Windows 替换已有文件时受平台文件系统语义限制，但始终先在同目录写入完整临时文件，再替换目标。
- 当前界面不提供结构化表单、第三方配置导入、服务器模板或自动发现；其中表单是为避免重复状态和不完整字段映射而有意省略，其他能力仍需要独立契约和威胁分析。

## 未采用方案

### 直接把表单字段写入 SQLite

未采用，因为运行时事实会与用户可检查、可版本控制的配置文件分裂，也会让项目配置难以共享。

### 让前端直接访问文件系统

未采用，因为会绕过工作区路径规范化、链接逃逸防护、严格校验和审计边界。

### 自动迁移并删除 extensions.json 中的 MCP 配置

未采用，因为自动重写混合配置可能改变 Hooks 或用户格式，并会制造难以恢复的隐式变更。
