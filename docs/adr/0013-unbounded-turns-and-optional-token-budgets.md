# ADR 0013：无固定调用上限与可选 Token 预算

## 状态

已接受，2026-08-03。本 ADR 取代 ADR 0012 第 1、4 项中保留 24 次调用上限及自治任务必须设置 Token 预算的决定，也取代 ADR 0004 第 4 项和 ADR 0005 第 2 项中的必填 Token 预算部分。上下文窗口、累计用量、时间预算、权限和取消边界继续有效。

## 背景

复杂编程 Turn 可能需要连续读取、修改和验证超过 24 次。固定 Provider 迭代数与工具调用数无法区分持续取得新结果的任务和原地循环，最终会以 `tool_call_limit: exceeded 24 calls in one turn` 误杀仍在推进的对话。

普通 Turn 已默认不设累计 Token 上限，但 Goal 和子智能体仍会在前后端隐式注入固定 Token 预算。默认预算会产生同类误停，而且界面只适合展示有限预算百分比，不能准确表达“持续累计消耗但没有显式上限”。

## 决定

1. `AgentRuntime` 不再设置固定 Provider 迭代数或单 Turn 工具调用总数上限。单次响应、Provider 上下文、工具输出和文件边界仍保持有界。
2. 普通 Turn、Goal 和子智能体默认都不设置累计 Token 预算。Goal 与子智能体只在用户或宿主显式提供正整数预算时调用 `with_token_budget`，并继续硬性执行该预算。
3. Goal 与子智能体始终累计并展示 `tokens_used`。无显式预算时界面显示“已用 / 无上限”，有显式预算时显示“已用 / 预算”和百分比。
4. 运行时每 5 次 Provider 迭代检查实质进展。只有新的成功工具结果或新的文件内容变更会推进快照；连续 3 个检查窗口没有新进展时终止 Turn。失败生命周期事件和内容相同的重复结果不能伪造进展。
5. 同名同参工具调用的重复保护继续生效。自动 Compaction 按 ADR 0037 定义的硬窗口/工作基准和高水位触发；用户取消、Goal/子智能体时间预算和进程树清理继续提供外部终止能力。
6. 旧持久化记录中的数值型 `tokenBudget` 直接迁移为显式预算；缺失或 `null` 表示不设预算，不需要重写历史文件。

## 影响

- 持续获得新工具结果的 Turn 可以超过 24 次调用，不再被任意总次数截断。
- 默认运行不会因为累计 Token 消耗达到宿主预设值而停止，但真实用量仍被持久化和展示，供应商成本不会被隐藏。
- 移除总次数上限要求无进展检测只依赖稳定的领域结果，不能对每个新增日志事件都视为进展。
- 显式 Token 预算仍是用户选择的资源边界；时间预算、取消和权限约束不因默认无 Token 预算而放宽。

## 验证

- 一个包含 25 次不同成功工具结果的 Turn 能正常完成。
- 连续失败且没有新成功结果的工具循环由无进展检测终止。
- 显式 1,000 tokens 预算仍在累计 1,001 tokens 时失败。
- 无 Token 预算 Goal 在累计 2,500,000 tokens 后仍保持活动并更新消耗。
- 桌面和窄屏界面都显示无预算 Goal/子智能体的累计 Token 消耗，创建子智能体时默认不发送 `tokenBudget`。
