# ADR 0009：安全的运行时流式事件

## 状态

已接受，2026-08-02。

## 背景

模型会在同一 Turn 中交错产生可见说明、推理摘要和工具调用，命令工具也会持续产生 stdout/stderr。把这些内容压成最终消息会丢失时间顺序；直接展示原始推理或无限转发进程输出又会引入隐私、内存和背压风险。

## 决策

- 公共协议区分活动状态、安全推理摘要、助手正文和工具输出。
- 只接收 Provider 明确标记的 reasoning summary；不接收、不持久化、不展示原始 reasoning text。
- OpenAI Responses 请求 `reasoning.summary=auto`；Gemini `generateContent` 在推理启用时请求 `includeThoughts=true`，并且只把标记为 `thought` 的摘要文本转换为公共事件。Chat Completions 的非标准 `reasoning_content` 和 Anthropic 原始 thinking 块不视为安全摘要。
- 完成的安全摘要持久化为 Turn 时间线事件，但不进入 Provider 对话历史。
- Thinking 等活动状态和命令输出增量是瞬时事件。命令输出必须先经过运行时脱敏，再通过固定容量队列和有界批次转发；最终工具结果继续作为持久化事实。命令完成等待同时使用状态通知和 100ms 状态复核，进程已进入终态后不能因遗漏通知而无限停留在执行中。
- 前端对摘要和实时输出分别设置独立上限，并把 stdout/stderr 保留为不同展示流。
- 前端以 `turnTimeline` 作为文字、摘要和工具活动的唯一实时事实源，按 Turn/调用 ID 和输出游标去重；兼容数组只参与旧会话迁移，不能与时间线同时追加。
- 文本节奏缓冲只属于前端展示投影。Provider 增量、工具状态、运行时终态、持久化和消息队列继续立即处理；活动 Turn 按未展示正文积压量自适应揭示文字，并把最早一段尚未揭示完成的正文作为可见前缀边界，后到的工具、事件和正文必须等待该边界追平后再按事实顺序展示，多段正文也不得同时推进。终态到达后先排空已接收正文，再切换完成折叠。历史恢复和减少动态效果偏好不重放吐字动画。
- 消息列表只在视口贴近底部时随流式内容尺寸增长自动跟随。明确的向上滚轮、触摸或滚动条拖动必须暂停跟随，回到底部后恢复；任何已经排入动画帧的自动滚动在执行前都要重新检查用户意图，不能在终态或窄屏布局变化时强制跳底。
- 公共运行时指令要求多步骤任务在首次工具调用前，以及每组探索、修改或验证工具完成后、下一组工具开始前输出简短进度说明。说明只包含当前动作、刚确认的事实和下一步，不逐条复述命令，也不暴露私有思维链。
- 取消是请求而不是本地终态。界面保持运行状态，直到运行时发布或恢复出已持久化的终态；停止按钮与取消命令共同使用按线程活动表作为唯一目标来源，请求发出后立即显示“正在停止”并禁止重复提交，IPC 请求超时则恢复为可重试状态；排队消息绑定其原线程，重试复用已有用户消息。
- 活动 Turn 中从输入区发送的新内容只进入可见队列，不提前追加为用户对话消息，也不隐式取消当前 Turn。只有队列项的独立立即发送操作会把该项提升为其线程的下一项并请求取消；同一 Turn 的重复取消请求必须合并，持久化终态到达后才投影用户消息并启动新 Turn。
- Turn 调度以线程为隔离边界：同一线程最多一个活动 Turn，并保持 FIFO；不同线程拥有独立的活动表项、队列执行锁和取消请求，可以并行执行。前端只把所选线程的队列和时间线投影到当前界面，后台线程终态只释放自身队列并刷新会话摘要。
- 重试沿用失败或取消 Turn 持久化的 Craft、Ask 或 Plan 模式，并重新应用相同工具 Capability；`request_user_input` 使用宿主共享管理器，不能因重建运行时而产生无法解析的私有请求。
- 同一 Provider 响应中的工具调用严格按返回顺序串行执行。批次中的调用先投影为 pending，只有当前工具持久化并发布 started 后才成为 running；它的最终结果持久化并发布后才启动下一项，避免多个命令、搜索、写入或审批同时争用运行时资源，也避免刷新后把未启动项误报为执行中。
- 同一 Turn 的连续工具审批按请求 ID 持久化并在界面 FIFO 排队。线程恢复取消全部未决审批；解析已过期请求时只丢弃对应界面项，不把整个 Turn 误判为运行失败。
- 普通工具失败作为结构化结果回送 Provider，允许模型在同一 Turn 中修复并复验。审计或存储失败保持类型化致命错误；当前工具取消或失败后，同批剩余调用不再启动，但仍写入配对的跳过结果，完成必要回滚后终止，不能伪装成模型可继续处理的工具文本。Turn 启动后的未处理致命错误必须尽力落盘并发布 `turn_failed`。
- Provider 只有协议定义的正常终止原因才能发布完成。长度上限、内容过滤、上下文窗口和其他不完整终止统一转成失败，但同一终止帧的 Usage 仍需累计。无效工具 JSON 只在本次尝试尚未产生正文、摘要、工具调用或 Provider 上下文时允许重试；所有失败尝试的已知 Usage 都使用独立调用序号计入 Turn 累计值和显式预算。
- 助手正文、流式说明和安全摘要使用同一个 GFM Markdown 渲染器。禁用原始 HTML 和远程图片自动加载；代码块、表格及长内容必须保持有界并适配窄屏。
- 安全摘要是否持久化与是否进入可见对话相互独立。短小且只描述 planning、preparing、checking、running、testing 等当前动作的过程短句继续保留在 Turn 事实中，但不渲染原文；活动 Turn 由紧凑的通用状态表达仍在处理。包含结论、原因、风险、约束或足够上下文的摘要才显示为“思考摘要”：未完成时持续展开，完成后立即收起为可展开步骤。尚无工具活动和可见摘要的空时间线只显示无边框状态，不能使用大块空列表占据对话空间。进入 Turn 终态后完整执行过程继续默认折叠。该展示规则先由 `P10-044` 调整、再由 `P10-088` 降噪，不改变安全摘要的持久化和 Provider 上下文边界。
- 自动 Compaction 在领域事件落盘后发布带稳定事件 ID、来源和压缩消息/用户约束/近期工具结果三项计数的 `context_compacted` 实时事件；内部摘要和工具结果正文不复制到前端。当前时间线立即显示默认收起的“已自动压缩上下文”步骤，刷新恢复使用同一领域事件，不需要前端猜测阈值或制造本地终态。

## 结果

界面可以按真实时间顺序展示“思考、说明、执行、继续说明”，刷新后仍能恢复安全摘要、最终工具结果和多个审批的确定顺序。取消、切换线程和重试不会制造伪终态或重复用户消息，智能体也能在测试失败后继续修复。高频输出不会扩大 JSONL，也不能让慢消费者阻塞命令进程；代价是队列拥塞时对话内可能缺少部分瞬时输出，用户仍可依赖最终结果。
