# ADR 0009：安全的运行时流式事件

## 状态

已接受，2026-08-02。

## 背景

模型会在同一 Turn 中交错产生可见说明、推理摘要和工具调用，命令工具也会持续产生 stdout/stderr。把这些内容压成最终消息会丢失时间顺序；直接展示原始推理或无限转发进程输出又会引入隐私、内存和背压风险。

## 决策

- 公共协议区分活动状态、安全推理摘要、助手正文和工具输出。
- 只接收 Provider 明确标记的 reasoning summary；不接收、不持久化、不展示原始 reasoning text。
- OpenAI Responses 请求 `reasoning.summary=auto`；Gemini `generateContent` 在推理启用时请求 `includeThoughts=true`，并且只把标记为 `thought` 的摘要文本转换为公共事件。Chat Completions 的非标准 `reasoning_content` 和 Anthropic 原始 thinking 块不视为安全摘要。
- 完成的安全摘要持久化为 Turn 时间线事件，但不进入 Provider 对话历史。
- Thinking 等活动状态和命令输出增量是瞬时事件。命令输出必须先经过运行时脱敏，再通过固定容量队列和有界批次转发；最终工具结果继续作为持久化事实。命令完成等待同时使用状态通知和 100ms 状态复核，进程已进入终态后不能因遗漏通知而无限停留在执行中。
- 前端对摘要和实时输出分别设置独立上限，并把 stdout/stderr 保留为不同展示流。
- 前端以 `turnTimeline` 作为文字、摘要和工具活动的唯一实时事实源，按 Turn/调用 ID 和输出游标去重；兼容数组只参与旧会话迁移，不能与时间线同时追加。
- 取消是请求而不是本地终态。界面保持运行状态，直到运行时发布或恢复出已持久化的终态；排队消息绑定其原线程，重试复用已有用户消息。
- 活动 Turn 中从输入区发送的新内容只进入可见队列，不提前追加为用户对话消息，也不隐式取消当前 Turn。只有队列项的独立立即发送操作会把该项提升为下一项并请求取消；同一 Turn 的重复取消请求必须合并，持久化终态到达后才投影用户消息并启动新 Turn。
- 同一 Provider 响应中的工具调用严格按返回顺序串行执行。只有当前工具发布 started 状态；它的最终结果持久化并发布后才启动下一项，避免多个命令、搜索、写入或审批同时争用运行时资源。
- 同一 Turn 的连续工具审批按请求 ID 持久化并在界面 FIFO 排队。线程恢复取消全部未决审批；解析已过期请求时只丢弃对应界面项，不把整个 Turn 误判为运行失败。
- 普通工具失败作为结构化结果回送 Provider，允许模型在同一 Turn 中修复并复验。审计或存储失败保持类型化致命错误；当前工具取消或失败后，同批剩余调用不再启动，但仍写入配对的跳过结果，完成必要回滚后终止，不能伪装成模型可继续处理的工具文本。
- 助手正文、流式说明和安全摘要使用同一个 GFM Markdown 渲染器。禁用原始 HTML 和远程图片自动加载；代码块、表格及长内容必须保持有界并适配窄屏。
- 活动 Turn 中已经收到的安全摘要持续展开；摘要完成只表示该摘要项停止追加，不能在 Turn 仍运行时立即把内容收起。尚无工具活动的空时间线只显示无边框的紧凑单行状态，不能使用大块空列表占据对话空间。进入 Turn 终态后再随执行过程默认折叠。

## 结果

界面可以按真实时间顺序展示“思考、说明、执行、继续说明”，刷新后仍能恢复安全摘要、最终工具结果和多个审批的确定顺序。取消、切换线程和重试不会制造伪终态或重复用户消息，智能体也能在测试失败后继续修复。高频输出不会扩大 JSONL，也不能让慢消费者阻塞命令进程；代价是队列拥塞时对话内可能缺少部分瞬时输出，用户仍可依赖最终结果。
