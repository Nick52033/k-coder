# ADR 0045：基于文件版本与覆盖区间收敛工具观察

## 状态

已接受，2026-08-21。

## 背景

一次修改 `GetCompanyConfig` 的真实 Turn 持续约 30 分钟。补丁在前 9 分钟已经成功应用，但后续仍产生 37 次模型响应和 59 次工具调用，其中 52 次是对同一文件的重叠读取。60 次 `read_file` 都成功且非空，问题不是权限确认或读取失败，而是运行时把变化过的行范围参数和输出片段误判为新进展。

同一 Turn 的两次 Compaction 还保留了修改前的 `JObject.Parse` 观察。旧摘要、近期工具结果和修改后的真实读取同时进入下一轮，模型因此不断尝试“确认真实状态”。DeepSeek 缺少可回传私有推理时的安全降级会放大这种不一致，但不是唯一根因。

## 决策

1. `read_file` 的结果元数据必须包含规范化工作区相对路径、完整文件字节的 SHA-256 修订、实际开始/结束行和既有范围信息。读取不同片段不得产生不同文件修订。
2. `AgentRuntime` 在一个 Turn 内按“规范路径 + 文件修订”合并已返回的行区间。新修订和非重叠区间属于进展；请求区间已有至少 80% 被覆盖时，不再把重复正文送回 Provider。
3. 第一次高度重叠读取返回成功的 `read_observation_already_covered` 结构化观察，说明文件未变化、正文已抑制以及可选的下一步。相同修订再次出现高度重叠读取时，以 `repeated_observation_loop` 类型化失败终止 Turn。插入搜索、目录读取或改变 `startLine/lineCount` 不能重置该计数；文件修订变化后自动允许一次新的针对性验证。
4. 进展快照不再把每个成功工具输出字符串直接当作进展。文件读取使用路径、修订和新增覆盖区间；目录、搜索和命令使用各自稳定观察修订；已抑制的重复观察不计进展。
5. Compaction 遇到当前消息中的最新成功 `apply_patch` 或 `write_file` 时，以该结果作为工作区事实失效边界。继承摘要中的工具观察、近期工具结果和自由摘要正文全部清除；当前消息中边界之前的读取、搜索和命令事实不再进入摘要或保留历史。真实用户请求、用户约束以及写入结果继续保留。
6. DeepSeek 安全降级的固定 user 续跑意图必须要求：工作已经应用并充分验证时立即给出最终答复；只有存在具体未决事实时才能继续调用工具；不得为再次确认而读取未变化文件的重叠区间。
7. 确定性仓库搜索限制同一行重复词的加权，并降低 `.min.js`、`.min.css`、`wwwroot/lib`、vendor 和 third-party 路径的排序权重。`run_command` 无输出失败必须返回退出码；`rg` 退出码 1 明确表示没有匹配。

## 安全与边界

- SHA-256 只标识已通过工作区规范化和链接逃逸检查的文件内容，不扩大可读取路径，也不替代 Patch 的审批前哈希校验。
- 收敛状态只存在当前 `AgentRuntime` Turn 内，不写入模型可控权限字段；Compaction 不会重置它。
- 重复观察仍作为有界 `ToolResult` 审计并进入 JSONL；正文抑制不删除之前已经持久化的读取事实。
- `repeated_observation_loop` 在第三次同修订高度重叠观察时关闭 Turn，避免继续产生模型费用或重复副作用。写入工具、命令策略、审批、取消和进程树边界保持不变。
- Compaction 只改变发给 Provider 的派生历史，不重写原始 JSONL 事实。

## 影响

简单修改在补丁成功和一次针对性验证后应自然收尾。模型即使通过移动行范围或插入搜索绕过字面同参检测，也无法持续取得相同正文。成功写入后的压缩历史只表达当前事实，不会把修改前实现提升为新的用户上下文。

代价是模型连续第三次读取同一修订的高度重叠区间会使当前 Turn 失败；若确有新事实需要读取，应请求未覆盖区间，文件发生变化时运行时也会自动建立新的修订状态。

## 验证

- 单元测试覆盖稳定文件修订、内容变化、新增覆盖、重叠抑制、插入其他工具仍终止以及新修订恢复读取。
- Compaction 回归覆盖旧 `JObject.Parse` 观察、成功 Patch、当前用户请求和写入结果；压缩结果不得包含旧标记。
- Provider、搜索、命令和系统提示测试覆盖最终答复边界、源码符号排序、`rg` 无匹配和一次针对性验证约束。
- 质量门槛执行 `pnpm build`、Rust 格式检查、`cargo check`、`cargo test` 和 `git diff --check`；桌面路径使用隔离应用标识和本地假 Provider 验证。
