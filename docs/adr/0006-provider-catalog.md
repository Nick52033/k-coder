# ADR 0006：多供应商配置与凭据隔离

- 状态：已接受
- 日期：2026-07-25

## 背景

设置页曾把多个供应商保存在浏览器 `localStorage`，而 Rust 运行时只持久化一个 `provider.json` 和一个 API Key。界面可以创建多条记录，但只有默认记录能参与 Turn，非默认供应商的密钥也没有真实保存，输入区因此无法安全切换供应商。

## 决策

运行时使用 `providers.json` 持久化版本化供应商集合和唯一活动供应商 ID。每个供应商拥有稳定 ID、公开配置和独立的操作系统凭据账户；公开载荷只返回 `hasApiKey`，不得返回密钥。

旧 `provider.json` 在读取时作为 ID 为 `default` 的供应商迁移，旧默认凭据账户仅为该 ID 提供兼容读取。前端旧供应商列表只迁移公开配置，不信任其中的 `hasApiKey` 标记；无法恢复的密钥必须由用户重新输入。

保存非活动供应商时允许暂缺密钥，便于完成公开配置迁移；激活、连接测试和发起 Turn 前必须确认该供应商自己的凭据存在。删除供应商时同时删除其独立凭据，并确定性选择剩余首项作为活动供应商。

## 影响

- 设置页、输入区选择器和运行时共享同一供应商事实来源。
- 切换供应商不会复用其他供应商的 API Key。
- 旧单供应商配置和凭据继续可用，无需手工迁移。
- 历史上只存在于前端内存或 `localStorage` 的非默认 API Key 无法恢复，用户需要重新填写。
