# ADR 0040：本地 Codex 插件兼容宿主

- 状态：已接受
- 日期：2026-08-17

## 背景

k-Coder 已通过 `ExtensionService` 统一管理规则、Skills、MCP、Hooks、工具风险、审批、取消和审计，但用户取得的 Codex 插件目录此前不能作为一个整体被发现、诊断和管理。若为插件另建智能体循环、工具执行器或权限模型，会产生重复状态、工具覆盖、路径逃逸和密钥泄露风险；若把插件当作可信安装包执行，又会把不兼容组件静默升级为宿主权限。

## 决策

1. 插件只通过本地目录投放。宿主扫描 `<app_data_dir>/runtime-data/plugins` 的直接子目录，并只把包含 `.codex-plugin/plugin.json` 的目录视为候选。k-Coder 不提供市场、下载、解包、升级或外部运行时安装。
2. 有效插件使用稳定 ID `<manifest.name>@local`，首次发现默认禁用。启用意图写入现有设置投影；同一次应用运行中已启用插件消失时，宿主移除其能力并把设置重置为禁用，重新复制不会静默恢复执行。
3. 插件能力复用唯一 `ExtensionService`、`ToolRegistry`、`AgentRuntime` 和 `PolicyEngine`。每次发现、启停、删除或修订变化都重建完整注册表；准备失败时先回退到不含插件能力的基础注册表，旧处理器不得残留。
4. 插件内容按不可信输入处理。所有清单、组件、Skill、资源、MCP 工作目录和删除目标都从受信任根解析并规范化；拒绝绝对路径、`..`、符号链接、Windows reparse point、目录联接和规范化逃逸。删除命令只接收当前索引中的插件 ID，不接收调用方路径，并在删除前再次确认目标仍是同一个直接子目录。
5. 支持 Codex 常见的 `skills` 目录。宿主只把有界的插件、Skill 名称和描述加入运行时目录；正文和已索引 UTF-8 资源分别通过 `plugin_skill_read` 与 `plugin_resource_read` 按需读取。两者是普通只读工具，仍受模式能力收缩与策略链约束；Skill 清单中的风险或权限字段不能授权工具。
6. 支持插件 `.mcp.json` 中常见的 stdio 与 Streamable HTTP 子集。服务器 ID 使用插件隔离且有界的命名空间；工作目录固定在插件根内，`${CODEX_PLUGIN_ROOT}` 是唯一替换变量。除 `CODEX_PLUGIN_ROOT` 外，环境变量名和 HTTP bearer 名都解释为现有操作系统凭据名称，秘密值只在进程环境或请求 Header 内存中出现。
7. 既有全局/项目 MCP 配置继续维持 ADR 0003 和 ADR 0038 的整体关闭失败语义；插件 MCP 按插件和服务器隔离失败。一个插件组件失败不会阻止其他插件或配置来源，失败组件不注册任何工具，完整注册表重建会移除上一轮处理器。
8. Apps、`.app.json`、Codex/Claude/Cursor Hooks、`agents/`、`commands/` 和 OAuth MCP 只进入组件摘要与诊断，本期不执行。需要 Node、Python 或其他外部二进制时，宿主只报告实际启动错误，不自动安装依赖，也不退化到匿名或更宽权限模式。
9. 公共状态固定为 `disabled`、`loaded`、`degraded`、`blocked` 和 `invalid`。启用开关表达用户意图，因此组件失败时可以保持 `enabled: true` 并显示 `degraded` 或 `blocked`；“已发现”或“已启用”不等同于依赖已就绪。
10. 设置页只提供刷新、启用、禁用和经确认的删除，并以版本化后端诊断作为唯一事实。启停、消失、连接和删除写入既有扩展审计，但不得记录插件正文、完整环境变量、授权 Header 或秘密值。

## 影响

收益：

- 用户可以直接投放已有 Codex 插件目录，并在不引入第二套运行时的前提下复用其 Skills 和常见 MCP 配置。
- 插件 ID、工具名、凭据槽和失败范围彼此隔离；禁用、删除、无效化或消失后不会遗留旧能力。
- 对不支持组件和缺少运行时的情况提供可修复诊断，不以兼容名义削弱工作区、审批、取消、进程清理或密钥边界。

成本与限制：

- 兼容范围是明确子集，不承诺执行任意 Codex 插件组件。
- 插件作者依赖的外部运行时和凭据需要用户自行准备；k-Coder 不充当包管理器或 OAuth 客户端。
- 每次插件事实变化都重建扩展注册表，换取确定性的能力撤销和诊断。

## 未采用方案

### 为插件建立独立智能体循环

未采用，因为它会复制 Provider、工具、策略、取消和持久化语义，并允许插件绕过主运行时的安全链。

### 自动下载或安装插件依赖

未采用，因为远程来源、解包、供应链、签名、升级和回滚需要独立威胁模型，超出本地兼容宿主的范围。

### 发现后默认启用

未采用，因为目录内容和其中引用的进程都属于用户提供的不可信输入；明确启用是执行插件能力前的必要宿主状态。

### 遇到不支持的 OAuth 时匿名连接

未采用，因为这会改变插件的认证语义并可能把请求发送到错误的安全上下文。不支持的认证必须显示为 `blocked` 或 `degraded`。
