# ADR 0057：子智能体批量等待与主任务调度

- 状态：已接受
- 日期：2026-09-10
- 关联：P10-163、ADR 0004、ADR 0013、ADR 0018

## 背景

子智能体创建后已使用独立 AgentRuntime 并行运行，但主任务只能按单个 ID 等待结果。等待较慢任务时，较快任务的结果无法及时用于审阅、补充工作或失败处理。工具等待耗时和子任务生命周期耗时在界面中也容易混淆。

## 决策

1. 保持唯一主 AgentRuntime 和工具串行执行。创建独立子任务后，提示主任务先处理自身可独立推进的工作，再等待；不重复子任务工作，不要求等待期间另开推理循环。
2. 扩展现有 `wait_agent`，不增加工具数量。`agentId` 保留原有单任务快照响应；`agentIds` 接受 1～4 个不重复 ID，两种输入互斥。先检查整个批次的父会话归属，再开始等待或返回任何结果。
3. 批量结果版本为 1，返回 `agents`、`finishedAgentIds`、`timedOut`。任一目标达到 completed、failed、cancelled 或 timed_out 时返回；已结束目标立即返回。主任务处理结果后仅对剩余活动目标继续等待。
4. 批量快照只包含 ID、状态、有界摘要和错误、截断标记、累计 tokens 与更新时间。每个摘要最多 4096 UTF-8 字节，错误最多 512 字节，按字符边界截断；不返回可能很长的原任务正文，避免通用工具输出截断破坏 JSON。`truncated=true` 时可用单任务查询获取完整快照。
5. `timeoutMs` 默认 30000，0 表示即时快照，上限沿用 30 分钟。等待采用固定截止时间；无关任务的通知不重置超时。先登记通知再读取状态，避免状态读取与挂起之间错过完成通知。通知只影响等待，不启动模型推理。
6. 等待超时不取消子任务；等待自身取消立即返回。父 Turn 取消仍通过既有父子令牌传播。权限、并发、工作区、预算和写入冲突保护保持原运行时边界。
7. 只有实际阻塞至少 1 秒、成功返回且目标全部仍活动的等待才重置连续重复调用和无进展计数；快速快照、失败、终态结果与其他工具不豁免。子智能体时间预算与主任务软续跑门继续有效。
8. 对话行展示整个等待批次的 task 标签和“等待耗时”。超时明确显示“本次等待结束，子任务仍在运行”；右侧单独展示子任务从创建到最近状态更新的耗时，包含等待与恢复间隔。复用 Tool Item 与已有历史投影，不增加事件版本或持久化迁移。

## 验证

覆盖较快的第二个任务先返回、所有终态、多个等待者、固定截止时间、取消、跨会话拒绝、无效批次、JSON 大小与 Unicode 边界、单任务兼容和循环保护。前端验证四标签、超时、结果和详情定位；真实隔离 Tauri 宿主通过本地 SSE 验证创建、主任务独立工具工作、超时、先快后慢收集与刷新恢复。
