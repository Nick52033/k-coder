# ADR 0034：命令活动只显示单行状态

- 状态：已接受；多命令展开高度于 2026-08-15 由 `P10-101` 修订，失败摘要于 2026-08-16 由 `P10-109` 修订
- 日期：2026-08-15
- 关联：ADR 0010、ADR 0033、P10-049、P10-081、P10-100、P10-101、P10-109

## 背景

工具组已经采用紧凑折叠摘要，但展开纯命令组后，每条 `run_command` 仍重复显示动作标题、状态与耗时、Shell/工作目录/超时参数卡，以及命令输出折叠。命令文本同时出现在标题和参数卡中，层级过多，连续验证命令会显著拉长对话。

界面隐藏输出与模型上下文治理是两个不同问题。Provider 需要看到有界工具结果才能判断构建、测试或检查是否成功；前端是否渲染这些结果不会改变已经持久化并发送给 Provider 的历史。

## 决策

1. 展开命令组后，每条 `run_command` 只显示状态图标、脱敏后的原始命令文本和一个内联状态。
2. 命令状态固定映射为：pending“等待运行”、running“运行中”、completed“已运行”、cancelled“已取消”。failed 至少显示“运行失败”；存在 `recoveryHint` 时追加最多 180 字符的有界恢复提示，否则追加 `ToolResult.output` 的首条非空脱敏错误，空间不足时单行省略。
3. 命令行不再渲染耗时、Shell、工作目录、超时参数卡或“命令输出”子折叠；长命令允许在可用宽度内换行，失败摘要占用受限宽度并可省略，不把完整输出写入 DOM。多个连续命令的展开内容区高度上限为 168px，换行或命令数量导致内容超出时在组内纵向滚动；单命令保持自然高度。
4. 该变更只收敛 `run_command` 的前端投影。`ToolResult`、实际 Shell 元数据、有界且脱敏的 stdout/stderr chunks、JSONL、历史恢复、Provider 工具历史和 Compaction 输入保持不变。
5. 非命令工具沿用现有参数详情、文件详情、输出和耗时展示规则。

## 影响

- 连续命令组展开后不再出现重复命令卡和输出卡，实时与历史命令使用相同的紧凑行。
- UI 的可见长度和 DOM 节点减少，但模型上下文不会因为隐藏界面元素自动变短；上下文长度继续由工具输出边界和 Compaction 策略控制。
- 失败命令在对话中保留明确失败状态，并直接给用户一条足以区分路径、语法或执行错误的有界摘要；完整错误继续只由持久化工具结果提供给智能体和审计链路。
