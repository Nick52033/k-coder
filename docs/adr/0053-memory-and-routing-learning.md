# ADR 0053：记忆整理与本地模型路由自学习

- 状态：提案，待 `P10-142` 验收后实施
- 日期：2026-09-08

## 背景

k-Coder 已有用户显式维护的记忆、可恢复会话事件、Provider fallback、运行指标和知识库检索。产品希望增加两个能力：周期性调用模型整理记忆（dream），以及根据用户纠错学习模型/端点选择偏好。两者如果直接共享一套“自动学习”状态，会把用户内容、模型选择、Provider 配置和权限边界混在一起，也容易误把远程 dream 描述成完全本机能力。

## 决策

1. 记忆与路由学习分域。记忆保存有来源、作用域、置信度、保留期和修订的用户/项目事实；路由学习只保存有限数值特征、候选目标 ID、结果枚举和有界奖励。
2. dream 是复用唯一 `AgentRuntime` 的维护 Turn，不注册工具，不读取任意路径，不改变 `PolicyEngine`，模型输出必须经过宿主结构化校验。模型只能提出候选，不能指定 ID、时间、权限或删除事实。
3. 路由学习第一期采用本地 contextual bandit，先 shadow 后 active。active 只在用户已启用且能力匹配的 Provider 目标内重新排序；用户明确指定模型、视觉能力不匹配、高风险 Turn、目标删除和模型异常时使用 baseline/fallback。
4. `routingLearningEnabled` 开启时自动开启 `dreamEnabled`；用户单独关闭 dream 后仍采集样本，但不自动训练。训练不会因为普通 Turn 自动修改模型快照。
5. 远程 dream 必须在 UI 首次开启时披露数据外发和 Token 成本。只有路由特征提取、样本持久化和训练保证完全在本机；没有本地模型时的离线模式只做确定性 TTL/重复清理。
6. 事实事件由 `storage` 负责追加和投影。现有记忆 JSONL 保持兼容读取；学习样本、模型快照和决策使用版本化事件与 SQLite 投影，并提供保留期、重建、取消和回滚语义。
7. 自动记忆只允许高置信、非敏感的新增/更新；模型提出的删除、冲突和敏感项进入待审核。清除记忆与清除学习数据是两个独立、可审计、可恢复确认动作。

## 后果

### 收益

- 用户可以明确控制记忆整理、路由采样、训练和 active 路由的每一层状态。
- 路由样本不包含对话原文，训练和模型快照可以在本机完成，且能审计和回滚。
- 现有 Provider fallback、工具策略、工作区安全边界和唯一 AgentRuntime 不被绕过。
- 没有 Provider、远程失败或训练失败时，普通对话仍使用旧记忆和 baseline 路由。

### 成本与限制

- 远程 dream 仍可能外发脱敏会话材料并产生 Token 费用；若产品要求绝对离线，需要本地模型 Provider 或仅提供确定性维护。
- contextual bandit 的收益必须通过回放和 A/B 指标证明，不能把模型分数直接当成质量提升。
- 记忆 schema、学习特征 schema、事件日志和 SQLite 投影都需要迁移与损坏恢复测试。
- 第一阶段不做 LLM 微调、不自动新增 Provider、不学习权限策略，也不替换知识库检索。

## 不采用的方案

### 保存完整对话用于训练

不采用。它扩大隐私、磁盘和删除边界，且与“只保存特征向量”的产品约束冲突。dream 只读取有界的宿主摘要输入，路由样本完全不保存原文。

### 让模型直接选择或修改 Provider 配置

不采用。模型返回的目标、权限和配置字段不能成为授权依据；路由目标集合必须由用户配置和宿主能力过滤得到。

### 使用独立的第二套智能体循环

不采用。维护 Turn 复用 `AgentRuntime` 的取消、预算、Provider 事件、审计和失败语义，避免普通 Turn 与后台任务出现两套不一致的协议。

### 一开启就 active 路由

不采用。冷启动和错误样本会造成不可解释的回归；必须先积累样本、shadow 评估，并允许用户随时回到 baseline。

## 验证

- 记忆 scope、TTL、敏感信息、候选审核、删除和旧 JSONL 兼容测试。
- dream 24 小时调度、空闲判定、单实例、恢复、取消、无效 JSON、提示注入和远程失败测试。
- 特征向量确定性、有限数值、样本保留、无原文持久化、模型版本、shadow/active、能力过滤和 baseline 回退测试。
- `pnpm build`、Rust 格式检查、`cargo check`、Rust 全量测试以及真实 `pnpm tauri dev` 的设置/反馈/重启恢复验证。
