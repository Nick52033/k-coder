# ADR 0054：本地定时任务复用 AgentRuntime

## 状态

已接受（2026-09-08）

## 背景

用户需要让检查、整理和回顾类工作按固定时间自动运行。定时任务会在应用窗口隐藏到系统托盘后继续工作，因此它既是持久化数据，也是一个可能触发文件读取、修改和命令执行的智能体入口。把它做成前端计时器或直接调用 Provider 都会绕过现有 Turn、工作区和审批边界。

## 决策

1. 任务定义保存在 `runtime-data/scheduled-tasks.jsonl`。每次创建、编辑、启停、领取和运行收尾都追加一个带 `revision` 的完整快照，启动时按 ID 取最新未删除快照；损坏的末尾不完整行按既有 JSONL 兼容规则忽略，其他格式错误关闭读取。
2. 首版支持一次性、每天和每周三种计划。时间使用操作系统本地时区，后端根据 `chrono::Local` 计算 `nextRunAtMs`，不信任前端提交的下一次时间。一次性任务成功或失败收尾后自动停用，周期任务计算下一次本地触发时间。
3. 任务可以创建后台新会话，或把提示词发送到用户明确选择的已有会话。任务绑定规范化的项目空间；执行时如果该空间不是当前活动工作区则失败并保留下一次计划，不能自动切换全局工作区或改绑会话。
4. `ScheduledTaskStore` 只负责 CRUD、领取门闩、运行摘要和下一次计划。唯一后台调度器每 5 秒轮询，到期任务按任务 ID 去重后交给 `commands::execute_scheduled_task`；该函数调用现有 `execute_turn`，由同一个 `AgentRuntime` 处理 Provider、工具、审批、取消、超时、持久化和事件发布。
5. 调度任务不获得特殊授权。默认审批模式、工具风险、项目/独立会话能力收缩和工作区边界与手动 Turn 完全一致；无法在托盘中完成的审批会按既有超时语义失败，不自动提升为完整访问。
6. 桌面管理页通过类型化 IPC 展示任务、启停、立即触发、删除和运行摘要。立即触发只把下一次时间置为当前时间，由同一调度器领取，不在前端启动隐藏执行；批量操作逐项调用后端命令，失败保持可见。

## 取舍与后续

- 首版不依赖操作系统 Task Scheduler/cron，避免跨平台安装、升级和卸载的一致性问题；应用进程必须保持运行（可隐藏到托盘）。
- 首版不提供自定义时区、间隔秒级触发、Webhook 或远程唤醒。后续若增加这些能力，必须先定义唤醒、凭据、并发上限和外部副作用审计。
- 多任务可以并行进入现有 AgentRuntime，但每个任务自身只有一个领取实例；任务不会因为前端页面关闭而取消。

## 验证

- Rust 单测覆盖非法时间、未来一次性计划、每日下一次时间、追加快照恢复、领取去重和一次性完成自动停用。
- 前端构建覆盖类型化 schedule/mode 契约；桌面验收需确认侧栏入口、创建/编辑、启停、立即运行和托盘隐藏后调度路径。
