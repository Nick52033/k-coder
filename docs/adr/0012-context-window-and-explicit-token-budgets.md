# ADR 0012：区分上下文窗口、累计用量与显式 Token 预算

## 状态

已接受，2026-08-03；其中第 1、4 项关于 24 次调用上限和自治任务必填 Token 预算的决定已由 ADR 0013 取代，第 3 项的具体硬/工作上下文预算由 ADR 0037 细化。本文继续定义上下文窗口、累计用量、Compaction 和显式预算之间的区别。

## 背景

一个工具型 Turn 会在每次工具结果返回后再次调用模型。每次请求都携带当前上下文，因此一个约 145,000 tokens 的活动上下文连续调用七次，会产生超过 1,000,000 tokens 的真实累计统计，但当前上下文仍未超过模型窗口。把累计统计当作上下文安全边界会误杀仍可继续的复杂任务，并且与基于当前窗口的自动 Compaction 脱节。

运行时还支持 Goal 和子智能体。这些自治任务的累计 Token 预算是用户或宿主明确声明的资源边界，不能与普通对话的上下文窗口限制合并。

## 决定

1. 普通 Turn 不设置固定累计 Token 硬上限。24 次 Provider 迭代、24 次工具调用、重复调用、无进展、响应大小和取消边界继续生效。
2. Provider 每次调用的用量继续持久化；各次相加只用于 Turn/线程统计，最近一次调用的 `total_tokens` 用于表示当前活动上下文窗口。
3. 自动 Compaction 同时参考确定性本地估算和最近一次 Provider 当前窗口用量。活动模型 `contextWindow` 是硬上限；具体压缩高水位、工作上下文基准和低水位由 ADR 0037 定义，当前默认使用硬窗口以内的工作基准的 65% 在 Turn 前或 Turn 中压缩并继续。
4. `with_token_budget` 只表示 Goal、子智能体等显式累计预算，仍由宿主硬性执行，且单次配置不得超过 1,000,000 tokens。
5. Compaction 恢复不得重放孤立工具结果。近期结果以有界文本加入摘要，结构化工具输出只有在其调用仍存在时才能发送给 Provider。

## 影响

- 长工具循环可以跨过 1,000,000 累计 tokens，只要当前上下文和其他运行时边界仍然有效。
- 用量统计仍反映真实重复调用成本，取消固定硬停不代表请求免费或不会消耗供应商额度。
- 显式自治预算继续失败关闭，不会因为普通 Turn 语义调整而失效。
- Provider 未返回用量时，本地字符估算仍提供 Compaction 后备判断。

## 验证

- 普通 Turn 在八次调用累计 1,160,800 tokens 后完成。
- 显式 1,000 tokens 预算在累计 1,001 tokens 时失败。
- Provider 报告当前窗口超过 ADR 0037 工作基准的 65% 高水位时，在下一次采样前产生自动 Compaction。
- 压缩事件恢复后只生成摘要文本，不生成孤立 `function_call_output`。
