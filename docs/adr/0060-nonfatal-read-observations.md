# ADR 0060：成功读取返回正文，重复观察不单独终止 Turn

## 状态

2026-09-18，按用户反复遇到 `repeated_observation_loop` 的反馈修订。取代 ADR 0045、0046 中按文件覆盖比例抑制正文、临时纠偏后硬停和压缩后固定补读额度的决定。来源头、文件修订、写后摘要失效和原有安全边界继续有效。

## 原因与 Codex 对照

本地 `D:/code/codex/codex-rs/core/src/tools/parallel.rs` 的 `handle_tool_call` 把成功结果和普通工具错误编码为工具输出；只有明确的 `FunctionCallError::Fatal` 上升为运行时失败。`core/src/session/turn.rs` 根据 `needs_follow_up` 继续采样，并在上下文达到阈值时压缩后继续。核查的这两条执行路径没有按文件修订、行覆盖或重读次数中止 Turn 的分支。

`core/gpt_5_2_prompt.md` 通过模型指引减少补丁后的重复读取。该指引的存在不等于运行时会强制禁止重读，也不能由 `skills.read` 的分页缓存推断所有文件读取行为。

k-Coder 的旧策略把“此前返回过正文”当作“模型当前仍拥有且足以使用正文”。压缩、工具输出裁剪和长任务会使这一假设失效。第一次 80% 重叠就抑制全部内容，还会丢弃同次读取中尚未返回的部分。把一次补读窗口从 1 批增加到 8 批只是推迟相同问题。

## 决定

1. 每次成功的 `read_file` 都返回经过现有输出上限处理的真实正文。完全覆盖的读取可添加简短建议，提示复用已有事实、只做有目的的补查；不将其变成失败、不注入强制禁止读取的 System 消息，也不再产生新的 `repeated_observation_loop`。
2. 不设置路径/修订的终身补读额度。成功压缩和成功机器人节点切换只清空当前上下文的重复提示记录；正文读取始终经过原工具的路径规范化、工作区边界、编码、文件大小和输出上限校验。
3. 保留 ADR 0013 的全局无进展保护：每 5 轮检查，连续 3 个窗口没有新事实时终止。读取进展按规范化路径、文件修订和累计合并的实际返回范围计算；完全重复或只是改变范围形状不算进展，任何新增范围都算进展。字节分页不能被相同行号误判为重复；被运行时裁掉的正文不算已经返回。
4. 压缩和重复提示状态重置不清空全局进展事实，不能用反复压缩绕过无进展保护。零字节读取只建立首次路径/修订观察，改变空读取的偏移量不增加覆盖；UTF-8 字符边界回退造成的空正文也遵守该规则。持续取得其他真实工具结果的任务可以继续执行。
5. 连续失败或缺少版本化元数据的读取继续走原有同参保护；其他工具的同参保护、取消、显式预算和普通 Turn 软续跑门不变。
6. 旧 JSONL 和 `TurnError` 中的 `repeated_observation_loop` 保持可读兼容，不改写历史。Provider-facing 来源头继续由宿主结果元数据派生，模型不能用参数中的权限或修订字段改变上述行为。

## 验证要求

- 连续成功重读后可以最终完成，每次正文都进入工具结果和下一次 Provider 请求。
- 多次 Compaction、超过 8 批补读、同批多范围以及跨机器人节点读取都保持正文可用。
- 高重叠但含新增内容、字节分页和输出裁剪后的缺失部分被认作真实新覆盖；改变重叠范围形状不能伪造进展。
- 完全重复读取仍由整轮无进展保护有界终止；失败读取和工作区越界保护继续生效。
- 执行项目四项质量命令，并使用隔离的 `pnpm tauri dev` 与本地确定性 Provider 验证实际桌面完成和停止路径。
