# ADR 0048：用户介导的本地文件附件

## 状态

已接受，2026-08-28。

## 背景

k-Coder 已支持在输入区粘贴图片像素，也能从工作台把工作区文件附加到消息，但不能直接处理用户从资源管理器、桌面或其他应用复制后粘贴到对话框的文件。现有 `extract_attachment` 只接受工作区相对路径；为了支持任意本地文件，如果直接放宽该命令为绝对路径读取，会破坏工作区规范化和越界拒绝边界。

文件附件还存在三层不同语义：用户能否在系统对话框中选择文件、应用能否解析其内容，以及解析结果如何进入 Turn。选择能力不能被当前解析格式白名单限制；图片需要保留原始 data URL 交给视觉 Provider，文本、PDF、DOCX 和 Excel 则需要先执行有界文本提取。所有内容都必须在发送前给出可见状态和确定性错误，不能把读取或解析失败静默丢弃。

## 决策

1. 输入区把剪贴板 `files/items`、浏览器回退拖放、Tauri 原生拖放和文件选择器结果统一转换为用户介导的内存 `Blob`，普通文本粘贴继续使用浏览器默认行为。Windows 桌面使用 `onDragDropEvent` 接收操作系统提供的路径，并只在落点位于输入区时导入；原生监听注册成功后不再处理同一次 DOM `drop`，避免重复附件。文件选择器不设置扩展名过滤，允许用户选择任意普通文件；是否支持解析只在选择后的导入链路中判断，未知格式不读取正文并明确提示“暂不支持解析”。
2. 图片仅接受 PNG、JPEG、GIF 和 WebP，沿用每张 4 MiB、最多 4 张、合计 8 MiB 的运行时边界，并继续作为 `ImageAttachment` 发送。
3. 文档解析支持既有 UTF-8 文本、PDF、DOCX，以及常见 Excel `.xlsx`、`.xls`、`.xlsm`、`.xlsb`。单个源文件最大 8 MiB、后端提取最大 512 KiB；输入区进一步把所有待发送文档正文限制为合计 64 KiB，并在达到上限时标记截断，确保与 100 KB 用户输入上限兼容。
4. Excel 使用 `calamine` 根据内容探测真实工作簿格式，按原工作表顺序输出 `[工作表: 名称]` 分段，行以 TSV 表示，单元格内的反斜杠、制表符和换行转义。`.xlsm` 只读取工作表缓存值，不加载或执行宏。ZIP 容器格式在解析前限制最多 4,096 个条目、单条最多展开 16 MiB、合计最多展开 64 MiB，以拒绝压缩炸弹。
5. 新增 `extract_local_document(name, dataUrl)` Tauri 命令。它只接受经过文件名校验的显示名称和 base64 data URL，不接受磁盘路径，不解析 URI 为文件位置，也不读取工作区或工作区外文件系统。
6. 系统文件对话框选中的路径和 Tauri 原生拖放路径由 Tauri 临时加入运行期文件系统 scope，应用重启后自动清空。主窗口只授予 `fs:allow-stat` 与 `fs:allow-read-file` 两个命令权限，不配置任何静态本地路径 scope；因此任意前端 IPC 字符串不能自行获得读取授权。用户介导的路径先按名称判断支持类型，再通过动态 scope 读取元数据；未知格式和已知超限文件不会完整读入内存。读取后与后端 base64 解码后都再次限制原始字节数。后端还在解码前限制编码长度和 data URL metadata；解析结果使用内容摘要生成 `attachment://` 内部展示标识。该标识只用于前端附件去重，不是文件 Capability，也不会作为路径传给模型或文件工具。
7. 文件类型、大小、数量、解码和提取失败必须通过输入区 toast 明确反馈；附件尚在提取时禁用添加入口并公开 busy 状态。发送前再次按 UTF-8 字节数检查消息和文档上下文总量。
8. 文档继续被折叠到真实用户输入中的 `[附件: <name>]` 上下文；不新增持久化二进制副本或第二套附件事件协议。图片继续使用现有可恢复内容块。

## 后果

- 用户可以在输入框直接粘贴或拖入文件，并能从系统对话框选择任意普通文件；常见代码、文本、PDF、DOCX、Excel 和图片可立即解析，不支持的格式在选择后得到明确反馈。
- 支持工作区之外的用户文件不会扩大模型或工具的路径访问权限；前端文件 API 只能读取本次选择或拖放动态授权的精确路径，后端只能处理本次 IPC 已携带的有界内存字节。
- 文档原始二进制不会持久化，历史只保留已经进入用户消息的有界提取文本；图片仍按既有内容块持久化。
- 同一内容的文档可以确定性去重，但源文件在添加后发生变化不会自动刷新，需要用户重新添加。

## 验证

- Rust 单元测试覆盖有效 UTF-8 文档、路径样式文件名、无效 data URL、异常 metadata、未知二进制、解码前大小拒绝、真实 OpenXML 工作簿提取、四种 Excel 扩展名路由和 ZIP 展开限制。
- Playwright 在桌面和窄屏覆盖普通文本粘贴不被拦截、Markdown 与 Excel 文件粘贴发送、文件对话框无扩展名过滤、最小 fs capability 契约、Tauri 原生拖放落点、DOM 去重、未知格式选择后的可见错误，以及既有图片粘贴与预览。
- 执行 Phase 10 规定的前端构建、Rust 格式检查、编译、完整测试和真实 `pnpm tauri dev` 工作流验证；Windows 验证必须分别走系统文件对话框和从文件资源管理器发起的操作系统原生拖放，不能用脚本构造 DOM `File` 代替。
