# 重复读取误终止修复验证

日期：2026-09-18。路线图任务：P10-196。决策：[ADR 0060](adr/0060-nonfatal-read-observations.md)。

## 问题与原因

用户多次遇到 `repeated_observation_loop: 模型在文件未变化时仍反复读取`。旧读取观察状态机在同一文件修订的读取范围高度重叠时抑制正文，再经过有限纠偏机会直接终止 Turn。压缩后仍只有固定补读额度。

“历史上返回过内容”不能保证模型当前仍有该内容；压缩和工具输出裁剪都会造成缺失。旧 80% 覆盖规则还可能连带抑制同一次读取中新增的内容。运行时回归用确定性 Provider 复现了旧策略造成的失败；本次没有把本地测试日志视为用户实际失败会话的取证。

## Codex 源码对照

参考本地 `D:/code/codex`，核查时提交为 `2833985d88`：

- `codex-rs/core/src/tools/parallel.rs` 的 `handle_tool_call`：成功结果和普通工具错误作为工具输出交回模型；只有明确的 `FunctionCallError::Fatal` 转为运行时失败。
- `codex-rs/core/src/session/turn.rs`：根据 `needs_follow_up` 继续工具往返，达到上下文阈值后可以压缩并继续。所核查的两条执行路径没有按文件修订或重读次数直接终止 Turn 的分支。
- `codex-rs/core/gpt_5_2_prompt.md`：通过提示词减少补丁后的不必要重读。这是模型行为指引，不能推导为运行时对全部重复文件读取设置硬禁止。

## 实现与保护

- 成功 `read_file` 保留经过原有输出上限处理的正文；完全覆盖的重读通过 Provider 来源头附带建议，不抑制正文、不注入强制恢复 System 消息、不触发新的单文件重读错误。
- 压缩和机器人节点切换只重置当前上下文的重复提示记录。移除固定补读次数限制。
- 全局无进展检查继续存在：每 5 轮比较累计事实，连续 3 个窗口不变时终止；无其他进展的测试在 20 次 Provider 请求后停止，前 5 次建立比较基线。
- 读取进展按路径、文件修订和实际返回的累计范围合并。字节分页区分同一长行中的不同内容，运行时输出裁剪只记录保留的头尾范围。空字节区间不因偏移变化而制造进展，首次空文件观察仍建立路径/修订事实。
- 工作区路径规范化、链接逃逸防护、授权、取消、失败读取同参保护和输出上限仍走原有路径。历史错误保持兼容读取。
