## 修复

`ReadObservationTracker` 现在为每个“规范化路径 + 文件修订”提供一次性的压缩后重载窗口：

- 最多 8 个 Provider 批次可以重新返回真实正文；同一 Provider 批次内的多个重叠范围只消费一个批次额度。
- 重载结果标记为 `read_observation_rehydrated_after_compaction`，正文不被抑制，并继续执行 `read_file` 原有路径规范化、工作区越界、修订、编码、范围和输出上限检查。
- 窗口耗尽后恢复原有 `AlreadyCovered -> RecoveryRequired -> RepeatedLoop` 收敛；只有恢复纠偏已经送达的同一 Provider 批次仍重读时才硬停止。
- 已开始重载后，第二次自动或手动 Compaction 关闭同一路径/修订的重载窗口，不结转剩余额度也不重新开放；文件修订变化后使用独立状态。

参考了本地 Codex 源码 `D:/code/Nick/codex/codex-rs/ext/skills/src/tools/read.rs`：第 155 行起使用线程级快照为带 cursor 的技能分页读取返回正文，避免每一页都重新读取整个资源；第 258 行起保存可继续分页的快照，第 277 行起单独记录技能调用分析事件。该证据只说明 `skills.read` 的分页实现，不能据此声称 Codex 的所有文件读取都使用同样策略，也没有发现可直接移植的“8 批”配置。

k-Coder 的 8 批窗口是本项目的有界恢复策略：借鉴分页继续提供正文的思路，仍然每次执行真实 `read_file`，不缓存文件内容、不接受模型提供的修订作为授权事实，也不扩大文件访问范围。它修复本次已复现的压缩后多段补读误判，不承诺消除任何情况下的 `repeated_observation_loop`；超出窗口或模型收到纠偏后仍持续重读时，保护仍然生效。
