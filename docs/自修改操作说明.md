# 用 k-Coder 修改 k-Coder

不要用正在 `pnpm tauri dev` 的那份实例打开本仓库改代码。开发模式会监视源码，写入后重编译并重启窗口，当前 Turn 会中断。桌面是单实例，标识为 `com.kcoder.app`，后启动的进程只会聚焦已有窗口。

正确做法：冻住一份不监视源码的宿主二进制，再把 git 工作区当作普通项目打开。

## 准备宿主

在源码仓库执行一次完整打包：

```powershell
cd D:\code\Nick\k-coder
pnpm tauri build
```

Windows 安装包通常在：

```text
src-tauri\target\release\bundle\nsis\
```

安装这份 NSIS 包。安装目录在仓库外面，后续 `cargo test` 不会锁正在运行的 exe。

如果暂时不安装，把已编好的宿主拷到仓库外，例如 `D:\apps\k-coder-host\`。不要直接运行 `src-tauri\target\release\k-Coder.exe`：智能体再打包或跑会覆盖 `target\release` 的测试时，Windows 可能锁住该文件。

## 启动前先退出旧实例

关闭窗口只会隐藏到托盘，进程仍在。必须从托盘图标右键选择「退出」，或确认没有 `k-Coder.exe` / `pnpm tauri dev` 残留。

未退出时再开安装版或开发版，会看到「k-Coder 已在运行」，并回到旧窗口。

## 打开源码仓库

1. 启动安装版（或仓库外的宿主副本），不要再跑 `pnpm tauri dev`。
2. 在项目选择器中添加并打开 `D:\code\Nick\k-coder`。
3. 确认输入区和侧栏的活动项目都是这份源码仓库。
4. 用 Craft 模式描述要修的 Bug、复现步骤和期望行为。构建与测试让它跑仓库命令，不要让它执行 `pnpm tauri dev` 或覆盖当前宿主的打包命令。

建议让它使用：

```powershell
pnpm build
cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
cargo check --manifest-path src-tauri/Cargo.toml
cargo test --manifest-path src-tauri/Cargo.toml
```

会话、密钥和用量在应用数据目录，不在 git 仓库里：

```text
%APPDATA%\com.kcoder.app\runtime-data\
```

换新的宿主二进制后，一般可以继续同一批会话。

## 用上刚修好的版本

源码改完并通过测试后，当前窗口仍是旧二进制。要 dogfood 新版本：

1. 托盘右键退出宿主。
2. 在源码仓库再次执行 `pnpm tauri build`。
3. 安装新包，或覆盖仓库外的宿主副本。
4. 重新打开安装版，工作区仍选 `D:\code\Nick\k-coder`。

## 备选：两个 worktree

需要一边热重载宿主、一边改另一份源码时：

```powershell
cd D:\code\Nick\k-coder
git worktree add D:\code\Nick\k-coder-src HEAD
```

在 `D:\code\Nick\k-coder` 运行 `pnpm tauri dev`，工作区选 `D:\code\Nick\k-coder-src`。宿主目录没有被写入，开发 watcher 不会重启。修完再把病人工作区的提交合回主工作区。

日常修本仓库，优先用冻住的安装版。

## 不要这样做

| 做法 | 结果 |
| --- | --- |
| `pnpm tauri dev` 打开同一个 `k-coder` 仓库让它改自己 | 改文件后热重载或重编译，Turn 中断 |
| 关掉窗口后再开一份 k-Coder | 旧进程仍在托盘，单实例会弹回旧窗口 |
| 让智能体在 Turn 里执行 `pnpm tauri dev` | 抢开发端口和单实例 |
| 宿主直接跑 `target\release\k-Coder.exe`，同时再打包或跑会覆盖该 exe 的测试 | Windows 锁正在运行的文件 |
| 用 k-Coder 修 k-Coder 的同时，Cursor 也在写同一批文件 | 补丁哈希冲突，审批后无法落盘 |

改 k-Coder 自身：用本说明中的冻住宿主，或继续用 Cursor。用 k-Coder 修其他仓库：可以直接 `pnpm tauri dev`，工作区选那个项目。
