# 深色主题配色设计与对齐验证

日期：2026-09-11。用户提供 CodeBuddy IDE 深色界面作为参考，随后要求按 UI 设计 skill 重做这套配色。改动停留在工作区，未提交、未推送、未部署。

## 一、参考图实测

肉眼判断容易看反，因此用 `System.Drawing` 对用户提供的截图逐点采样：

| 参考图区域 | 实测色 | 蓝偏移 B−R |
| --- | --- | --- |
| 左侧活动栏、底部状态栏 | `#11111B` | +10 |
| 标签条 | `#11111B` | +10 |
| 右侧会话（消息）区 | `#181825` | +13 |
| 左侧欢迎区、会话内代码块 | `#1E1E2E` | +16 |
| 右侧标题栏 | `#2B2C31` | +6 |
| **右侧输入框** | `#313244` | +19 |
| 输入框内胶囊（Craft 等） | `#414255` | +20 |

结论：

1. **输入框明显偏浅、会话区偏深**，级差约 25（`#181825` → `#313244`），不是一个渐变档位。
2. **会话区比"大画面底色"还深**：`#181825` < `#1E1E2E`，不是"越靠中间越亮"。
3. **整体是靛蓝黑，不是中性灰**：各档 R≈G 且 B 高 10~20，色相稳定在蓝紫方向。

## 二、设计方向（frontend-design skill）

使用的 skill 是本地插件市场的 `frontend-design`（其 SKILL.md 要求先确定明确的美学方向，再落地生产级令牌，反对均匀分布、没有观点的配色）。据此定的方向是：

> **「靛蓝夜航」**——单一靛蓝色族承载全部中性面，一个品牌蓝作为唯一强操作色，语义色冷却到同一温度。

五条落地规则：

| 规则 | 做法 |
| --- | --- |
| 单色族 | 所有中性面色相 ≈243°、饱和度 16%~24%，任意两档的 B−R 都为正，不允许出现中性灰 |
| 唯一强色 | 品牌蓝（色相 ≈222°）只出现在可交互与选中元素上，不铺大面积、不做装饰 |
| 分层有主次 | 框架（标题栏 + 侧栏）< 会话区 < 卡片/输入区 < 悬停；输入区刻意拉开约 19 级，成为焦点面 |
| 层次要决定性的 | 框架只保留一档。标题栏与侧栏同色，不在顶部单独切出第二条带——无论切得更亮还是更暗，都是把"最亮的一条"换成"最暗的一条" |
| 语义色同温 | 红/绿/黄换成珊瑚红、鼠尾草绿、沙金，与靛蓝底同一饱和度区间，不再像贴上去的 |
| 角色分离 | 实心填充色与它上面的前景色拆成两个令牌，不允许共用一个值 |

最后一条是必须的：一个颜色不可能同时满足"够暗以承载浅色文字"（亮度 ≤ 0.183）和"够亮以在深色表面上阅读"（亮度 ≥ 0.238）。原实现让 `--color-error` 兼任两者，导致深色下白字压在 `#F87171` 上只有 **2.77:1**。

`--color-error-solid`、`--color-error-solid-hover`、`--color-on-error` 在 `:root` 中分别回退到 `var(--color-error)`、`var(--color-error-text)`、`var(--color-surface)`；`--color-surface-chrome` 在 `:root` 回退到 `var(--color-surface-raised)`。因此浅色外观与其余四套深色皮肤的观感不变。

标题栏这一档迭代了三次：

1. 原先用 `--color-surface-raised`，实际渲染成 `#313244`——与卡片同亮度的 48px 通栏成了全屏最亮的一条，用户要求"加黑"。
2. 按用户给出的目标色块改成 `#11111B`，又变成了全屏最暗的一条，用户反馈"太黑"。
3. 最终把框架收敛成一档：标题栏与侧栏同为 `#181825`，靠底部分隔线（`--color-border`）划出拖拽区，不再在顶部制造第二条强对比带。

参考图自己的顶栏其实是整屏**最亮**的一档（`#313244`，因为它承载菜单与控件），所以既不该照搬那个亮度，也不该压到参考图里属于竖向窄条（活动栏、标签条、状态栏）的 `#11111B`。横跨整窗的 48px 通栏没有可比对象，只能按"框架只留一档"来处理。

## 四、对比度

| 组合 | 改前 | 改后 | 门槛 |
| --- | --- | --- | --- |
| `--color-ink` / `--color-surface` | 13.5:1 | 13.4:1 | ≥ 4.5:1 |
| `--color-ink-subtle` / `--color-surface-panel` | 7.4:1 | 8.0:1 | ≥ 4.5:1 |
| `--color-ink-faint` / `--color-surface-raised` | 5.5:1 | 5.1:1 | ≥ 4.5:1 |
| 主按钮 `--color-surface` / `--color-brand` | 6.7:1 | 6.6:1 | ≥ 4.5:1 |
| 主按钮 hover | 7.3:1 | 8.0:1 | ≥ 4.5:1 |
| **破坏性按钮白字 / 实心填充** | **2.77:1 ✗** | **6.0:1 ✓** | ≥ 4.5:1 |
| 破坏性按钮 hover | 声明无效（`--color-error-hover` 未定义） | 4.8:1 ✓ | ≥ 4.5:1 |
| `--color-error` / `--color-surface` | 4.6:1 | 7.1:1 | ≥ 4.5:1 |
| `--color-success` / `--color-surface` | 6.5:1 | 11.0:1 | ≥ 4.5:1 |
| `--color-warning` / `--color-surface` | 8.4:1 | 12.9:1 | ≥ 4.5:1 |

顺带修掉的既有缺陷：`.agent-button--danger:hover` 引用了从未定义的 `--color-error-hover`，该声明在计算值阶段失效，悬停态的底色实际回退到非悬停值。

## 七、受影响的选择器

角色拆分需要把"实心填充"从 `--color-error` 换成 `--color-error-solid`，共 7 处：

- `src/App.css`：`.agent-button--danger`(含 hover)、`.window-control--close:hover`、`.stop-button`(含 hover)、`.danger-button`(含 hover)、`.turn-timeline-tool--failed .subagent-task-chip:hover`、`.claude-approval-choice--reject.is-highlight .claude-approval-index`
- `src/components/PluginSettingsPage.css`：`.plugin-confirm-actions .danger-button`(含 hover)

其余 `background: var(--color-error)` 的用法都是状态点与进度条等小面积指示器，继续使用亮色前景令牌。

框架层令牌只改动一处：`src/App.css` 的 `.titlebar` 由 `--color-surface-raised` 改为 `--color-surface-chrome`。
