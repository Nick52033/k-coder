# k-Coder 客户端 UI 重设计方案

- 状态：待评审
- 版本：v1
- 依据：`src/App.css` / `src/App.tsx` / `src/components` 实测数据 + `ui-harness` 实际渲染截图
- 范围：仅外观层（CSS 与 token）。不改交互行为、不改 Tauri 侧、不改协议、不改业务逻辑。

## 0. 一句话结论

界面"不好看"的根因不是样式太少，而是**样式太多且没有层级语言**。

8,628 行单体 CSS、1,511 处 `--color-*` 声明、9 套主题覆盖块、125 处 `border: 1px solid`，最终所有元素都靠"1px 描边 + 相近底色"表达层级，于是整个界面在视觉上塌成一张表格：面板、卡片、输入框、气泡之间只剩 1.3:1 的对比差，人眼读不出结构。

重设计方向：**减色、减边、加留白、加层级**，并用三段式 token 把设计决策集中到一处。

## 1. 现状体检（实测，非估算）

| 指标 | 实测值 | 含义 |
| --- | --- | --- |
| `src/App.css` | 240,803 B / 8,628 行 | 单文件承载全部样式 |
| `--color-*` 声明 | 1,511 处 | 语义未收敛，同一概念多套命名 |
| `rgba(` | 69 处 | 半透明色散落，对比度不可控 |
| `border: 1px solid` | 125 处 | 层级几乎全部由描边承担 |
| 皮肤 × 主题 token 块 | 9 个（196–503 行，全部 `[data-skin="codebuddy"]`） | 9 套配色需同时维护与回归 |
| 皮肤启用方式 | `src/App.tsx:699` 硬编码 `setAttribute("data-skin", "codebuddy")` | 皮肤机制只有一条实际路径 |
| 组件样式 | `src/components` 28 个 `.tsx`（383 KB）+ 80 KB CSS | 组件样式与 `App.css` 双轨并行 |

### 1.1 三个具体的"不好看"信号

1. **层级塌陷（最主要）**
   `--color-surface-panel` `#161A26` 与 `--color-surface-raised` `#232A3D` 仅约 1.4:1 亮度差，再叠加 `--color-border` `#2A3146` 对面板底约 1.3:1 的描边。W3C 对非文本元素的对比度建议是 3:1，而当前承载层级的最强信号只有 1.3:1 —— 结构信息在视觉上丢失了。

2. **圆角与间距无节奏**
   侧栏、卡片、按钮、输入框混用多套圆角与内边距，视觉重心分散，密集但不整齐。

3. **强调色不克制**
   品牌蓝 `#4F8AFF` 同时用于选中态、主按钮、链接、用户气泡，缺少"主色只出现在必须被看见的位置"的规则，导致满屏都在喊。

## 2. 目标与可量化验收

**目标**：不改任何交互与数据逻辑，让界面在 5 秒内传达"沉稳、可信、高密度但不拥挤"的专业工具气质。

在 `ui-harness` 上用同一 fixture 截图比对，逐条验收：

1. 层级可辨：面板 / 卡片 / 输入框两两之间至少有 3:1 非文本对比，或改用"亮度分层 + 1px 顶部高光"组合并给出实测对比度。
2. token 收敛：`--color-*` 声明数 1,511 → ≤ 260（9 套主题共用同一组语义名）。
3. 描边减少 ≥ 40%：`border: 1px solid` 125 → ≤ 70。
4. 间距与圆角全部来自 `--space-*` / `--radius-*`：`App.css` 中非 token 的裸值（如 `padding: 13px`）= 0 处。
5. 键盘焦点可见：所有可聚焦元素共用 `--focus-ring`，对比度 ≥ 3:1。
6. 暗 / 亮两套主题均达标：正文 ≥ 4.5:1，次要文本 ≥ 3:1。

## 3. 方案总览（三步，各自可独立交付与回滚）

- **P0 打地基 — token 体系**：把 `:root` 重写为三段式 token，9 套主题只允许覆盖语义层。业务样式先一行不动，保证默认外观等价。
- **P1 关键界面重排** — 侧栏 / 会话流 / composer / 工作台四个高频区域按新视觉语言重做（用户直接感知"变好看了"的部分）。
- **P2 清理与统一** — 裸值清零、未用选择器删除、状态态与动效统一。

## 4. P0：三段式 token 与文件组织

### 4.1 分层模型

```
原始层   --p-blue-500, --p-slate-900 ...
         （字面色值只允许出现在这一层）
   ↓
语义层   --surface-app / --surface-panel / --surface-card / --surface-hover
         --text-primary / --text-secondary / --text-muted
         --border-subtle / --border-default
         --accent / --accent-hover / --accent-soft
         --success / --warning / --danger（各含 -soft 变体）
         --focus-ring
   ↓
组件层   --sidebar-bg / --composer-bg / --message-user-bg / --workbench-bg
         --space-1..10 / --radius-sm|md|lg|pill
         --shadow-1|2|3 / --dur-fast|base|slow / --ease-standard
```

### 4.2 关键决策：用"亮度分层 + 顶部高光"替代描边

- 面板分层靠 `--surface-*` 的亮度台阶（相邻层 ≥ 4% L\* 或 ≥ 3:1），而不是 1px 线。
- 仅在"同层内容需要分隔"处保留 `--border-subtle`，把它降级为极淡辅助，不再承担层级语义。
- 卡片 / 弹窗用 `--shadow-*` + `box-shadow: inset 0 1px 0 rgba(255,255,255,.04)` 制造"抬起"感（暗色主题下最有效）。

### 4.3 默认暗色 token（草案值）

| 语义 | 值 | 说明 |
| --- | --- | --- |
| app 底 | `#0E1116` | 最深，退到最后 |
| 侧栏 | `#12161D` | 比 app 底高一层 |
| 面板 | `#171C24` | 主内容区 |
| 卡片 | `#1D232C` | 抬起层 |
| hover | `#232A34` | 交互反馈 |
| 文字主 / 次 / 弱 | `#E6EAF2` / `#A6AFBE` / `#7C8698` | 三级足够 |
| 边框 subtle / default | `rgba(255,255,255,.06)` / `rgba(255,255,255,.10)` | 辅助，不承载层级 |
| 强调 / 强调-soft | `#5B8CFF` / `rgba(91,140,255,.14)` | 降低饱和与使用面积 |

相邻面亮度差约 4–6%，配合顶部高光即可读出层次，不再需要描边。

### 4.4 文件组织

`App.css` 拆为：`styles/tokens.css`、`styles/base.css`、`styles/shell.css`、`styles/conversation.css`、`styles/workbench.css`、`styles/settings.css`，由 `main.tsx` 按序导入。Vite 打包后仍是单文件，不引入新工具链、不引入 CSS-in-JS 或 Tailwind。

## 5. P1：四个关键区域的重排

### 5.1 侧栏（`.sidebar` 1270 起、`.sidebar-primary-nav-button` 1286 起）

- 导航项去掉整块填充，改为"左侧 2px 强调条 + 文字提亮 + 图标同色"，减少大色块。
- 分组标题用小号大写 + 更弱颜色，与项目项拉开层级。
- `.sidebar-header` 压缩到 44 px 单行，与主区标题栏基线对齐。

### 5.2 会话流（`.message-*` 2024 起）

- 助手消息保持无容器（左留白 + 角色标签），用户气泡降低填充透明度、去掉边框，靠 8 px 圆角 + 微内高光区分。
- 正文行高统一 1.65、段间距 12 px、代码块圆角 10 px。
- 工具行（`.message-changes` / `.message-status`）统一为单行 meta 条：12 px + `--text-muted` + 左侧 2 px 状态色条（把现有 3 px 用法收敛为 2 px）。

### 5.3 Composer（`.composer` 3849 起、`.composer-footer` 1151 起）

- 输入框由"描边盒子"改为"抬起浮层"：`--surface-card` + `--shadow-2` + 顶部 1px 高光；聚焦只加 `--focus-ring`，不再换边框色。
- 底部操作区分主次：发送为实心强调色，其余为幽灵按钮。

### 5.4 工作台（`.workbench` 573 起、`.workbench--panel-open` 588 起）

- 面板与主区之间用 `--border-subtle` + 左侧阴影表达覆盖层。
- 分段控件（`.sidebar-segmented` 1590 起）抽成唯一实现，工作台与侧栏复用同一套样式。

## 6. P2：清理与统一

- 删除未命中选择器（脚本对比 class 使用情况），目标 `App.css` 行数 ≤ 6,000。
- 状态态矩阵收敛为四档：`:hover` / `:active` / `:focus-visible` / `:disabled`，统一由 `--accent-soft`、`--surface-hover`、`--focus-ring` 表达。
- 动效统一：`--dur-fast 120ms` / `--dur-base 200ms`，缓动 `cubic-bezier(.2,.8,.2,1)`；保留 `prefers-reduced-motion` 块（8584 行已有）。
- 其余 7 套主题只调整语义层映射，不改任何组件样式。

## 7. 实施顺序

| 步骤 | 内容 | 产出 | 预估 |
| --- | --- | --- | --- |
| 1 | token 三段式重写 + 暗 / 亮映射 | `:root` 重写，外观等价 | 0.5 天 |
| 2 | 侧栏重排 | 导航层级清晰 | 0.5 天 |
| 3 | 会话流 + composer 重排 | 主界面质感提升 | 1 天 |
| 4 | 工作台 + 设置页重排 | 收尾一致 | 0.5 天 |
| 5 | 其余 7 套主题映射适配 | token ≤ 260 | 0.5 天 |
| 6 | 裸值 / 未用选择器清理 | App.css ≤ 6,000 行 | 0.5 天 |
| 7 | 回归 | 截图对比 + e2e | 0.5 天 |

## 8. 验证方式

1. `pnpm build`（`tsc && vite build`）
2. `pnpm test:e2e`（Playwright 回归交互，确认视觉改动未破坏行为）
3. `ui-harness` 截图：`http://127.0.0.1:1420/ui-harness.html`，9 套主题各 1 张，做改动前 / 后并排对比表。
4. 对比度脚本：解析 `:root` 与 9 个主题块的 token，输出关键配对对比度数值表作为验收证据。

## 9. 风险与取舍

| 风险 | 缓解 |
| --- | --- |
| 9 套主题同时回归成本高 | token 收敛后只有语义层映射不同，回归收敛为"1 次对比度脚本 + 9 张截图" |
| 去掉描边后层级反而更糊 | 先 A/B 并排截图确认再全量铺开，明确"相邻亮度差 ≥ 4%"下限 |
| 样式清理改动面大、收益不可见 | P2 排在 P1 之后，且限定为零视觉差异的机械清理 |
| 工具链重写吸引人但收益低 | 不引入 CSS-in-JS / Tailwind，现有单文件 + token 已够用 |
