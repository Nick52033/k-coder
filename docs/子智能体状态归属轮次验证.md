# 子智能体状态归属轮次验证（P10-190）

- 日期：2026-09-16
- 范围：对话区「子智能体状态」块的归属与位置；不改动子智能体运行、持久化、授权与右侧面板行为。

## 现象

用户截图反馈：一轮对话已经结束，仍能在对话底部看到上一轮的子智能体状态（`task1 变更审查 失败`、`task2 测试范围分析 失败`）。旧行为把该状态块固定渲染在消息列表末尾（`hasConversationContent` 的最后一个子节点），只按 `parentThreadId` 过滤，不看它属于哪一轮，所以上一轮的结果会漂到最新内容之后。用户明确的期望是：**它本该在哪个轮次，就显示在哪。**

## 根因

`src/App.tsx` 把 `subagentList.filter(agent => agent.parentThreadId === activeThreadId)` 直接交给 `SubagentSummary` 挂在消息列表末尾。子智能体在投影里没有"所属轮次"字段，界面也没有做归属推导，于是终态记录跨轮次留在对话底部。

## 归属判定

对话内已经有一套"某轮次引用了哪些子智能体"的解析：`subagentIdsOf(activity)` 从委派工具调用取出子智能体 id（多数工具带 `agentId` 参数，`wait_agent` 支持 `agentIds`，`create_agent` 从结构化结果里取 `id`），对话时间线上的 `taskN` chip 也依赖它。本轮把这套解析提取到 `src/lib/subagent.ts`：

- `buildSubagentTurnIndex(activitiesByTurn)`：遍历各轮次的工具活动，得到 `子智能体 id → 最早引用它的轮次`（按 `startedAtMs` 取最早引用），`ConversationActivity` 与本模块共用同一份 `subagentIdsOf`。
- 归属即事实来源，不新增协议字段、不改后端、不读时间戳猜轮次。

## 修复

1. 新增 `src/lib/subagent.ts`：`isLiveSubagentState`（`queued`/`running`/`blocked`）、`DELEGATION_TOOL_NAMES`、`subagentIdsOf`、`buildSubagentTurnIndex`。
2. `src/components/ConversationActivity.tsx`：删除本地重复的 `DELEGATION_TOOL_NAMES` 与 `subagentIdsOf`，改为从 `src/lib/subagent.ts` 导入（同一份解析，避免两处漂移）。
3. `src/App.tsx`：
   - `subagentTurnIndex` / `subagentsByTurn`（轮次 → 该轮次的子智能体）/ `unownedSubagents`（无归属）；
   - `renderTurnSubagents(turnId)` 把状态块挂到该轮次的可见片段之后，并用 `attachedSubagentTurns` 保证同一轮次只渲染一次（引导分段、重试尝试可能让同一轮次出现多个片段）；
   - 挂载点覆盖全部轮次渲染路径：普通助手消息（回答之后）、`renderOrphanTurn`（只有执行过程、还没有最终回答的轮次，含活动 Turn）、`renderSteeredTurnSegment`（仅最后一个分段）、`renderRetryTurnGroup`（仅该次尝试的终止分段）；
   - 没有轮次归属的记录（从面板直接创建、或所属轮次历史尚未分页加载）继续由对话底部的兜底块承载，仍然可点击进入右侧详情；
   - `hasConversationContent` 恢复为"当前会话有子智能体即算有内容"，不再按状态隐藏。
4. `src/SubagentSummary.tsx`：新增 `ariaLabel` 属性，轮次内的块用「本轮子智能体状态」，底部兜底块保持「本会话子智能体状态」，两者不会重名。

可见性语义：**状态块不再随终态消失**，而是始终留在创建/等待它的那一轮里；终态（含失败与预算耗尽）因此既不会丢失，也不会跨轮次漂移。

## 边界与未覆盖

- 未启动 `pnpm tauri dev` 做原生桌面验收。三个原生脚本（`scripts/validate-subagent-navigation-native.cjs`、`scripts/validate-subagent-budget-native.cjs`、`scripts/validate-quota-native.cjs`）里的子任务都由页面直接调用 `createSubagent` 创建、没有委派轮次，因此继续走底部兜底块，脚本无需改动、内容与改动前一致；下次使用前仍需按脚本头部注释启动隔离客户端。
- 归属依赖委派工具活动的 `agentId`/结果 `id`。`create_agent` 只有在工具调用完成后才带结果 id，因此刚创建的那几百毫秒内该子任务会短暂出现在底部兜底块，随后移入所属轮次；`list_agents` 的返回值不参与归属（它可能列出其他轮次的任务）。
- 若某轮次的历史尚未分页加载（该轮次的工具活动不在内存里），其子任务会落在兜底块而不是消散——这是刻意的兜底，宁可多显示也不隐藏失败状态；`createdAtMs` 与轮次时间区间的时间推断未采用，避免引入第二套、容易错的归属规则。
