# k-Coder 运行时架构

## 目标

k-Coder 是桌面编程智能体，不是给 Shell 套一层聊天界面。运行时必须提供确定性的工具分发、工作区隔离、可恢复对话、取消、审计能力，以及与模型供应商无关的统一事件。

初始架构有意把 Tauri 保持在系统边界，确保智能体运行时无需打开桌面窗口也能独立测试。

## 系统结构

```text
React 界面
  -> 类型化 Tauri 命令
  -> 应用服务
  -> AgentRuntime
       -> ContextBuilder（上下文构建）
       -> Provider（模型适配）
       -> ToolRegistry（工具注册）
       -> PolicyEngine（权限策略）
       -> ToolExecutor（工具执行）
       -> ThreadRepository（会话存储）
  -> 版本化 AgentEvent 事件流
  -> Zustand 展示状态
```

## Rust 模块职责

| 模块 | 负责 | 不得负责 |
| --- | --- | --- |
| `commands` | Tauri 请求校验和响应映射 | 智能体循环、SQL、模型响应解析 |
| `agent` | Turn 生命周期、上下文组装、循环控制、取消 | 具体工具和 HTTP 协议格式 |
| `providers` | 认证头、请求体、SSE 解析 | 工作区访问和界面事件 |
| `tools` | 工具定义、参数校验、执行结果 | 用户授权决策 |
| `policy` | 允许、需要审批、拒绝决策 | 工具实现 |
| `storage` | JSONL 事件日志、SQLite 索引、Repository | 界面状态 |
| `protocol` | 版本化命令和事件 | 业务行为 |
| `ocr` | 通过 Tauri 资源加载本地 PP-OCRv5 ONNX 模型，执行图片文字识别 | 模型供应商请求、工作区文件访问 |

## 前端职责

```text
src/
  components/       通用视觉组件
  features/         对话、设置、工作区、活动面板
  stores/           从运行时事件派生的展示状态
  api/              类型化 invoke/listen 封装
  types/            前端协议类型
```

前端不得直接调用模型 API、打开 SQLite、执行命令或决定某项工具操作是否安全。

## Turn 状态机

```text
queued（排队）
  -> streaming（流式响应）
  -> awaiting_approval（等待审批）
  -> running_tool（执行工具）
  -> streaming（继续响应）
  -> completed（完成）

任意活动状态 -> cancelled（已取消）
任意活动状态 -> failed（失败）
```

运行时必须先持久化会改变状态的事件，再发布对应的界面事件。这样应用崩溃后可以恢复状态，界面也能重新构建。Turn 进入 completed、failed 或 cancelled 终态后，同一 Turn 不得保留 running 工具活动；缺少最终工具结果的活动在失败 Turn 中投影为 failed，在取消 Turn 中投影为 cancelled，实时事件与 JSONL 恢复必须使用相同规则。

## 智能体循环

1. 校验会话、工作区、模式和用户输入。
2. 追加用户消息和 `turn_started` 事件。
3. 从持久化历史、项目规则和 Token 预算构建上下文。
4. 携带原生工具 Schema 发起流式 Provider 请求。
5. 将文本增量作为非持久化展示事件转发。
6. 使用注册的 Schema 校验每个工具调用。
7. 请求 `PolicyEngine` 给出允许、审批或拒绝决策。
8. 执行已授权工具，把结构化结果追加到历史中。
9. 继续调用模型，直到模型返回最终文本或达到运行时限制。
10. 持久化 `turn_completed`、`turn_failed` 或 `turn_cancelled`。

## Provider 契约

Provider 负责把外部协议转换为少量内部事件：

- `text_delta`：文本增量
- `tool_call_delta` 或完整工具调用
- `usage`：Token 用量
- `completed`：请求完成
- 类型化 Provider 错误

`AgentRuntime` 不得直接解析 OpenAI、Anthropic 或 Google 的协议载荷。当前适配器支持 OpenAI-compatible Chat Completions、OpenAI Responses、Anthropic Messages 和 Google Gemini；新增供应商必须继续通过独立适配器接入，不能在智能体循环内部增加协议分支。

供应商配置明确区分“供应商”和“模型”：运行时持久化供应商集合和唯一活动供应商，每个供应商拥有稳定 ID、名称、传输协议、API 地址、独立凭据槽、结构化模型列表和当前默认模型。每个模型保存请求使用的模型 ID、界面显示名称和上下文长度；活动模型的上下文长度同时控制主智能体、手动压缩和子智能体的上下文预算。输入区模型选择器只能读取这份持久化集合，不得维护跨供应商的硬编码目录；切换供应商会原子更新活动 ID，后续 Turn 和连接测试按所选供应商构建 Provider。旧版单个 `provider.json`、单个 `model` 或字符串模型列表加载时会自动升级；历史前端 `localStorage` 供应商列表只作为一次性公开配置迁移输入，不再是事实来源。API Key 始终按供应商 ID 隔离保存在操作系统凭据设施中，不能从旧前端标记推断密钥存在。

## 实时交互事件

- `AgentRuntime` 在每轮 Provider 调用前发布独立的 `thinking` 状态，并在回复、工具执行、审批等待和收尾之间显式切换。活动状态是瞬时展示状态，不写入 JSONL。
- OpenAI Responses 适配器按全局推理强度请求 `reasoning.effort` 并附带 `reasoning.summary=auto`，只把 `response.reasoning_summary_text.delta/done` 转换为公共事件；Gemini `generateContent` 在推理启用时请求 `includeThoughts=true`，只把标记为 `thought` 的摘要文本投影为同一类事件。Chat Completions 的非标准 `reasoning_content`、Anthropic 原始 thinking 块和 Responses `reasoning_text` 都必须忽略；完成的安全摘要以有界领域事件持久化并进入 Turn 时间线，但不加入下一轮模型消息。关闭推理时省略对应推理配置。
- `run_command` 从 `CommandRuntime` 已脱敏的游标缓冲区读取 stdout/stderr，按有界批次送入固定容量进展队列。队列拥塞时允许丢弃瞬时展示事件，最终 `ToolResult` 和审计语义不能丢失。进程退出、超时或取消后只允许输出读取任务在有界窗口内排空；命令等待除状态通知外每 100ms 复核一次会话终态，通知遗漏或派生进程遗留输出句柄都不能无限阻塞最终 `ToolResult`。`corepack npm/pnpm/yarn build|test|lint|typecheck` 与直接调用包管理器使用相同的构建/测试风险分类，不产生未知可执行程序审批。
- 前端按事件顺序投影说明文字、安全摘要、工具状态、生命周期摘要和命令输出。审批请求与解决事件按对应工具调用 ID 排在工具活动之前，避免工具仍在执行时把已完成审批显示在其后；刷新历史使用审批快照执行同样规范化。实时命令输出设独立展示上限，不允许通过无限追加拖垮界面。
- `turnTimeline` 是当前线程的唯一实时展示事实源，除 `text`、`reasoning`、`tool` 外还包含有界的 `event` 生命周期项；旧 `toolActivities` 只用于无时间线历史的迁移。前端按 Turn/调用 ID 去重工具生命周期，并按 stdout/stderr 与游标去重输出增量，不能再把同一事件同时追加到消息和活动列表。相邻思考摘要只在完成状态相同且中间没有其他条目时合并展示。
- Turn 完成、失败和取消事件公开 `startedAtMs`、`completedAtMs` 与 `durationMs`，返回值和实时事件使用同一组时间；历史投影从同一 Turn 的 `turn_started` 与终态事件恢复总耗时。活动 Turn 使用随 `thinking`、回复、工具、审批和收尾阶段变化的紧凑状态标题并保持展开，不使用固定的“正在执行”外层标题；状态标题显示在过程内容之后，始终跟随时间线的最新记录，不显示折叠用的上下箭头，标题上方直接展示进行时动作、动态指示、实时耗时和已收到的思考摘要。时间线上相邻的思考摘要合并为一个可折叠展示组，内部仍按事件顺序保留各段内容；工具、说明或生命周期事件会切断分组。单项摘要完成不能在 Turn 仍活动时自动收起，工具完成到下一次 Provider 输出之间必须保留紧凑活动状态；尚无工具活动时不渲染额外的空工具调用占位行。进入终态后前端才默认折叠计划、说明、推理、工具和生命周期项，但最终回答独立显示，完整时间线仍可随时展开审计。对话内容不显示助手头像，避免头像动画与真实执行状态形成两个竞争信号。该折叠和分组只改变展示状态，不删除领域事件、不缩减 Provider 历史，也不触发 Compaction。
- `request_user_input`、任务清单、审批、变更、Provider 用量和 Turn 终态都先写入 JSONL 再发布实时事件。线程加载期间当前线程的事件进入 hydration buffer，快照应用后按顺序重放；切换线程不会把事件写入错误的时间线。
- 当用户行为、变更范围或兼容性取舍无法从工作区上下文确定，且错误假设会改变结果或造成返工时，Craft、Ask 和 Plan 模式都可以通过 `request_user_input` 主动询问；回答会在同一 Turn 中继续处理。低风险、可从仓库发现或已经明确的事项不重复确认。
- 取消请求发出后，界面必须保持 Turn 忙碌，直到收到或恢复出持久化的 `turn_cancelled`、`turn_failed` 或 `turn_completed`。排队消息绑定入队时的线程，切换线程不能把后续 Turn 错发到当前线程；重试复用原用户消息，不能重复追加。
- 当前 Turn 处于 thinking、工具执行或等待审批时，输入区仍保持可编辑；从输入区发送的内容只追加到绑定线程的 FIFO 队列，不提前投影为对话中的用户消息，也不自动取消当前 Turn。待处理队列项提供独立的立即发送和删除操作；立即发送把目标项提升为下一项并请求取消当前 Turn，同一 Turn 的取消请求必须去重。队列只在持久化终态到达后才投影该用户消息并启动下一次 `run_turn`；正常完成、失败和取消都必须唤醒队列，且任何时刻不得并发启动多个 `run_turn`。
- 图片附件保留原始 data URL 交给支持视觉的 Provider，同时在本地通过 Tauri `recognize_image` 命令调用随应用打包的 PP-OCRv5 模型。原图持久化为可恢复的 `image` 内容块，允许不输入文字直接发送，并在用户消息中显示紧凑附件标签；有界识别文字及图片单独发送时的分析提示持久化为仅供 Provider 使用的 `context` 内容块，不进入可见用户正文，也不在附件区展示识别正文、行数或失败状态。OCR 失败不能阻塞原图发送；模型、运行时 DLL 和词表只能从应用资源目录加载。
- 助手正文、实时说明和安全摘要共用受控的 GFM Markdown 渲染边界。原始 HTML 不解析，远程 Markdown 图片不自动请求；表格和代码块在自身容器内滚动，不能撑破对话布局。

## Phase 2 只读运行时边界

- 应用启动时把进程启动目录 canonicalize 为本次工作区根目录；正式的工作区选择和切换由 Phase 6 提供。
- `list_directory` 只列直接子项，默认最多 200 项、最多 500 项，并忽略 `.git`、`node_modules`、`target`、`dist` 和 `build`。
- `read_file` 识别 UTF-8 BOM、UTF-16LE 和 UTF-16BE；单文件最大 4 MiB。无范围参数时默认最多返回 64 KiB；优先使用 `startLine/lineCount` 读取代码范围，只要任一行范围字段存在就忽略冗余的 `offset/limit`，旧字节范围在没有行范围时继续兼容，显式范围单次最多返回 256 KiB。结果元数据同时记录实际行号、字节数、总行数、总字节数和前后任一侧是否仍有省略内容。
- 普通 Turn 不设置 Provider 迭代数或工具调用总数硬上限，也不因多次 Provider 请求的累计统计值达到固定阈值而终止；同名同参调用最多重复 2 次。运行时每 5 轮比较成功工具结果与文件内容变更，连续 3 个窗口没有新结果时以类型化失败终止。Goal 和子智能体默认不设累计 Token 预算，只有显式配置时才由宿主硬性执行。
- `assistant_tool_calls`、每个 `tool_result`、用户输入/任务清单生命周期与 Turn 终态先写入 JSONL，再发布工具或状态界面事件。同一次 Provider 响应中的工具调用严格按返回顺序串行执行；当前工具的最终结果持久化并发布后才允许下一个工具进入 started 状态，避免构建、Git、搜索和写操作争用资源或同时等待审批。Provider 历史继续使用调用 ID 校验完整工具组。
- 从 JSONL 重建 Provider 历史时，每次请求前都必须按 `tool_call_id` 校验完整工具组，不能只在 Compaction 时修复。只有调用 ID 唯一且每个调用恰好对应一个紧随其后的结果时才保留结构化工具组；缺失、重复、错配和孤立结果全部丢弃，工具调用前已经持久化的非空助手说明降级为普通助手文本保留。
- 工具调用前已流式输出的可见进度说明与 `assistant_tool_calls` 一起持久化并带入下一次 Provider 请求；`read_thread` 同时投影按事件顺序排列的 Turn 时间线，界面在活动期间据此交错展示说明、单个工具状态和最终回答。Turn 结束后允许把中间过程默认折叠为带真实总耗时的摘要，但不得覆盖、删除或阻止展开任何已持久化进度；最终回答不得放进过程折叠区。进度说明只描述当前动作和已确认事实，不暴露模型隐藏推理链。
- 时间线单项摘要最多 2,000 字符；Provider 上下文最多 512 KiB，单次模型响应最多 512 KiB，工具结果继续受各自载荷边界限制，但单 Turn 不设固定调用总数。`run_command` 最终结果可携带最多 64 KiB 的脱敏 stdout/stderr chunks，刷新后仍按 stream 与 cursor 恢复。
- 逐次 Provider 用量同时服务两种不同语义：所有调用相加得到 Turn/线程累计统计；最近一次调用的 `total_tokens` 代表当前活动上下文窗口。自动 Compaction 同时参考本地历史估算和最近一次 Provider 用量，任一达到活动模型窗口的 80% 即在 Turn 中压缩并继续。Compaction 事件会重置恢复侧的当前窗口用量基线；近期工具结果以有界普通摘要恢复，不能生成没有配对工具调用的孤立工具输出。
- 参数有效且已执行的普通工具失败会作为结构化 `tool_result` 进入下一次 Provider 请求，使同一 Turn 可以检查失败、修改并重新验证。审批审计或事件存储失败不属于模型可修复的工具结果：运行时取消当前工具并把同批剩余未启动调用记录为跳过，完成必要回滚与失败审计后，保留原始类型化错误并终止 Turn。

## Phase 3 安全编辑边界

- 模型只能通过注册的 `apply_patch` 或 `write_file` 提议文件修改；回复文本和 Markdown 代码块没有写入能力。
- `apply_patch` 使用严格的 Begin/End、文件头和 hunk 语法，支持新增、修改、删除和移动；`write_file` 只用于明确的完整 UTF-8 文件替换。
- 写工具的模型参数不包含审批字段。`PolicyEngine` 按读取、写入、删除和外部访问分类，后端创建并持有审批能力。默认 `ask` 模式使用一次性审批；用户显式选择的会话级 `full_access` 模式可以自动批准已注册工具，但不扩大工具 Capability 或工作区边界。
- 审批请求先写入 JSONL，再发布到界面。用户可以选择文件、编辑 Patch、查看统一或并排 Diff，并明确应用或拒绝；未批准、超时和取消都不会写盘。
- `full_access` 每次自动批准仍写入配对的审批请求和解决事件，并复用 Patch 预览、修改前哈希与变更审计。模式不持久化，应用重启恢复 `ask`；活动 Turn 或子智能体存在时不能切换。
- 同一 Turn 的连续工具调用可以产生多个审批请求。前端按请求 ID 去重并以 FIFO 队列逐个展示；解析或过期只移除对应请求。线程恢复必须把全部未决审批投影为取消，不能遗留可操作但后端已失效的审批卡片。
- 执行前重新解析 Patch、规范化路径并验证审阅时的 SHA-256。文件在审阅期间发生改变时返回冲突，不覆盖新内容。
- 多文件操作在单个编辑锁内执行；任一操作失败会根据修改前快照逆序回滚已经开始的操作。
- `change_applied` 保存有界的修改前后快照和完整 Diff。撤销前验证修改后哈希，防止撤销覆盖应用后产生的新修改，并记录 `change_undone` 审计事件。
- 当前限制为单个 Patch 1 MiB、最多 20 个文件、单文件 512 KiB、单次变更前后快照合计 2 MiB。
- 工作台中的用户直接编辑不是模型提议，不从自由文本或工具参数触发，也不伪造审批事件。界面使用本地打包的 Monaco Editor 展示行号和语法高亮，但只能通过类型化 `save_workspace_file` Tauri 命令保存；后端仅接受 256 KiB 内的 UTF-8 文本，重新规范化工作区相对路径，校验预览时返回的 SHA-256，并与模型 Patch 共用进程内编辑锁。文件在打开后被其他来源修改时必须返回冲突，不能静默覆盖。

## 工具契约

每个工具必须提供：

- 稳定的名称和说明
- JSON 输入 Schema
- 类型化参数校验
- 风险等级
- 异步处理器
- 包含成功状态、输出和元数据的结构化结果
- 取消行为
- 对有效参数、无效参数、拒绝、取消和边界情况的单元测试

`ToolRegistry` 负责发现 Schema 和处理器；`PolicyEngine` 负责授权；`ToolExecutor` 负责协调策略判断、审批、超时、取消、审计事件和处理器执行。

## 工作区安全

文件操作必须按以下顺序处理路径：

1. 把相对路径拼接到已选择的工作区。
2. 规范化路径，并对最近存在的父级目录执行 canonicalize。
3. 在平台允许时解析符号链接和目录联接。
4. 使用当前平台对应的路径比较规则。
5. 拒绝规范化后位于工作区之外的路径。

普通工作区工具不接受绝对路径。访问工作区之外的资源必须使用独立的显式 Capability，并经过用户审批。

不能因为 Shell 的当前目录位于工作区内就认为命令天然安全。命令执行前必须经过策略判断，并支持输出上限、超时、取消和进程树终止。

## 持久化

JSONL 是对话和 Turn 事件的持久化事实来源。SQLite 保存便于查询的投影，例如会话列表、设置、用量和搜索索引。

```text
runtime-data/
  sessions/<thread-id>.jsonl
  providers.json
  k-coder.db
  logs/
```

在可行情况下，SQLite 数据应当可以从 JSONL 重新构建。API Key 必须存入操作系统凭据设施，不能写入数据库或 TOML 配置文件。

## 子智能体

子智能体是使用受限上下文、可选预算、工具和工作区权限的普通 `AgentRuntime` 实例。`multi_agent` 只协调生命周期，不实现第二套模型或工具循环。

- 主运行时通过 `create_agent`、`wait_agent`、`send_agent_message`、`resume_agent`、`list_agents` 和 `close_agent` 获取结构化委派能力；创建、跟进、恢复和关闭按外部风险继续走后端审批。
- 每个子智能体拥有独立会话、明确工作区快照和父工具 Capability 的子集。默认只提供 `list_directory` 与 `read_file`。
- 最大派生深度为一层，最多同时运行 4 个子智能体；单个子智能体默认不设 Token 预算，显式设置后在恢复和跟进之间累计并硬性执行。默认运行 10 分钟、最多 30 分钟。
- 子智能体使用父取消令牌的子令牌。关闭或取消父 Turn 会真正取消子智能体的 Provider 流和活动工具。
- 子智能体继承创建时的审批模式快照，但不能借此获得父智能体未提供的工具 Capability。
- 写操作继续经过 Patch 审阅、修改前哈希和进程内编辑锁。并发写入同一路径时，后到操作必须报告冲突，不能静默覆盖。
- `subagents.jsonl` 持久化有界生命周期快照。主智能体和界面只能读取状态、可选预算、累计 Token 消耗、摘要与错误；完整子会话保留在独立线程中。
- 桌面界面在同一窗口的活动面板展示子任务，不为每个智能体创建独立窗口。应用重启时未完成子任务确定性标记为失败。

更深层委派保持关闭；自动创建仍需明确审批。评估方法和边界见 `docs/多智能体评估.md`。

## Phase 9 高级智能体边界

- `advanced` 统一拥有计划、Goal、浏览器、搜索、记忆、文档、评估和指标服务；这些能力继续注册为普通 `ToolHandler`，不得绕开 `PolicyEngine`。
- 计划以追加式快照持久化，每个线程最多一项处于 `in_progress`。计划快照与工具活动通过 Turn 关联显示在对话时间线，工作台只保留文件和 Git 等检查视图；页面恢复后必须从持久化投影重建相同关联。Goal 默认只保留时间预算，Token 预算可选；累计 Token 消耗始终可见，显式 Token 预算与时间预算由宿主限制，暂停、阻塞、完成和预算耗尽是显式状态。
- 浏览器使用单个受控 Chromium CDP 会话，默认关闭。导航、点击、输入、截图和关闭属于外部风险，取消 Turn 会关闭会话；URL、审计日志和 8 MiB 截图制品都受边界限制。
- 仓库搜索先采用确定性、有文件数和文件大小上限的词法扫描。记忆默认关闭，启用后每项都保存来源、到期时间、修订和删除事件。
- Provider 故障切换只处理产生输出前的网络错误、408、429 和 5xx；鉴权/参数错误、无效响应、取消和流中断不会切换。备用模型与备用端点属于供应商配置，仍共用操作系统凭据。
- 文档提取仅支持有界 UTF-8 文本、PDF 和 DOCX，源文件最大 8 MiB、提取文本最大 512 KiB。运行指标使用本地追加日志记录延迟、Token、工具成功率、故障切换和任务终态；未知成本必须明确显示为未知。

## Phase 7 可控扩展边界

- `extensions` 负责规则、Skill、MCP、Hooks、凭据名称映射、诊断和扩展审计；它不得实现第二套智能体循环。
- 全局指令、项目指令和项目规则按确定性优先级编译，在每次 Provider 请求构建后加入上下文。Skill 先由触发词选择，再在执行前把完整正文加入同一运行时指令。
- 非只读 Skill 必须由宿主显式启用，且 Skill 内容不能改变 `PolicyEngine` 决策。
- MCP stdio 与 Streamable HTTP 都先完成初始化和能力协商，再发现工具。外部名称只能以 `mcp__<server>__<tool>` 注册；任何规范化冲突都会关闭失败。
- MCP 工具是普通 `ToolHandler`。只读、写入、删除和外部访问风险由服务端 annotations 保守映射，再经过与内置工具相同的 Schema、策略、一次性审批、取消、Hook 和持久化结果流程。
- 注入的 MCP 密钥只存在于子进程环境或 HTTP Header，不进入 Provider 消息、工具参数、扩展诊断或日志。
- Hook 只能运行宿主配置的结构化命令，接收有界 JSON 并返回类型化 allow/block 决策。超时、崩溃、超限和无效输出都阻止工具。
- 扩展文件使用修订指纹；改变后重建完整注册表。加载失败时不得继续沿用“已准备”缓存。

## 初始版本不包含的能力

- 手机远程控制
- 机器人工作流设计器
- 浏览器录制与回放
- 自主长期记忆
- 插件市场
- 首发即支持多种 Provider 协议

这些能力保留在路线图中作为后续选项，但不作为成熟编程智能体的必要前置条件。

## 推理强度配置

推理强度是全局运行时设置，持久化在 SQLite `settings` 表的 `reasoning_effort` 键中，默认值为 `medium`。运行中的 Provider 请求会在开始时取得该值；Thinking 期间修改不会改变当前请求，但会作用于下一次请求和队列项。

前端选择器只使用 `off`、`minimal`、`low`、`medium`、`high`、`x_high` 六个稳定值。关闭时不发送推理字段；启用时由 Provider 适配器映射为协议字段：OpenAI Chat Completions 使用 `reasoning_effort`，OpenAI Responses 使用 `reasoning.effort`，Anthropic Messages 使用 `thinking.budget_tokens`，Gemini 使用 `generationConfig.thinkingConfig.thinkingBudget`。映射失败由既有 Provider 错误和重试边界处理，AgentRuntime 不包含协议分支。

## 工具执行详情

对话时间线中的工具活动保留开始时间、结束时间和耗时。`run_command` 的结果元数据同时记录结构化命令会话的 `startedAtMs`、`finishedAtMs` 和 `durationMs`，前端可以展开查看实际 `program`、参数、工作目录、超时和工具输出；`read_file` 的实际有界结果仍进入 Provider 历史并保留在持久化工具事件中，但对话时间线只显示目标路径、读取范围和状态等摘要，不再提供“查看读取内容”入口，也不重新读取工作区；`apply_patch`/`write_file` 显示目标路径并可展开有界提议正文，即使 Patch 在预览阶段失败也保留参数诊断。输出仍沿用既有的密钥脱敏边界。历史工具事件由 JSONL 的事件时间重建耗时，旧事件缺少这些字段时仍按兼容默认值加载。

文件变更事件继续使用 `ChangeSet` 中的工作区相对路径和有界 unified diff。时间线的“查看变更”入口只读取已审计的变更快照，不重新读取工作区，也不把模型自由文本当作文件修改依据。

## 工作台响应式边界

桌面端工作台文件/Git 面板是根网格中的独立右列，不是覆盖对话的浮层；常规桌面宽度限制为 360–440px，中等窗口隐藏侧边栏并将右栏限制为 320–400px，窄屏才切换为单独的右侧面板视图。对话列及其消息列表、消息正文和输入区都必须设置可收缩宽度边界，任何子元素的最小内容宽度都不得撑进工作台列。输入区底部选择器允许换行，模型选择器优先弹性收缩，发送和停止按钮保持固定尺寸并始终位于输入区可见范围内。
