# k-Coder 运行时架构

## 目标

k-Coder 是桌面编程智能体，不是给 Shell 套一层聊天界面。运行时必须提供确定性的工具分发、工作区隔离、可恢复对话、取消、审计能力，以及与模型供应商无关的统一事件。

初始架构有意把 Tauri 保持在系统边界，确保智能体运行时无需打开桌面窗口也能独立测试。

## 系统结构

```text
React 界面
  -> 类型化 Tauri 命令
  -> 应用服务
  -> AgentRuntime
       -> ContextBuilder（上下文构建）
       -> Provider（模型适配）
       -> ToolRegistry（工具注册）
       -> PolicyEngine（权限策略）
       -> ToolExecutor（工具执行）
       -> ThreadRepository（会话存储）
  -> 版本化 AgentEvent 事件流
  -> Zustand 展示状态
```

## Rust 模块职责

| 模块 | 负责 | 不得负责 |
| --- | --- | --- |
| `commands` | Tauri 请求校验和响应映射 | 智能体循环、SQL、模型响应解析 |
| `agent` | Turn 生命周期、上下文组装、循环控制、取消 | 具体工具和 HTTP 协议格式 |
| `providers` | 认证头、请求体、SSE 解析 | 工作区访问和界面事件 |
| `tools` | 工具定义、参数校验、执行结果 | 用户授权决策 |
| `policy` | 允许、需要审批、拒绝决策 | 工具实现 |
| `storage` | JSONL 事件日志、SQLite 索引、Repository | 界面状态 |
| `protocol` | 版本化命令和事件 | 业务行为 |

## 前端职责

```text
src/
  components/       通用视觉组件
  features/         对话、设置、工作区、活动面板
  stores/           从运行时事件派生的展示状态
  api/              类型化 invoke/listen 封装
  types/            前端协议类型
```

前端不得直接调用模型 API、打开 SQLite、执行命令或决定某项工具操作是否安全。

## Turn 状态机

```text
queued（排队）
  -> streaming（流式响应）
  -> awaiting_approval（等待审批）
  -> running_tool（执行工具）
  -> streaming（继续响应）
  -> completed（完成）

任意活动状态 -> cancelled（已取消）
任意活动状态 -> failed（失败）
```

运行时必须先持久化会改变状态的事件，再发布对应的界面事件。这样应用崩溃后可以恢复状态，界面也能重新构建。

## 智能体循环

1. 校验会话、工作区、模式和用户输入。
2. 追加用户消息和 `turn_started` 事件。
3. 从持久化历史、项目规则和 Token 预算构建上下文。
4. 携带原生工具 Schema 发起流式 Provider 请求。
5. 将文本增量作为非持久化展示事件转发。
6. 使用注册的 Schema 校验每个工具调用。
7. 请求 `PolicyEngine` 给出允许、审批或拒绝决策。
8. 执行已授权工具，把结构化结果追加到历史中。
9. 继续调用模型，直到模型返回最终文本或达到运行时限制。
10. 持久化 `turn_completed`、`turn_failed` 或 `turn_cancelled`。

## Provider 契约

Provider 负责把外部协议转换为少量内部事件：

- `text_delta`：文本增量
- `tool_call_delta` 或完整工具调用
- `usage`：Token 用量
- `completed`：请求完成
- 类型化 Provider 错误

`AgentRuntime` 不得直接解析 OpenAI、Anthropic 或 Google 的协议载荷。当前适配器支持 OpenAI-compatible Chat Completions、OpenAI Responses、Anthropic Messages 和 Google Gemini；新增供应商必须继续通过独立适配器接入，不能在智能体循环内部增加协议分支。

供应商配置明确区分“供应商”和“模型”：供应商拥有名称、传输协议、API 地址、凭据、结构化模型列表和当前默认模型。每个模型保存请求使用的模型 ID、界面显示名称和上下文长度；活动模型的上下文长度同时控制主智能体、手动压缩和子智能体的上下文预算。输入区模型选择器只能读取这份持久化配置，不得维护跨供应商的硬编码模型目录。旧版单个 `model` 或字符串模型列表加载时会自动升级为结构化列表，并使用 128000 Token 默认上下文；API Key 仍只保存在操作系统凭据设施中。

## Phase 2 只读运行时边界

- 应用启动时把进程启动目录 canonicalize 为本次工作区根目录；正式的工作区选择和切换由 Phase 6 提供。
- `list_directory` 只列直接子项，默认最多 200 项、最多 500 项，并忽略 `.git`、`node_modules`、`target`、`dist` 和 `build`。
- `read_file` 识别 UTF-8 BOM、UTF-16LE 和 UTF-16BE；单文件最大 4 MiB，单次最多返回 256 KiB。
- 单个 Turn 最多执行 8 次 Provider 迭代、24 次工具调用；同名同参调用最多重复 2 次。
- `assistant_tool_calls` 与每个 `tool_result` 先写入 JSONL，再发布工具生命周期界面事件。

## Phase 3 安全编辑边界

- 模型只能通过注册的 `apply_patch` 或 `write_file` 提议文件修改；回复文本和 Markdown 代码块没有写入能力。
- `apply_patch` 使用严格的 Begin/End、文件头和 hunk 语法，支持新增、修改、删除和移动；`write_file` 只用于明确的完整 UTF-8 文件替换。
- 写工具的模型参数不包含审批字段。`PolicyEngine` 按读取、写入、删除和外部访问分类，后端创建并持有一次性审批能力。
- 审批请求先写入 JSONL，再发布到界面。用户可以选择文件、编辑 Patch、查看统一或并排 Diff，并明确应用或拒绝；未批准、超时和取消都不会写盘。
- 执行前重新解析 Patch、规范化路径并验证审阅时的 SHA-256。文件在审阅期间发生改变时返回冲突，不覆盖新内容。
- 多文件操作在单个编辑锁内执行；任一操作失败会根据修改前快照逆序回滚已经开始的操作。
- `change_applied` 保存有界的修改前后快照和完整 Diff。撤销前验证修改后哈希，防止撤销覆盖应用后产生的新修改，并记录 `change_undone` 审计事件。
- 当前限制为单个 Patch 1 MiB、最多 20 个文件、单文件 512 KiB、单次变更前后快照合计 2 MiB。

## 工具契约

每个工具必须提供：

- 稳定的名称和说明
- JSON 输入 Schema
- 类型化参数校验
- 风险等级
- 异步处理器
- 包含成功状态、输出和元数据的结构化结果
- 取消行为
- 对有效参数、无效参数、拒绝、取消和边界情况的单元测试

`ToolRegistry` 负责发现 Schema 和处理器；`PolicyEngine` 负责授权；`ToolExecutor` 负责协调策略判断、审批、超时、取消、审计事件和处理器执行。

## 工作区安全

文件操作必须按以下顺序处理路径：

1. 把相对路径拼接到已选择的工作区。
2. 规范化路径，并对最近存在的父级目录执行 canonicalize。
3. 在平台允许时解析符号链接和目录联接。
4. 使用当前平台对应的路径比较规则。
5. 拒绝规范化后位于工作区之外的路径。

普通工作区工具不接受绝对路径。访问工作区之外的资源必须使用独立的显式 Capability，并经过用户审批。

不能因为 Shell 的当前目录位于工作区内就认为命令天然安全。命令执行前必须经过策略判断，并支持输出上限、超时、取消和进程树终止。

## 持久化

JSONL 是对话和 Turn 事件的持久化事实来源。SQLite 保存便于查询的投影，例如会话列表、设置、用量和搜索索引。

```text
runtime-data/
  sessions/<thread-id>.jsonl
  k-coder.db
  logs/
```

在可行情况下，SQLite 数据应当可以从 JSONL 重新构建。API Key 必须存入操作系统凭据设施，不能写入数据库或 TOML 配置文件。

## 子智能体

子智能体是使用受限上下文、预算、工具和工作区权限的普通 `AgentRuntime` 实例。`multi_agent` 只协调生命周期，不实现第二套模型或工具循环。

- 主运行时通过 `create_agent`、`wait_agent`、`send_agent_message`、`resume_agent`、`list_agents` 和 `close_agent` 获取结构化委派能力；创建、跟进、恢复和关闭按外部风险继续走后端审批。
- 每个子智能体拥有独立会话、明确工作区快照和父工具 Capability 的子集。默认只提供 `list_directory` 与 `read_file`。
- 最大派生深度为一层，最多同时运行 4 个子智能体；单个子智能体默认 64000 Token、最多 200000 Token，默认运行 10 分钟、最多 30 分钟。Token 在恢复和跟进之间累计。
- 子智能体使用父取消令牌的子令牌。关闭或取消父 Turn 会真正取消子智能体的 Provider 流和活动工具。
- 写操作继续经过 Patch 审阅、修改前哈希和进程内编辑锁。并发写入同一路径时，后到操作必须报告冲突，不能静默覆盖。
- `subagents.jsonl` 持久化有界生命周期快照。主智能体和界面只能读取状态、预算、摘要与错误；完整子会话保留在独立线程中。
- 桌面界面在同一窗口的活动面板展示子任务，不为每个智能体创建独立窗口。应用重启时未完成子任务确定性标记为失败。

更深层委派保持关闭；自动创建仍需明确审批。评估方法和边界见 `docs/多智能体评估.md`。

## Phase 9 高级智能体边界

- `advanced` 统一拥有计划、Goal、浏览器、搜索、记忆、文档、评估和指标服务；这些能力继续注册为普通 `ToolHandler`，不得绕开 `PolicyEngine`。
- 计划以追加式快照持久化，每个线程最多一项处于 `in_progress`。Goal 的 Token 与时间预算由宿主限制，暂停、阻塞、完成和预算耗尽是显式状态。
- 浏览器使用单个受控 Chromium CDP 会话，默认关闭。导航、点击、输入、截图和关闭属于外部风险，取消 Turn 会关闭会话；URL、审计日志和 8 MiB 截图制品都受边界限制。
- 仓库搜索先采用确定性、有文件数和文件大小上限的词法扫描。记忆默认关闭，启用后每项都保存来源、到期时间、修订和删除事件。
- Provider 故障切换只处理产生输出前的网络错误、408、429 和 5xx；鉴权/参数错误、无效响应、取消和流中断不会切换。备用模型与备用端点属于供应商配置，仍共用操作系统凭据。
- 文档提取仅支持有界 UTF-8 文本、PDF 和 DOCX，源文件最大 8 MiB、提取文本最大 512 KiB。运行指标使用本地追加日志记录延迟、Token、工具成功率、故障切换和任务终态；未知成本必须明确显示为未知。

## Phase 7 可控扩展边界

- `extensions` 负责规则、Skill、MCP、Hooks、凭据名称映射、诊断和扩展审计；它不得实现第二套智能体循环。
- 全局指令、项目指令和项目规则按确定性优先级编译，在每次 Provider 请求构建后加入上下文。Skill 先由触发词选择，再在执行前把完整正文加入同一运行时指令。
- 非只读 Skill 必须由宿主显式启用，且 Skill 内容不能改变 `PolicyEngine` 决策。
- MCP stdio 与 Streamable HTTP 都先完成初始化和能力协商，再发现工具。外部名称只能以 `mcp__<server>__<tool>` 注册；任何规范化冲突都会关闭失败。
- MCP 工具是普通 `ToolHandler`。只读、写入、删除和外部访问风险由服务端 annotations 保守映射，再经过与内置工具相同的 Schema、策略、一次性审批、取消、Hook 和持久化结果流程。
- 注入的 MCP 密钥只存在于子进程环境或 HTTP Header，不进入 Provider 消息、工具参数、扩展诊断或日志。
- Hook 只能运行宿主配置的结构化命令，接收有界 JSON 并返回类型化 allow/block 决策。超时、崩溃、超限和无效输出都阻止工具。
- 扩展文件使用修订指纹；改变后重建完整注册表。加载失败时不得继续沿用“已准备”缓存。

## 初始版本不包含的能力

- 手机远程控制
- 机器人工作流设计器
- 浏览器录制与回放
- 自主长期记忆
- 插件市场
- 首发即支持多种 Provider 协议

这些能力保留在路线图中作为后续选项，但不作为成熟编程智能体的必要前置条件。
