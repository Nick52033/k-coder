# k-Coder 运行时架构

## 目标

k-Coder 是桌面编程智能体，不是给 Shell 套一层聊天界面。运行时必须提供确定性的工具分发、工作区隔离、可恢复对话、取消、审计能力，以及与模型供应商无关的统一事件。

初始架构有意把 Tauri 保持在系统边界，确保智能体运行时无需打开桌面窗口也能独立测试。

## 系统结构

```text
React 界面
  -> 类型化 Tauri 命令
  -> 应用服务
  -> AgentRuntime
       -> ContextBuilder（上下文构建）
       -> Provider（模型适配）
       -> ToolRegistry（工具注册）
       -> PolicyEngine（权限策略）
       -> ToolExecutor（工具执行）
       -> ThreadRepository（会话存储）
  -> 版本化 AgentEvent 事件流
  -> Zustand 展示状态
```

## Rust 模块职责

| 模块 | 负责 | 不得负责 |
| --- | --- | --- |
| `commands` | Tauri 请求校验和响应映射 | 智能体循环、SQL、模型响应解析 |
| `agent` | Turn 生命周期、上下文组装、循环控制、取消 | 具体工具和 HTTP 协议格式 |
| `providers` | 认证头、请求体、SSE 解析 | 工作区访问和界面事件 |
| `tools` | 工具定义、参数校验、执行结果 | 用户授权决策 |
| `policy` | 允许、需要审批、拒绝决策 | 工具实现 |
| `storage` | JSONL 事件日志、SQLite 索引、Repository；`history_pagination` 负责有界 turns/items 游标分页与历史 Item 视图裁剪 | 界面状态 |
| `protocol` | 版本化命令和事件 | 业务行为 |
| `extensions` | 规则、Skills、MCP、Hooks、本地插件发现、运行时注册表准备和扩展审计 | 第二套智能体循环、模型协议或授权决策 |
| `ocr` | 通过 Tauri 资源加载本地 PP-OCRv5 ONNX 模型，执行图片文字识别 | 模型供应商请求、工作区文件访问 |

## 前端职责

```text
src/
  components/       通用视觉组件
  features/         对话、设置、工作区、活动面板
  stores/           从运行时事件派生的展示状态
  api/              类型化 invoke/listen 封装
  types/            前端协议类型
```

前端不得直接调用模型 API、打开 SQLite、执行命令或决定某项工具操作是否安全。

## 桌面生命周期

桌面入口在其他 Tauri 插件之前注册官方单实例插件。用户重复启动 k-Coder 时，后启动的进程不创建第二套窗口和运行时；首个进程恢复、取消最小化并聚焦 `main` 窗口，同时通过原生信息对话框明确提示应用已经在运行。该入口只负责桌面生命周期，不创建第二套 `AppState` 或智能体循环。关闭主窗口会隐藏到托盘而不是退出进程。

用 k-Coder 修改本仓库时，不要使用正在监视源码的 `pnpm tauri dev` 实例。应先打包并启动一份冻住的宿主二进制，再把 git 工作区当作普通项目打开。步骤见 `docs/自修改操作说明.md`。

## Turn 状态机

```text
queued（排队）
  -> streaming（流式响应）
  -> awaiting_approval（等待审批）
  -> running_tool（执行工具）
  -> streaming（继续响应）
  -> completed（完成）

任意活动状态 -> cancelled（已取消）
任意活动状态 -> failed（失败）
```

运行时必须先持久化会改变状态的事件，再发布对应的界面事件。这样应用崩溃后可以恢复状态，界面也能重新构建。Turn 进入 completed、failed 或 cancelled 终态后，同一 Turn 不得保留 running 工具活动；缺少最终工具结果的活动在失败 Turn 中投影为 failed，在取消 Turn 中投影为 cancelled，实时事件与 JSONL 恢复必须使用相同规则。

## 智能体循环

`turn_start` 和 `turn_retry` 在 Tauri 边界预分配稳定 `turnId`，但只在运行时持久化并发布 `turn_started` 后返回 `TurnHandle`。此后 AgentRuntime 在后台继续执行；启动命令不返回终态，客户端只从公共事件和统一历史查询获取结果。活动线程上的新消息或重试先以带类型的工作项进入 Rust Thread mailbox，并立即返回 `queued` handle。启动前校验失败仍作为命令错误返回，阻塞式 `run_turn`/`retry_turn` 仅作为迁移兼容入口复用同一执行函数。

1. 校验会话、工作区、模式和用户输入，并占用该线程的活动 Turn 槽位。
2. 追加用户消息、Turn 模式和 `turn_started` 事件，发布启动事件并确认 handle。
3. 从持久化历史、项目规则和 Token 预算构建上下文。
4. 携带原生工具 Schema 发起 Provider 请求；支持流式文本和图像生成模型的单次响应。
5. 将文本增量作为非持久化展示事件转发。
6. 使用注册的 Schema 校验每个工具调用。
7. 请求 `PolicyEngine` 给出允许、审批或拒绝决策。
8. 执行已授权工具，把结构化结果追加到历史中。
9. 继续调用模型，直到模型返回最终文本或达到运行时限制。
10. 持久化 `turn_completed`、`turn_failed` 或 `turn_cancelled`。

## Provider 契约

Provider 负责把外部协议转换为少量内部事件：

- `text_delta`：文本增量
- `image`：有界的生成图片数据（由助手 `ChatMessage` 的 `Image` 内容块持久化）
- `tool_call_delta` 或完整工具调用
- `usage`：Token 用量
- `completed`：请求完成
- 类型化 Provider 错误

`AgentRuntime` 不得直接解析 OpenAI、DeepSeek、Anthropic 或 Google 的协议载荷。当前适配器支持 OpenAI-compatible Chat Completions、DeepSeek Chat Completions、OpenAI Responses、Anthropic Messages 和 Google Gemini；新增供应商必须继续通过独立适配器接入，不能在智能体循环内部增加协议分支。显式选择 DeepSeek 传输时使用 DeepSeek 方言；为兼容已有供应商配置，OpenAI-compatible 传输中只要模型 ID 的独立供应商段以 `deepseek` 开头并带 `-`、`_` 或 `.` 分隔符（覆盖 `deepseek-chat`、`deepseek-reasoner`、V3/V4/R1 以及网关前缀）也会自动进入同一适配器，相近名称保持原有 OpenAI 载荷。

供应商配置明确区分“供应商”和“模型”：运行时持久化供应商集合和唯一活动供应商，每个供应商拥有稳定 ID、名称、传输协议、API 地址、独立凭据槽、结构化模型列表和当前默认模型。每个模型保存请求使用的模型 ID、界面显示名称和上下文长度；活动模型的上下文长度是 Provider 的硬上限，主智能体和手动压缩另外使用不超过硬上限的工作上下文基准，默认 `128,000` 硬窗口对应 `96,000` 工作基准。输入区模型选择器只能读取这份持久化集合，不得维护跨供应商的硬编码目录；切换供应商会原子更新活动 ID，后续 Turn 和连接测试按所选供应商构建 Provider。旧版单个 `provider.json`、单个 `model` 或字符串模型列表加载时会自动升级；历史前端 `localStorage` 供应商列表只作为一次性公开配置迁移输入，不再是事实来源。API Key 始终按供应商 ID 隔离保存在操作系统凭据设施中，不能从旧前端标记推断密钥存在。

## 实时交互事件

- 对话协议按 ADR 0015 至 0025 收敛为 `Thread -> Turn -> Item`。最新事件 schema 为 v5；v4 开始要求 `text_delta` 携带运行时生成的稳定 `itemId`，v5 为 `usage_updated` 增加独立的当前上下文用量。助手回复、安全 Reasoning 摘要、Tool call、Approval、Change、UserInput 和 ContextCompaction 都复用 `item_started`/`item_completed` 生命周期。助手增量、工具前说明持久化投影和最终 `ChatMessage.id` 使用同一 ID，Tool 使用 `callId`，Approval/UserInput/Change 使用各自领域对象 ID，ContextCompaction 使用外层事实事件 ID；前端只按 ID 合并和展示，不生成新的领域身份。Turn 失败或取消以及崩溃恢复必须闭合实际启动的 Item，没有启动事实的旧事件不得伪造完成事件。旧 schema v1/v2/v3/v4 事件继续显示兼容，缺少 `turn_started.userMessage` 时不伪造用户消息。正常客户端使用异步 `turn_start`/`turn_retry`，活动输入和重试由 Rust Thread mailbox 串行接纳，控制命令以 `expectedTurnId` 精确匹配活动 Turn；steer 在同一 Turn 中继续，不能退化为取消后排队，错误恢复也不得退回线程级取消。
- 版本化历史载荷位于 `protocol/`，`storage/` 只从 JSONL 构建 `ThreadTurn -> ThreadItem`。`read_thread_history` 为工作台提供最近 Turn 快照，`list_thread_turns` 和 `list_thread_items` 提供最大 100 条的独立页面；游标绑定 thread、资源、锚点和 items 的可选 Turn 过滤条件，跨查询复用或陈旧锚点必须失败。`nextCursor` 继续当前方向，`backwardsCursor` 可反向读取锚点及其后的新记录。Item 自带类型化领域载荷与对应时间线片段，审批和关联工具的展示顺序在后端统一，界面不得再从消息、工具、审批和变更快照重新猜测。
- `AgentRuntime` 在每轮 Provider 调用前发布独立的 `thinking` 状态，并在回复、工具执行、审批等待和收尾之间显式切换。活动状态是瞬时展示状态，不写入 JSONL。公共运行时指令要求多步骤任务在首次工具调用前，以及完成一组探索、修改或验证工具后、开始下一组工具前输出简短进度说明，使时间线形成“说明 -> 工具 -> 已确认事实与下一步 -> 工具”的自然过程；说明不得包含私有思维链或逐步内心推演。
- OpenAI Responses 适配器按全局推理强度请求 `reasoning.effort` 并附带 `reasoning.summary=auto`，只把 `response.reasoning_summary_text.delta/done` 转换为公共事件；Gemini `generateContent` 在推理启用时请求 `includeThoughts=true`，只把标记为 `thought` 的摘要文本投影为同一类事件。普通 Chat Completions 的非标准 `reasoning_content`、Anthropic 原始 thinking 块和 Responses `reasoning_text` 都必须忽略；DeepSeek 是受限例外：适配器发送官方顶层 `thinking`，把应用推理档位映射到 `low/high/max`，并仅在当前 Provider 实例的有界内存中暂存工具调用前的 `reasoning_content`，用于同一 Turn 的官方原样回传。官方流的首帧空串只是占位；思考工具响应结束后仍没有非空私有推理时，不能把空串伪装成完整 passback，而应视为兼容端点没有提供必要协议事实。该明文不得成为 ProviderEvent、JSONL、SQLite、日志、摘要或界面内容；重启、进入后续 Turn，或兼容端点没有返回可用私有推理时，适配器只保留非空助手进度并把工具结果转换为自然语言的 assistant 历史观察，不发送缺少 passback 的原生工具消息，不包含调用 ID、原始参数和内部协议标记，也不得把工具输出提升为 user 角色。`request_user_input` 的旧记录只保留解析后的用户澄清；请求边界可以从同一请求的结构化工具事实重建旧内部格式，并定向清理逐字匹配的 assistant 尾块，但不得模糊删除无关 assistant 说明、user/system 正文或持久化事实。只要降级请求仍以 assistant 观察收尾，DeepSeek 适配器就追加一条固定、不含任何工具内容的 user 续跑意图，避免端点继续要求无法取得或已经安全释放的私有 `reasoning_content`。如果兼容端点仍在带原生工具历史的思考请求上返回明确包含 `reasoning_content` 与 passback/thinking 语义的 HTTP 400，Provider 只在流尚未开始时清空私有缓存、强制同一安全降级并自动重发一次；第二次失败以及其他 400 均直接返回，不进入通用重试。该降级状态只存在当前 Provider 实例。完成的安全摘要仍以有界领域事件持久化并进入 Turn 时间线，但不加入下一轮模型消息。摘要是否进入可见对话由展示层独立决定，不能反向删除事实事件。关闭推理时，DeepSeek 显式发送 `thinking.type=disabled`，其他 Provider 省略对应推理配置。
- 模型可见的 `run_command` 接收 `command`、工作区相对目录和超时。execution 层参考 Codex 按平台选择默认 shell：Windows 依次尝试 `pwsh`、Windows PowerShell 和 `cmd.exe`，PowerShell 使用 `-NoProfile -Command` 并设置 UTF-8 控制台输出；Unix 优先使用受支持的用户 `SHELL`，再回退到 `zsh`、`bash` 或 `sh`。Windows x86_64 桌面包固定内置经过归档和文件 SHA-256 校验的 ripgrep 15.2.0；Tauri 只把资源目录交给 execution 层，普通命令与交互 PTY 在各自子进程环境中把该目录置于 `PATH` 首位，不修改多线程宿主的全局环境。模型可以直接调用 `rg`，但 PowerShell 不替原生程序展开路径通配符，必须把 `index-*.js` 放入 `rg --glob` 并传入目录，或先用 `Get-ChildItem` 得到精确路径；匹配到该类失败时，工具结果附加有界恢复提示但不静默改写命令。Windows PowerShell 还会把原生命令管道重新编码为 CRLF；下游 `rg` 使用 `$` 行尾锚点时必须增加 `--crlf` 或改用 `Select-String`。只有 `powershell.exe` 中退出码 1、空输出且命令形态与该问题一致时才附加专用恢复提示；`pwsh`、已有错误输出和其他终态不得误提示，原始命令继续完整审计且不由运行时改写重跑。其他 Shell 操作继续使用 `Get-Content`、`Get-ChildItem`、`Select-String` 等 PowerShell 原生命令。宿主 IPC 的结构化 `start_command(program, args)` 保持不变。策略在 shell 转换前评估原始脚本，只有单条可静态拆分的已知只读或构建/测试命令可以免审批；管道、重定向、串联、动态展开、未知程序和写入/破坏性命令必须审批。运行时从已脱敏的游标缓冲区读取 stdout/stderr，按有界批次送入固定容量进展队列。队列拥塞时允许丢弃瞬时展示事件，最终 `ToolResult` 和审计语义不能丢失。进程退出、超时或取消后只允许输出读取任务在有界窗口内排空；命令等待除状态通知外每 100ms 复核一次会话终态，通知遗漏或派生进程遗留输出句柄都不能无限阻塞最终 `ToolResult`。`corepack npm/pnpm/yarn build|test|lint|typecheck` 与直接调用包管理器使用相同的构建/测试风险分类，不产生未知可执行程序审批。
- 前端按事件顺序投影说明文字、安全摘要、工具状态和生命周期摘要。审批请求与解决事件在事实投影中按对应工具调用 ID 排在工具活动之前，刷新历史使用审批快照执行同样规范化；常规对话不渲染 Provider 上下文、逐次用量、命令输出或已解决/自动批准审计行，待处理手动审批只显示可操作卡片。实时命令输出仍经过固定容量进展队列和有界持久化结果传给运行时，不通过对话 DOM 无限追加。
- 对话中的 `run_command` 工具项只渲染脱敏后的原始命令文本和内联状态；失败时状态可附带一条最多 180 字符的恢复提示或首条脱敏错误并做省略，不展开完整命令输出。工作目录、超时、实际 Shell、耗时和输出子面板继续隐藏。该约束只作用于界面投影；持久化的工具结果、实际 Shell 元数据和有界 stdout/stderr 仍用于 Provider 历史、恢复和审计。文件和补丁详情继续按需懒加载只读 Monaco。
- `turnTimeline` 是当前线程的唯一实时展示事实源，除 `text`、`reasoning`、`tool` 外还包含有界的 `event` 生命周期项；旧 `toolActivities` 只用于无时间线历史的迁移。前端按 Turn/调用 ID 去重工具生命周期，并按 stdout/stderr 与游标去重输出增量，不能再把同一事件同时追加到消息和活动列表。公共运行时指令以中英文同时要求用户可见 reasoning summary 使用简体中文；常规中文界面过滤 Provider 偶发返回的纯英文或英文叙述占主导的摘要，以及只描述 planning、checking、running、testing 等当前动作的短小过程句，活动状态仍由 Turn 状态标题表达。包含结论、原因、风险、约束或足够上下文的中文安全摘要才以“思考摘要”展示；全部相邻可见摘要不再按完成状态拆分，而是合并为无边框、无底色、不可折叠的平铺组，标题与正文始终一起显示。相邻工具活动聚合为独立可展开组，任何说明、可见思考、变更或其他可见生命周期事件都会切断工具组。展示过滤不删除或改写事实事件，原始摘要仍完整持久化和恢复，无可见内容的审计型孤立 Turn 不渲染空助手容器。
- 助手正文的展示节奏属于 `src/` 展示状态，不能反向延迟或改写 `turnTimeline`、运行时终态、工具状态、持久化和队列调度。活动 Turn 按已接收正文积压量自适应揭示文本；展示层以最早一段尚未揭示完成的正文截断可见时间线，后到的工具、事件和正文等待其追平后再按事实顺序放行，多段正文只依次推进。终态已经进入事实状态但仍有未展示正文时，界面继续保持生成态，排空后再显示终态并折叠过程。历史恢复直接展示完整文本；从其他会话切回仍在运行的 Turn 时，快照中已有正文同样必须首帧完整显示，只有恢复后新收到的增量继续按实时节奏揭示，切换展示不得调用 `turn_start` 或 `turn_retry`。减少动态效果偏好也直接展示完整文本。消息区只在视口贴近底部时随内容尺寸增长跟随；明确的向上滚轮、触摸或滚动条拖动暂停跟随，回到底部后恢复，已排队的滚动帧执行前必须复查用户意图。
- Turn 完成、失败和取消事件公开 `startedAtMs`、`completedAtMs` 与 `durationMs`，阻塞兼容返回值、终态事件和历史查询使用同一组时间；异步 `TurnHandle` 只公开身份和活动状态。历史投影从同一 Turn 的 `turn_started` 与终态事件恢复总耗时。活动 Turn 使用随 `thinking`、回复、工具、审批和收尾阶段变化的紧凑状态标题并保持外层展开，不使用固定的“正在执行”外层标题；状态标题显示在过程内容之后，始终跟随时间线的最新记录，不显示折叠用的上下箭头，标题上方直接展示进行时动作、动态指示和实时耗时。经过可见性过滤的相邻中文思考摘要合并为一个平铺展示组，内部仍按事件顺序保留全部内容；摘要组不显示卡片、完成状态或箭头，也不提供独立折叠，工具、说明或生命周期事件会切断分组。活动 Turn 中 pending/running 工具组自动展开，已经完成的过程步骤和带详情生命周期事件默认折叠；思考摘要只受 Turn 外层可见性控制，仅有过程短句或纯英文摘要时只显示通用活动状态。正式 `update_plan` 计划不进入执行过程折叠区，而是在回答后持续显示“第 X/Y 步”的紧凑胶囊；当前 Turn 存在未撤销文件变更时同时显示唯一目标文件数和累计增删行，悬停、键盘聚焦或点击可查看各步骤和状态。工具组摘要使用无边框、透明背景的轻量行，仅保留状态点、标题和紧跟标题的展开箭头；收起显示右箭头，展开显示下箭头，非完成态状态文字跟在箭头之后，不再显示终端或扳手 logo，展开内容通过左侧连接线表达层级，不再使用卡片外框。纯 `run_command` 组按数量显示“运行了命令”或“运行了多个命令”；展开后每条命令保留状态图标，只显示命令文本和状态，多个命令的内容区最多显示 168px 并在超出时独立纵向滚动，单命令与普通操作组按内容自然展开；其他工具保留适用的参数、输出、状态与耗时，运行、失败和取消继续使用各自状态色。同一连续工具组内，后续成功的 `apply_patch` 只会按补丁头解析出的完整目标文件集合，覆盖此前同目标的失败展示；被覆盖失败不再贡献组状态、明细行和外层可见操作数，不同目标、最终失败、尚未成功或无法确定目标的调用仍显示。文件变更事件独立显示为“编辑了文件”，修改类文件明细显示“已编辑 文件名”。助手阶段性说明与最终回复不进入步骤折叠区；尚无工具活动时不渲染额外的空工具调用占位行。完成、失败或取消任一终态到达后，Turn 外层统一默认折叠为单行摘要；用户展开失败或取消 Turn 时直接看到终态原因和就地操作，思考摘要随外层内容直接显示，工具组和生命周期步骤仍可按需展开审计，命令输出不进入对话投影；计划胶囊继续可见。最终回答始终独立显示。对话内容不显示助手头像，避免头像动画与真实执行状态形成两个竞争信号。该折叠、分组和重试过滤只改变展示状态，不删除领域事件、不缩减 Provider 历史，也不触发 Compaction。
- Turn 进入任一终态并触发执行过程收起时，前端复用同一 `details` 节点并通过 `details::details-content` 以 380ms 高度缓出收缩，箭头使用较慢缓出；`prefers-reduced-motion` 时即时收起。展开工具组后，每条命令保持“命令文本 + 状态”的单行摘要，失败状态允许附带有界诊断并在空间不足时省略，不再创建参数卡或输出子折叠；原始工具结果和脱敏边界不变。`apply_patch` 和 `write_file` 参数详情仍按需使用只读 Monaco；已应用文件变更只使用 `change_applied` 中持久化的前后快照渲染内联 Monaco Diff，不重新读取磁盘，快照因大小边界缺失时改用已持久化 unified diff 的只读编辑器。
- `request_user_input`、任务清单、审批、变更、Provider 用量、Compaction 和 Turn 终态都先写入 JSONL 再发布实时事件。自动 Compaction 落盘后立即发布带稳定事件 ID、自动/手动来源和三项有界计数的 `context_compacted` 公共事件，不能把内部摘要或近期工具结果正文复制到前端；当前界面无需刷新即可显示与恢复投影一致的“已自动压缩上下文”步骤。线程加载期间当前线程的事件进入 hydration buffer，快照应用后按顺序重放；切换线程不会把事件写入错误的时间线。
- `ProviderCallUsage` 同时参与两个不同投影：`lastUsage` 与 `usage_updated.usage` 是当前 Turn 内多次 Provider 调用的累计消耗，只用于成本/预算；`contextUsage` 与 `usage_updated.contextUsage` 始终取最近一次已完成 Provider 调用的单次 `totalTokens`，表示模型实际看到的当前上下文。线程详情和统一历史快照都恢复 `contextUsage`；`context_compacted` 会立即清空它，等待压缩后的下一次 Provider 用量重新建立基线。输入区进度以 `contextUsage.totalTokens / 当前活动模型 contextWindow` 计算，禁止用累计消耗冒充上下文占用。
- 当用户行为、变更范围或兼容性取舍无法从工作区上下文确定，且错误假设会改变结果或造成返工时，Craft、Ask 和 Plan 模式都可以通过 `request_user_input` 主动询问；回答会在同一 Turn 中继续处理。低风险、可从仓库发现或已经明确的事项不重复确认。
- 每个 Turn 的 Craft、Ask 或 Plan 协作模式作为独立 JSONL 事件持久化。失败或取消后的重试必须由后端恢复原 Turn 模式，并重新应用相同的模式指令和工具 Capability；前端不能通过省略参数把 Plan/Ask 重试升级为 Craft。重试运行时复用 `AppState` 持有的 `UserInputManager`，确保恢复后的 `request_user_input` 与普通 Turn 通过同一解析入口继续。
- 取消请求发出后，界面必须保持 Turn 忙碌，直到收到或恢复出持久化的 `turn_cancelled`、`turn_failed` 或 `turn_completed`。排队消息绑定入队时的线程，切换线程不能把后续 Turn 错发到当前线程；重试复用原用户消息，不能重复追加。每次重试仍创建独立 Turn 并保留各自时间线与终态，以维持取消、审计和恢复边界；实时事件与历史投影都把这些 Turn 锚定到原用户消息，前端将同一用户消息的多次尝试渲染在一个助手回复容器中，只显示一次助手角色标识。
- 当前 Turn 处于 thinking、工具执行或等待审批时，输入区仍保持可编辑；主发送调用 `turn_start`，并在存在活动 Turn 时携带点击瞬间观察到的 `interruptActiveTurnId`。`AppState` 按 operation gate -> active Turn -> mailbox 的固定锁序先让新消息进入 mailbox，再关闭并取消 ID 精确匹配的活动 Turn；过期 ID 只保留新消息，不得取消已经接替的 Turn。前端在 IPC 前立即显示“正在停止”，但仍等待持久化的旧 Turn 终态；原 mailbox worker 随后按 FIFO 接纳新消息，在同一 thread 中写入新的 `UserMessage` 和 `TurnStarted`，因此新方向是新的审计 Turn，而不是注入正在取消的 Turn。兼容阻塞入口若没有 mailbox worker，新 worker 必须等旧活动项释放后再取 replacement，不能提前出队并拒绝消息。失败/取消后的重试继续调用 `turn_retry`。Rust Thread mailbox 对每个线程只运行一个 worker，其余输入和重试按 FIFO 保存为带 `kind` 的 pending 项，返回 `queued` handle；不同线程拥有独立 mailbox，可并行调用 Provider 与工具。pending 输入尚未成为领域事实，不提前投影为对话用户消息；只有 worker 接纳普通输入、写入 `UserMessage` 和 `TurnStarted` 后，`turn_started.userMessage` 才把稳定身份交给前端，重试则复用原用户消息。工作台通过 mailbox revision 事件和 snapshot 展示、删除或清空 pending 项，不持有调度锁。普通消息队列项的“加入当前对话”仍只调用 `turn_steer_queued(threadId, expectedTurnId, queuedTurnId)`；后端从 mailbox 读取原始正文和附件，并在活动 Turn 精确匹配、`TurnControl` 接纳成功后原子删除 pending 项。该动作是真正的同 Turn steer，不取消活动 Turn；停止期间必须禁用。worker 已先取走、Turn 已收尾、重复请求或 retry 项都不会被重复注入；前端不再组合 steer 与删除命令。重试项不可 steer，但可删除。独立停止和错误恢复仍使用 `turn_interrupt(expectedTurnId)` 精确取消匹配的活动 Turn，并等待持久化终态或重新读取运行时状态，不调用线程级兼容取消。steer 在 Provider 请求完成后的受控边界持久化输入并发布 `turn_steered`，收尾锁关闭后到达的请求必须拒绝。
- 图片附件保留原始 data URL 交给支持视觉的 Provider，同时在本地通过 Tauri `recognize_image` 命令调用随应用打包的 PP-OCRv5 模型。原图持久化为可恢复的 `image` 内容块，允许不输入文字直接发送，并在用户消息中显示紧凑附件标签；有界识别文字及图片单独发送时的分析提示持久化为仅供 Provider 使用的 `context` 内容块，不进入可见用户正文，也不在附件区展示识别正文、行数或失败状态。OCR 失败不能阻塞原图发送；模型、运行时 DLL 和词表只能从应用资源目录加载。
- 助手正文、实时说明和安全摘要共用受控的 GFM Markdown 渲染边界。原始 HTML 不解析，远程 Markdown 图片不自动请求；表格和代码块在自身容器内滚动，不能撑破对话布局。

## Phase 2 只读运行时边界

- 应用启动时把进程启动目录 canonicalize 为本次工作区根目录；正式的工作区选择和切换由 Phase 6 提供。
- `list_directory` 与 `read_file` 只接受一个已存在的精确工作区相对路径，分别要求目录和普通文件，不接受猜测名称或 `*`、`?`、`[...]` 通配符。解析仍先拒绝绝对路径、父级遍历和链接逃逸；不存在时优先扫描最多 500 个已存在父目录同级项，父目录本身不存在时再进行最多 2,000 个条目、深度 8 的工作区候选扫描，并返回最多 3 个同类型候选。候选只用于诊断，不自动打开模糊匹配项；文件/目录混用时返回正确工具及父目录探索动作。
- `list_directory` 只列直接子项，默认最多 200 项、最多 500 项，并忽略 `.git`、`node_modules`、`target`、`dist` 和 `build`。
- `read_file` 识别 UTF-8 BOM、UTF-16LE 和 UTF-16BE；单文件最大 4 MiB。无范围参数时默认最多返回 64 KiB；优先使用 `startLine/lineCount` 读取代码范围，只要任一行范围字段存在就忽略冗余的 `offset/limit`，旧字节范围在没有行范围时继续兼容，显式范围单次最多返回 256 KiB。结果元数据同时记录规范化工作区相对路径、完整文件字节的 SHA-256 修订、实际行号、字节数、总行数、总字节数和前后任一侧是否仍有省略内容；不同读取范围不能改变同一内容的文件修订。
- 普通、无活动 Goal 的根 Turn 不设置生命周期 Provider 迭代数或工具调用总数硬上限，也不因累计统计值达到固定阈值而失败；但按 `100` 次 Provider 请求（包含内部重试尝试）、`1,000,000` 累计 tokens 或 `10` 分钟分段墙钟时间设置软续跑门，任一达到后在下一安全轮次边界通过 `turn_continuation` 类型的 UserInput Item 暂停。提示明确请发送“继续”，界面以“继续执行”结构化动作提交该指令；用户也可选择压缩后继续或停止。前两者重置本段计数并允许反复续跑，停止、跳过、超时或取消以 `turn_cancelled` 收尾。显式 Goal/子智能体 Token 与时间预算保持原硬边界且不叠加该软门。普通工具和连续失败或缺少版本元数据的 `read_file` 同名同参最多重复 2 次；已成功产出版本化观察的文件读取改由更精确且有界的语义保护负责。运行时在当前 Turn 内按规范路径、文件 SHA-256 修订和已返回行区间跟踪 `read_file`：新修订或新增覆盖属于进展；同一修订的请求区间已有至少 80% 被覆盖时，第一次冗余读取返回 `read_observation_already_covered` 并抑制正文，第二次返回成功的 `read_observation_recovery_required`，为下一次 Provider 请求加入一条不持久化的宿主 System 纠偏，要求复用已有观察且不得通过读取、Shell 或搜索绕过；纠偏后第三次冗余读取才以中文 `repeated_observation_loop` 终止。插入其他工具、改变行范围参数或 Compaction 不能重置状态，文件修订变化后允许定向复查。每次请求最多消费 4 条待处理读取纠偏，纠偏不伪造成用户消息。每 5 轮的兜底进展快照只比较文件修订/覆盖、目录/搜索/命令观察修订和文件变更，不把不同输出片段自动视为进展；连续 3 个窗口没有新状态时类型化失败。
- `assistant_tool_calls`、每个 `tool_started`、每个 `tool_result`、用户输入/任务清单生命周期与 Turn 终态先写入 JSONL，再发布工具或状态界面事件。同一次 Provider 响应中的工具调用严格按返回顺序串行执行；批次落盘时所有调用先处于 pending，只有当前工具写入 `tool_started` 后才进入 running 并开始计时，它的最终结果持久化并发布后才允许下一项启动，避免恢复时把尚未执行的调用误报为“执行中”。Provider 历史继续使用调用 ID 校验完整工具组。
- 从 JSONL 重建 Provider 历史时，每次请求前都必须按 `tool_call_id` 校验完整工具组，不能只在 Compaction 时修复。只有调用 ID 唯一且每个调用恰好对应一个紧随其后的结果时才保留结构化工具组；缺失、重复、错配和孤立结果全部丢弃，工具调用前已经持久化的非空助手说明降级为普通助手文本保留。
- 工具调用前已流式输出的可见进度说明与 `assistant_tool_calls` 一起持久化并带入下一次 Provider 请求；`read_thread` 同时投影按事件顺序排列的 Turn 时间线，界面在活动期间据此交错展示说明、单个工具状态和最终回答。公共指令要求长任务在工具批次之间报告刚确认的事实和下一步，但不逐条复述每个命令；文件路径尚未由当前用户请求或此前发现结果确认时，模型必须先单独发现并等待结果，不得在同一批并行发起猜测的 `read_file`/`list_directory` 调用。路径和内容已经确认且文件修订未变化时，不得为“再次确认真实状态”读取高度重叠区间；修改后最多做一次针对改动点的验证，工作已经完成时直接给出最终答复。Turn 进入完成、失败或取消任一终态后，中间过程默认折叠为带真实总耗时或失败语义的摘要；展开外层后，错误原因和操作直接可见，过程步骤仍可按需逐层展开。任何终态都不得覆盖、删除或阻止展开已持久化进度，最终回答不得放进过程折叠区。进度说明只描述当前动作、已确认事实和下一步，不暴露模型隐藏推理链。
- 时间线单项摘要最多 2,000 字符；Provider 上下文最多 512 KiB，单次模型响应最多 512 KiB，工具结果继续受各自载荷边界限制，但单 Turn 不设固定调用总数。AgentRuntime 对 Provider-facing 工具 Schema 的顶层描述设置 2 KiB 上限，对超出 128 KiB 的工具结果保留首尾并记录原始/省略字节数；`run_command` 最终结果可携带最多 64 KiB 的脱敏 stdout/stderr chunks，刷新后仍按 stream 与 cursor 恢复。
- 逐次 Provider 用量同时服务两种不同语义：所有调用相加得到 Turn/线程累计统计；最近一次调用的 `total_tokens` 代表当前活动上下文窗口。失败但已返回 Usage 的内部重试也使用唯一调用序号落盘并计入累计值、普通 Turn 当前软额度和显式 Token 预算，不能只统计最终成功尝试。自动 Compaction 同时估算消息历史、运行时指令和工具 Schema，并参考最近一次 Provider 用量；默认以活动模型硬窗口以内的 `96,000` 工作基准的 65% 触发，压缩后的历史只保留工作历史预算的四分之一和同等规模的确定性摘要，避免刚压缩就再次触发。软续跑门的“压缩后继续”会在下一次 Provider 请求前强制尝试压缩。CompactionSummary v5 保留当前用户请求、最近 4 条有界请求、用户约束、最多 12 条高信号工具观察和最近 2 个工具结果；从 JSONL 派生 Provider 历史时，有效 `read_file` 结果根据宿主持久化元数据增加 `[read_file observation]` 结构化来源头，包含路径、文件修订和实际起止行，使来源进入工具观察、自由摘要和近期结果。来源头只存在于 Provider-facing 派生输出，不改写原始工具正文或 JSONL。超过 4 KiB 的工具结果在摘要中替换为包含原始长度、行数和首尾片段的确定性摘要。当前压缩消息出现成功 `apply_patch` 或 `write_file` 时，最新成功写入是工作区事实失效边界：不得继承旧摘要中的工具观察、近期工具结果或自由摘要正文，也不得保留边界之前的读取、搜索和命令事实；真实用户请求、约束及写入结果继续保留。Provider 历史必须把结构化摘要与压缩后新增消息分开保存，只能在发起 Provider 请求时渲染摘要；请求身份和约束只从 JSONL 中真实的 `UserMessage` 重建，后续压缩不得把 `[Compacted context vN]` 摘要文本再次识别为用户输入。旧 v4 摘要继续兼容读取，旧 v3 递归摘要在内存恢复时用真实用户事件清理，事实日志不重写。Compaction 事件会重置恢复侧的当前窗口用量基线，并在落盘后实时进入当前 Turn 时间线；原始 JSONL 事实不删除，压缩前后估算规模、压缩消息数和估算节省 token 仅进入本地 Runtime Metrics，不能生成没有配对工具调用的孤立工具输出。
- 参数有效且已执行的普通工具失败会作为结构化 `tool_result` 进入下一次 Provider 请求，使同一 Turn 可以检查失败、修改并重新验证。审批审计或事件存储失败不属于模型可修复的工具结果：运行时取消当前工具并把同批剩余未启动调用记录为跳过，完成必要回滚与失败审计后，保留原始类型化错误并终止 Turn。`turn_started` 发布后的未处理运行时错误必须尽力先持久化并发布 `turn_failed`；不能留下没有终态的活动 Turn。

## Phase 3 安全编辑边界

- 模型只能通过注册的 `apply_patch` 或 `write_file` 提议文件修改；回复文本和 Markdown 代码块没有写入能力。
- `apply_patch` 使用严格的 Begin/End、文件头和 hunk 语法，支持新增、修改、删除和移动；`write_file` 只用于明确的完整 UTF-8 文件替换。
- 写工具的模型参数不包含审批字段。`PolicyEngine` 按读取、写入、删除和外部访问分类，后端创建并持有审批能力。默认 `ask` 模式使用一次性审批；用户显式选择的会话级 `full_access` 模式可以自动批准已注册工具，但不扩大工具 Capability 或工作区边界。
- 审批请求先写入 JSONL，再发布到界面。用户可以选择文件、编辑 Patch、查看统一或并排 Diff，并明确应用或拒绝；未批准、超时和取消都不会写盘。
- `full_access` 每次自动批准仍写入配对的审批请求和解决事件，并复用 Patch 预览、修改前哈希与变更审计。模式不持久化，应用重启恢复 `ask`；活动 Turn 或子智能体存在时不能切换。输入区仅让 `full_access` 持续显示文字状态，默认 `ask` 使用低干扰图标入口。
- 同一 Turn 的连续工具调用可以产生多个审批请求。前端按请求 ID 去重并以 FIFO 队列逐个展示；解析或过期只移除对应请求。线程恢复必须把全部未决审批投影为取消，不能遗留可操作但后端已失效的审批卡片。
- 执行前重新解析 Patch、规范化路径并验证审阅时的 SHA-256。文件在审阅期间发生改变时返回冲突，不覆盖新内容。
- 多文件操作在单个编辑锁内执行；任一操作失败会根据修改前快照逆序回滚已经开始的操作。
- `change_applied` 保存有界的修改前后快照和完整 Diff。撤销前验证修改后哈希，防止撤销覆盖应用后产生的新修改，并记录 `change_undone` 审计事件。
- 当前限制为单个 Patch 1 MiB、最多 20 个文件、单文件 512 KiB、单次变更前后快照合计 2 MiB。
- 工作台中的用户直接编辑不是模型提议，不从自由文本或工具参数触发，也不伪造审批事件。界面使用本地打包的 Monaco Editor 展示行号和语法高亮，但只能通过类型化 `save_workspace_file` Tauri 命令保存；后端仅接受 256 KiB 内的 UTF-8 文本，重新规范化工作区相对路径，校验预览时返回的 SHA-256，并与模型 Patch 共用进程内编辑锁。文件在打开后被其他来源修改时必须返回冲突，不能静默覆盖。

## 工具契约

每个工具必须提供：

- 稳定的名称和说明
- JSON 输入 Schema
- 类型化参数校验
- 风险等级
- 异步处理器
- 包含成功状态、输出和元数据的结构化结果
- 取消行为
- 对有效参数、无效参数、拒绝、取消和边界情况的单元测试

`ToolRegistry` 负责发现 Schema 和处理器；`PolicyEngine` 负责授权；`ToolExecutor` 负责协调策略判断、审批、超时、取消、审计事件和处理器执行。

## 工作区安全

文件操作必须按以下顺序处理路径：

1. 把相对路径拼接到已选择的工作区。
2. 规范化路径，并对最近存在的父级目录执行 canonicalize。
3. 在平台允许时解析符号链接和目录联接。
4. 使用当前平台对应的路径比较规则。
5. 拒绝规范化后位于工作区之外的路径。

普通工作区工具不接受绝对路径。访问工作区之外的资源必须使用独立的显式 Capability，并经过用户审批。

主智能体继续使用单个活动工作区，但项目会话必须持久化创建时的规范工作区绑定。项目会话创建、选择和启动恢复先让界面同步后端真实活动工作区；后端在普通 Turn、重试和 Compaction 开始前独立校验绑定，不能把前端项目分组或模型参数当作授权依据。旧会话没有 `in_project` 事实时按项目会话兼容，只允许在首次执行前绑定一次当前规范工作区；绑定写入后不可改写，当前工作区不一致时必须在模型调用和工具执行前关闭失败。工作区切换与 Turn 启动共用活动 Turn 互斥复核，确保校验后不能切换根目录。

显式无项目会话以 `thread_created.in_project = false` 持久化，并保持 `workspace_path` 为空；Repository 必须拒绝后续工作区绑定，fork 继续保留该状态。无项目 Turn 不加载项目指令、项目 Skill、MCP 或 Hook，不注册文件、仓库搜索、Patch、Shell 和子智能体能力，system prompt 也不得暴露宿主当前工作区路径；只允许提问、计划、Goal、待办、用户启用的记忆与浏览器等显式白名单非项目工具。内部构造 `ToolContext` 所需的占位路径不能转化为模型 Capability。直接子智能体创建和输入区 `@` 文件、`/` 项目 Skill 候选同样必须关闭。

侧栏项目组与对话输入区项目选择器以同一份前端派生项目集合为基础：持久化会话 `workspace_path` 是项目归属的首要事实，显式添加但尚无会话的项目和当前活动工作区作为补充；SQLite 项目注册表的当前/最近记录只为集合中相同规范路径的项目补全名称、原始路径、信任和最近打开信息，不能让历史父目录或子目录只出现在其中一个入口。两处按共享路径等价规则去重，并从当前活动会话工作区派生同一个活动项目；输入区切换项目后创建目标工作区绑定的新会话，侧栏选择项目内会话后输入区同步显示该会话项目，侧栏活动态也随之双向更新。用户可以删除任意侧栏项目分组，无论其下是否存在会话；删除只写入按规范路径去重的前端隐藏分组集合并清理置顶、展开和显式添加状态，不调用线程删除或项目文件操作。被隐藏分组中的会话回到“会话”列表，但继续保留原始 `in_project` 与不可变 `workspace_path`，选择后仍先同步真实工作区；输入区项目选择器继续保留这些事实项目，重新选择或显式添加同一路径会清除隐藏标记并恢复分组。该展示状态不能作为授权、归属或会话存在性的依据。选择器底部的“不在项目中”创建新的显式无项目会话且不切换全局工作区，触发器和勾选状态从 `in_project` 派生；旧会话尚无该事实和绑定时才回退使用后端活动工作区。

Windows `canonicalize` 产生的 verbatim 路径继续作为项目记录、会话绑定、工作区切换和后端授权的原始事实，前端仅在展示、搜索与等价比较边界通过共享转换把 `\\?\D:\...` 还原为 `D:\...`、把 `\\?\UNC\server\share` 还原为 `\\server\share`，不得改写持久化或工具参数。用户选择另一个项目时，界面必须先通过类型化工作区命令切换真实运行时，再创建不可变绑定到目标路径的新会话，不得通过修改前端分组把已有会话改绑。活动 Turn 或子智能体存在时继续由后端拒绝工作区切换；选择器的禁用状态只是交互反馈，不替代该门禁。后端只有在完成工作区规范化、链接解析和越界拒绝后，才可以在子进程工作目录或系统文件打开的最后操作系统边界创建一次性的 Shell 兼容路径；该派生值不能参与授权或回写领域事实。工作台文件打开和资源管理器定位统一使用 Tauri opener 的系统 API，禁止把目标交给 `cmd /C start` 二次解析。

不能因为 Shell 的当前目录位于工作区内就认为命令天然安全。命令执行前必须经过策略判断，并支持输出上限、超时、取消和进程树终止。

## 持久化

JSONL schema 9 是对话和 Turn 事件的持久化事实来源。线程是否属于项目由 `thread_created.in_project` 记录，会话工作区通过 `thread_workspace_bound` 事件记录；SQLite 的 `sessions.in_project` 和 `sessions.workspace_path` 只保存可重建投影。SQLite 还保存便于查询的会话列表、设置、用量和搜索索引。

历史重写先回放已有 rollback 审计标记，再计算当前有效 Turn。连续 rollback 不重新计入已隐藏的终态，fork 也不复制已回退的 Turn；原始 JSONL 仍保留供审计。

统一历史和分页游标都从当前 JSONL 事件序列按稳定顺序即时构建，不创建平行数据库事实。读取旧会话时可以从已有领域事件推导缺失的生命周期展示状态和缺少 `TurnStarted` 的 Turn，但读取不得反写伪造事件；AppState 必须先完成既有崩溃恢复，再返回历史页面。`thread_fork` 复制全部或截至指定已完成 Turn 的有效对话历史，并写入来源审计标记；它不复制活动 Turn、工作区变更事实或 Change Item，避免产生第二份撤销能力。`thread_rollback` 追加审计标记并在读取时截断指定数量的完整 Turn；它只回退对话历史，不修改工作区文件，文件恢复仍由独立 change transaction 负责。fork/rollback 在活动 Turn 存在时拒绝，rollback 还要求 mailbox 无 pending 输入。

```text
runtime-data/
  sessions/<thread-id>.jsonl
  providers.json
  k-coder.db
  logs/
```

在可行情况下，SQLite 数据应当可以从 JSONL 重新构建。API Key 必须存入操作系统凭据设施，不能写入数据库或 TOML 配置文件。

## 子智能体

子智能体是使用受限上下文、可选预算、工具和工作区权限的普通 `AgentRuntime` 实例。`multi_agent` 只协调生命周期，不实现第二套模型或工具循环。

- 主运行时通过 `create_agent`、`wait_agent`、`send_agent_message`、`resume_agent`、`list_agents` 和 `close_agent` 获取结构化委派能力；创建、跟进、恢复和关闭按外部风险继续走后端审批。
- 每个子智能体拥有独立会话、明确工作区快照和父工具 Capability 的子集。默认只提供 `list_directory` 与 `read_file`。
- 显式无项目线程不提供子智能体 Capability，模型工具调用和直接宿主命令都必须拒绝创建。
- 最大派生深度为一层，最多同时运行 4 个子智能体；单个子智能体默认不设 Token 预算，显式设置后在恢复和跟进之间累计并硬性执行。默认运行 10 分钟、最多 30 分钟。
- 子智能体使用父取消令牌的子令牌。关闭或取消父 Turn 会真正取消子智能体的 Provider 流和活动工具。
- 子智能体继承创建时的审批模式快照，但不能借此获得父智能体未提供的工具 Capability。
- 写操作继续经过 Patch 审阅、修改前哈希和进程内编辑锁。并发写入同一路径时，后到操作必须报告冲突，不能静默覆盖。
- `subagents.jsonl` 持久化有界生命周期快照。主智能体和界面只能读取状态、可选预算、累计 Token 消耗、摘要与错误；完整子会话保留在独立线程中。
- 桌面界面在同一窗口的活动面板展示子任务，不为每个智能体创建独立窗口。应用重启时未完成子任务确定性标记为失败。

更深层委派保持关闭；自动创建仍需明确审批。评估方法和边界见 `docs/多智能体评估.md`。

## Phase 9 高级智能体边界

- `advanced` 统一拥有计划、Goal、浏览器、搜索、记忆、文档、评估和指标服务；这些能力继续注册为普通 `ToolHandler`，不得绕开 `PolicyEngine`。
- 内置机器人由 `advanced/workflow.rs` 作为主 `AgentRuntime` 上的受限工作流实现，不创建第二套智能体循环。后端持有版本化定义、角色正文、当前节点和追加式 `advanced/workflows.jsonl` 快照；前端只通过类型化命令选择机器人和读取投影。首条消息的可选 `workflowId` 只允许精确匹配内置定义，并且必须绑定项目线程和 Craft 模式；后续 Turn 与 retry 从后端活动实例恢复。
- 节点只能由普通 `complete_workflow_node` 工具推进，参数必须命中宿主当前节点并携带有界总结与证据；普通回复、特殊文本标记、模型传入的下一节点或权限字段都不能改变状态。机器人不自动启用 Skill、MCP、Hook 或子智能体，也不扩大工作区、工具、审批和外部副作用边界。自定义定义、条件分支、并行节点与可视化设计器仍不属于初始范围。
- 计划以追加式快照持久化，每个线程最多一项处于 `in_progress`。计划快照与工具活动通过 Turn 关联显示在对话时间线，工作台只保留文件和 Git 等检查视图；页面恢复后必须从持久化投影重建相同关联。Goal 默认只保留时间预算，Token 预算可选；累计 Token 消耗始终可见，显式 Token 预算与时间预算由宿主限制，暂停、阻塞、完成和预算耗尽是显式状态。
- 浏览器使用单个受控 Chromium CDP 会话，默认关闭。导航、点击、输入、截图和关闭属于外部风险，取消 Turn 会关闭会话；URL、审计日志和 8 MiB 截图制品都受边界限制。
- 仓库搜索先采用确定性、有文件数和文件大小上限的词法扫描。记忆默认关闭，启用后每项都保存来源、到期时间、修订和删除事件。
- Provider 故障切换只处理产生输出前的网络错误、408、429 和 5xx；鉴权/参数错误、无效响应、取消和流中断不会切换。配置路由仍以用户启用的备用模型和备用端点为唯一目标集合；整条路由在 `Provider::stream()` 返回流之前因网络错误或 `408/429/502/503/504` 失败时，`AgentRuntime` 对完全相同的请求执行最多 3 次、1/2/4 秒且可取消的自动重试，不启用 `fallback = false` 的模型，不虚构端点。OpenAI Chat Completions 和 Responses 还必须保留流内错误的 code/type；`server_error`、过载或暂时不可用事件映射为类型化临时故障，并且只在当前尝试尚未产生正文、图片、安全摘要、工具调用或 Provider 上下文时复用同一重试预算。此前 Provider 调用已经完成的工具轮不阻止重试当前零输出请求；当前尝试一旦产生可见或持久化输出就以失败终止，避免重复片段或工具。每次真实重放使用独立调用序号，计入软 Turn 请求数、Provider 成败、失败尝试 Usage 和自动重试指标；重试耗尽保留最后脱敏原因和实际重试次数。运行时内部的无效工具 JSON 重试遵守相同的零输出边界。OpenAI Responses `response.incomplete`、Chat Completions `length/content_filter`、Gemini 非 `STOP` finish reason，以及 Anthropic 非 `end_turn/stop_sequence/tool_use` stop reason 都映射为失败而不是完成；同一终止帧的 Usage 仍须先计入。备用目标继续共用该供应商的操作系统凭据。
- 文档提取仅支持有界 UTF-8 文本、PDF 和 DOCX，源文件最大 8 MiB、提取文本最大 512 KiB。运行指标使用本地追加日志记录延迟、Token、工具成功率、自动重试、故障切换和任务终态；未知成本必须明确显示为未知。

## Phase 7 可控扩展边界

- `extensions` 负责规则、Skill、MCP、Hooks、凭据名称映射、诊断和扩展审计；它不得实现第二套智能体循环。官方内置 Skill 从 Tauri 只读资源目录发现，用户全局 Skill 位于应用数据目录，项目 Skill 位于工作区 `.k-coder/skills`；三层按“内置、全局、项目”从低到高覆盖，同名时只保留最高优先级来源。
- 本地 Codex 插件宿主位于 `extensions/plugins.rs`，只扫描应用数据目录 `runtime-data/plugins` 的直接子目录，并要求 `.codex-plugin/plugin.json`。插件使用 `<name>@local` 稳定 ID、首次默认禁用和独立命名空间；k-Coder 不下载、解包、升级插件或安装其外部运行时。长期边界见 ADR 0040。
- 插件发现只建立有界的清单、Skill、文本资源和 MCP 索引。运行时目录只包含插件 ID、Skill 名称和描述；完整 `SKILL.md` 与已索引 UTF-8 资源通过 `plugin_skill_read`、`plugin_resource_read` 两个普通只读 `ToolHandler` 按需取得，不能覆盖内置、全局或项目 Skill，也不能凭清单风险字段扩大授权。
- 插件 MCP 把常见 stdio/HTTP 配置适配到现有 MCP 客户端，并按插件生成冲突安全且有界的服务器命名空间。相对工作目录必须留在插件根内，`${CODEX_PLUGIN_ROOT}` 是唯一替换变量；其他环境变量与 bearer 名只映射同名系统凭据。插件或单个服务器失败只关闭相应插件组件，既有全局/项目 MCP 仍保持整体关闭失败。
- Apps、OAuth MCP、Codex 专用 Hooks、`agents/` 和 `commands/` 只进入诊断，不执行。有效插件分别呈现 `disabled`、`loaded`、`degraded`、`blocked` 或 `invalid`；组件失败不得遗留上一轮工具。
- 插件启停、消失、修订和删除都由 `AppState` 编排完整扩展注册表重建。删除边界只接收当前索引的插件 ID，先禁用并撤销能力，再重新确认目标仍是无链接的直接子目录；前端和模型都不能提交删除路径。
- 全局指令、项目指令和项目规则按确定性优先级编译，在每次 Provider 请求构建后加入上下文。Skill 先由触发词选择，再在执行前把完整正文加入同一运行时指令。
- 内置 Skill 随应用资源打包并参与扩展修订指纹，不能在运行时写回或复制覆盖用户目录；全局和项目 Skill 可覆盖同名内置 Skill。非只读 Skill 必须由宿主显式启用，且任何来源的 Skill 内容都不能改变 `PolicyEngine` 决策。
- MCP stdio 与 Streamable HTTP 都先完成初始化和能力协商，再发现工具。外部名称只能以 `mcp__<server>__<tool>` 注册；任何规范化冲突都会关闭失败。
- MCP 配置使用全局 `runtime-data/mcp.json` 与项目 `.k-coder/mcp.json` 两个专用作用域，并继续兼容 `extensions.json` 中的旧配置；合并顺序为“全局旧配置、全局专用配置、项目旧配置、项目专用配置”。设置界面只编辑原始 JSON 并写入用户选择的专用作用域，不维护可视化表单副本；所有路径在读取和写入前都必须规范化并拒绝符号链接或目录联接逃逸。
- `mcp_config` 返回两份专用文件的原文、路径、解析错误和合并后的运行时诊断；`save_mcp_config` 只接收作用域与完整 JSON 文本，后端执行大小、UTF-8、严格字段、重复 ID、传输和凭据名称校验后再替换同目录文件。格式错误可以进入 JSON 修复界面，但扩展运行时继续关闭失败。
- MCP 工具是普通 `ToolHandler`。只读、写入、删除和外部访问风险由服务端 annotations 保守映射，再经过与内置工具相同的 Schema、策略、一次性审批、取消、Hook 和持久化结果流程。
- 注入的 MCP 密钥只存在于子进程环境或 HTTP Header，不进入 Provider 消息、工具参数、扩展诊断或日志。
- Hook 只能运行宿主配置的结构化命令，接收有界 JSON 并返回类型化 allow/block 决策。超时、崩溃、超限和无效输出都阻止工具。
- 扩展文件使用修订指纹；改变后重建完整注册表。加载失败时不得继续沿用“已准备”缓存。

## 初始版本不包含的能力

- 手机远程控制
- 机器人工作流设计器
- 浏览器录制与回放
- 自主长期记忆
- 插件市场
- 首发即支持多种 Provider 协议

这些能力保留在路线图中作为后续选项，但不作为成熟编程智能体的必要前置条件。

## 推理强度配置

推理强度是全局运行时设置，持久化在 SQLite `settings` 表的 `reasoning_effort` 键中，默认值为 `medium`。运行中的 Provider 请求会在开始时取得该值；Thinking 期间修改不会改变当前请求，但会作用于下一次请求和队列项。

前端选择器只使用 `off`、`minimal`、`low`、`medium`、`high`、`x_high` 六个稳定值。关闭时不发送推理字段；启用时由 Provider 适配器映射为协议字段：OpenAI Chat Completions 使用 `reasoning_effort`，OpenAI Responses 使用 `reasoning.effort`，Anthropic Messages 使用 `thinking.budget_tokens`，Gemini 使用 `generationConfig.thinkingConfig.thinkingBudget`。映射失败由既有 Provider 错误和重试边界处理，AgentRuntime 不包含协议分支。

## 工具执行详情

同一连续工具组的 Patch 重试降噪只作用于前端投影：有明确补丁目标时，后续成功调用按完整目标文件集合覆盖此前同目标失败；首个失败的补丁头没有可解析目标时，仅在其后恰好只有一次成功 `apply_patch` 的场景下视为被覆盖。多次成功、无后续成功、成功之后的失败以及不同目标仍保留；任何被隐藏失败的 Tool Item、JSONL、Provider 历史和工具结果继续完整保存。

对话时间线中的工具活动保留开始时间、结束时间和耗时。`run_command` 的结果元数据同时记录命令会话的 `startedAtMs`、`finishedAtMs`、`durationMs` 和实际 shell，但对话只显示原始 `command` 与内联状态；旧历史中的 `program + args` 继续转换为同一只读命令摘要，不属于新模型工具契约。工作目录、超时、Shell 和输出仍保留在工具调用或结果事实中，不进入命令行界面。`read_file` 的实际有界结果仍进入 Provider 历史并保留在持久化工具事件中，但对话时间线只显示目标路径、读取范围和状态等摘要，不再提供“查看读取内容”入口，也不重新读取工作区；`apply_patch`/`write_file` 显示目标路径并可展开有界提议正文，未被同目标成功重试覆盖的 Patch 即使在预览阶段失败也保留参数诊断。输出仍沿用既有的密钥脱敏边界。历史工具事件由 JSONL 的事件时间重建耗时，旧事件缺少这些字段时仍按兼容默认值加载。

文件变更事件继续使用 `ChangeSet` 中的工作区相对路径和有界 unified diff。时间线的“查看变更”入口只读取已审计的变更快照，不重新读取工作区，也不把模型自由文本当作文件修改依据。

## 工作台交互终端边界

工作台"终端"标签是用户主动操作的宿主能力，与模型 `run_command` 工具相互独立。前端通过类型化 `start_pty`/`read_pty_output`/`write_pty`/`resize_pty`/`pty_status`/`close_pty` 命令驱动 `NativePtyRuntime`，并使用本地打包的 xterm.js 渲染；`start_pty` 的空 `program` 表示平台默认交互式 Shell，复用 `execution/shell.rs` 的默认 shell 检测，Windows 为 `pwsh` → Windows PowerShell → `cmd.exe` 并附带 UTF-8 初始化，Unix 使用受支持的用户默认 shell。`cwd` 只允许工作区相对路径，空值固定为当前工作区根目录；终端不经过 `PolicyEngine` 审批，因为工作目录与进程行为完全由用户本人控制，但继续沿用 PTY 运行时的有界输出缓冲、敏感环境变量过滤、输出脱敏和进程树清理。PTY 输出脱敏只能替换敏感词元，不得重排空格、制表符、CRLF 或 ANSI 控制序列；前端按原始游标顺序写入 xterm，并以短批次串行发送用户输入、合并尺寸更新，避免并发 IPC 改变按键或 resize 顺序。终端会话在工作台开关和标签切换间保持，重新显示时只重新 fit 并聚焦，不能启动第二个会话；进程退出后界面显示终态并可显式重启。切换工作区会重建 PTY 运行时，旧会话随之失效。

## 工作台响应式边界

桌面端工作台文件/Git 面板是根网格中的独立右列，不是覆盖对话的浮层；常规桌面宽度限制为 360–440px，中等窗口隐藏侧边栏并将右栏限制为 320–400px，窄屏才切换为单独的右侧面板视图。对话列及其消息列表、消息正文和输入区都必须设置可收缩宽度边界，任何子元素的最小内容宽度都不得撑进工作台列。输入区底部选择器允许换行，模型选择器优先弹性收缩，发送和停止按钮保持固定尺寸并始终位于输入区可见范围内。

输入区的本地图片按钮统一为“添加”菜单：附件继续复用有界图片输入链路，Skill 入口唤起现有 `/Skill` 候选并遵守无项目会话的能力收缩，MCP 入口只导航到专用配置页，不绕过扩展加载、命名空间、凭据和策略边界。插件入口导航到本地插件设置页；页面只显示后端发现事实，并提供刷新、启停和经确认的删除，不提供安装或市场。小程序和自定义 Workflow 在对应运行时契约完成前仍只导航到明确未接入状态；入口聚合不能被当作工具注册、权限授予或能力已经可用的事实。内置机器人使用独立的输入区选择器，待发送选择、mailbox 中的 `workflowId` 和后端活动运行实例按优先级收敛为同一显示状态；已排队或活动时锁定机器人和 AgentMode，不能通过前端切换改写已接纳事实。菜单使用视口约束的浮层定位，并支持焦点进入、方向键、`Escape`、外部点击和桌面/窄屏布局。
