# k-Coder 扩展配置

## 文件位置与优先级

运行时按以下顺序加载指令，后加载的内容优先级更高：

1. 应用数据目录 `runtime-data/AGENTS.md`
2. 工作区根目录 `AGENTS.md`
3. 工作区 `.k-coder/rules/*.md`，按文件名排序

扩展配置按下面的顺序合并，后加载的同 ID 配置覆盖前面的配置：

- 应用数据目录 `runtime-data/extensions.json`
- 应用数据目录 `runtime-data/mcp.json`
- 工作区 `.k-coder/extensions.json`
- 工作区 `.k-coder/mcp.json`

`mcp.json` 是 MCP 服务器的专用配置文件，只允许顶层 `mcpServers` 字段。`extensions.json` 继续承载 Hooks，并兼容已有的 `mcpServers` 配置。设置中心的 MCP 页面可以分别编辑全局和当前项目的 `mcp.json`；继承自其他作用域或旧 `extensions.json` 的服务器只显示诊断，不会在保存时复制到当前文件。

已存在的文件如果不是 UTF-8、超过限制或格式错误，扩展准备和后续 Turn 会关闭失败。

## Skills

Skill 放在 `runtime-data/skills/<name>/SKILL.md` 或 `.k-coder/skills/<name>/SKILL.md`。项目同名 Skill 覆盖全局版本。

```markdown
---
name: review
description: Review repository changes
triggers:
  - review
  - code review
risk: read
enabled: true
---
Read the affected files and report findings by severity.
```

`name` 必须与目录名一致并使用小写 kebab-case。`risk` 只能是 `read`、`write`、`delete` 或 `external`。非 `read` Skill 即使声明 `enabled: true` 也默认停用，必须在设置中心显式启用。Skill 指令不会改变工具策略。

## 内置机器人与扩展

内置机器人是主 `AgentRuntime` 上的受限工作流，不是 Skill、插件或第二套智能体运行时。机器人只注入宿主持有的角色、目标和当前节点指令，并通过 `complete_workflow_node` 提交有界进度证据。

选择或运行机器人不会自动启用、安装或扩大 Skill、MCP、Hook 和子智能体能力。扩展仍按本文件的作用域、启用状态、凭据、风险映射、审批与审计规则独立准备；机器人定义和模型输出中的任何权限字段都不能作为授权依据。设置中心的“Workflows”继续保留给后续自定义编排，当前内置机器人不读取用户提供的任意工作流文件。

## 本地 Codex 插件

本地插件根目录为应用数据目录下的 `runtime-data/plugins`。设置中心的“插件”页会显示精确路径。把一个完整插件目录复制为该目录的直接子目录，并保留根清单 `.codex-plugin/plugin.json`；k-Coder 会在刷新时发现它，但首次始终为禁用。k-Coder 不提供插件市场、下载、解包、升级或 Node/Python 等外部运行时安装。

最小目录示例：

```text
runtime-data/plugins/review-tools/
  .codex-plugin/plugin.json
  skills/review/SKILL.md
  skills/review/references/checklist.md
  .mcp.json
```

清单至少包含 `name`、`version` 和 `description`；`skills` 与 `mcpServers` 可以覆盖默认的 `skills` 和 `.mcp.json` 相对路径。未知清单字段为了 Codex 包兼容可以保留，但不会获得执行能力。

```json
{
  "name": "review-tools",
  "version": "1.0.0",
  "description": "Repository review helpers",
  "skills": "skills",
  "mcpServers": ".mcp.json"
}
```

有效插件 ID 固定为 `<name>@local`。名称只允许 1-64 位小写字母、数字、点、下划线或连字符，并且必须以字母或数字开头；重复 ID 的所有候选都会成为 `invalid`，不会加载其中任意一个。

插件 Skill 使用与普通 Skill 相同的 frontmatter，`name` 和 `description` 必填，`triggers`、`risk` 与 `enabled` 可选。缺少 `risk` 时只在诊断中保守视为 `write`，不能据此授权任何工具。启用插件后，AgentRuntime 只获得有界的 Skill 目录；模型必须先调用 `plugin_skill_read(pluginId, skillName)` 才能读取已索引正文，并使用 `plugin_resource_read(pluginId, path)` 读取 Skill 树中已索引的 UTF-8 文本资源。两个工具都只读、重新校验路径，并在插件禁用、消失或失效后立即拒绝。

插件 `.mcp.json` 使用对象形式的 `mcpServers`，与上文独立 `mcp.json` 的数组契约不同：

```json
{
  "mcpServers": {
    "local": {
      "command": "node",
      "args": ["${CODEX_PLUGIN_ROOT}/server.mjs"],
      "cwd": ".",
      "env_vars": ["CODEX_PLUGIN_ROOT", "GITHUB_TOKEN"],
      "timeout_ms": 30000
    },
    "remote": {
      "type": "http",
      "url": "https://example.com/mcp",
      "bearer_token_env_var": "REMOTE_TOKEN"
    }
  }
}
```

stdio 支持字符串 `command`、字符串数组 `args`、插件根内的相对 `cwd`、`timeout_ms` 或 `tool_timeout_sec`，以及字符串数组 `env_vars`。`${CODEX_PLUGIN_ROOT}` 是唯一会被替换的变量；`CODEX_PLUGIN_ROOT` 可由宿主注入，其他名称都解释为同名操作系统凭据，不会从 k-Coder 的完整环境透传。HTTP 支持 `type: "http"`、受既有 URL 策略约束的 `url` 和可选 `bearer_token_env_var`，宿主只在内存中添加 `Bearer ` 前缀。配置与诊断只包含凭据名称，不包含值。

插件 MCP 工具仍以普通 `ToolHandler` 进入 Schema、`PolicyEngine`、审批、取消、Hooks、结果持久化和审计链。服务器会获得插件隔离的有界命名空间；一个插件 MCP 启动失败只关闭该组件，不影响其他插件或既有 MCP 配置。OAuth MCP 不会退化为匿名连接。

插件页使用以下稳定状态：

- `disabled`：有效且已发现，但用户尚未启用。
- `loaded`：声明的受支持组件均已加载。
- `degraded`：至少一个受支持组件可用，同时有失败或不支持组件。
- `blocked`：用户已启用，但没有可注册能力或缺少运行时、命令、凭据等前置条件。
- `invalid`：清单、重复 ID、路径或组件格式不合法。

Apps、`.app.json`、Codex/Claude/Cursor Hooks、`agents/`、`commands/` 和 OAuth MCP 只计入摘要与警告，不会执行。扫描最多接受 128 个候选；单个清单最大 256 KiB；每个插件最多 128 个 Skills 和 128 个 MCP 服务器；单个 `SKILL.md` 或文本资源最大 256 KiB；单个 `.mcp.json` 最大 1 MiB。Skill 树另受资源数和遍历条目上限约束，宿主不会递归扫描未声明的 `node_modules` 或构建产物。

所有组件路径都必须留在插件根内；绝对路径、`..`、符号链接、Windows reparse point、目录联接和规范化逃逸都会关闭该插件。删除必须在页面确认；后端只接受当前索引中的插件 ID，先禁用并重建注册表，再次确认目标仍是同一个直接子目录后才删除。若删除失败，目录保留且插件保持禁用。插件消失后，宿主同样撤销能力并重置启用状态，重新复制不会静默启用。

## MCP

stdio 示例：

```json
{
  "mcpServers": [
    {
      "id": "github",
      "enabled": true,
      "timeoutMs": 30000,
      "transport": "stdio",
      "command": ["node", "server.mjs"],
      "secret_env": {
        "GITHUB_TOKEN": "github-token"
      }
    }
  ]
}
```

Streamable HTTP 示例：

```json
{
  "mcpServers": [
    {
      "id": "remote",
      "transport": "streamable_http",
      "url": "https://example.com/mcp",
      "secret_headers": {
        "Authorization": "remote-authorization"
      }
    }
  ]
}
```

`id` 必须使用 1-64 位小写字母、数字、下划线或连字符。`secret_env` 和 `secret_headers` 的值是凭据名称，不是密钥；凭据名称只允许 1-128 位字母、数字、点、下划线或连字符。密钥通过设置中心写入系统凭据存储，不会写入 `mcp.json`。远程 HTTP 必须使用 HTTPS；只有 loopback 地址允许 HTTP。工具以 `mcp__<server>__<tool>` 暴露。

MCP 页面直接编辑原始 JSON，并提供全局/项目作用域切换、格式化、文件状态和运行诊断，不维护第二套可视化表单状态。保存前会校验文件大小、未知字段、重复 ID、结构化命令、超时、URL、Header、环境变量和凭据映射；后端会再次执行相同的安全校验。格式错误的已有文件仍可在同一编辑器中修复，但不会被运行时加载。

## Hooks

```json
{
  "mcpServers": [],
  "hooks": [
    {
      "id": "external-guard",
      "phase": "before",
      "tool": "mcp__github__*",
      "command": ["node", ".k-coder/hooks/guard.mjs"],
      "timeoutMs": 10000,
      "enabled": true
    }
  ]
}
```

`phase` 为 `before`、`after` 或 `both`。Hook 从 stdin 读取单个 JSON 对象，并向 stdout 输出不超过 64 KiB 的单个 JSON 对象：

```json
{ "decision": "allow", "message": "", "output": null }
```

`decision: block` 会阻止工具。后置 Hook 可以用 `output` 替换返回给模型的文本。超时、非零退出、无效 JSON 和未知字段都会阻止工具。

## 诊断与审计

设置中心显示指令来源、Skill 风险、MCP 状态、工具数量、凭据状态、Hooks 和最近审计记录。审计保存在 `runtime-data/extension-audit.jsonl`，不包含密钥值。
