# Phase 8 多智能体评估

## 目标

验证多智能体只在任务边界独立时提供可测收益，同时不牺牲取消、权限、预算和写冲突安全。该评估不用于证明真实模型答案质量。

## 选定任务

确定性夹具把“检查后端”和“检查前端”视为两个独立只读任务。每个 Fake Provider 流包含两个间隔 100 ms 的事件，因此串行执行的理论下限为 400 ms。

并行验收条件：

- 两个任务都返回 `completed` 和结构化摘要。
- 总耗时低于 350 ms。
- 子智能体只获得 `list_directory` 和 `read_file`。
- 父级取消、20 ms 超时、Capability 越权、Token 超限和同路径并发写分别有关闭失败测试。

## 结果

确定性测试 `runs_independent_subagents_concurrently_and_returns_bounded_summaries` 通过；整个多智能体测试组在本机约 0.3 秒完成。并行夹具满足低于 350 ms 的阈值，相比串行理论下限至少减少 12.5% 等待时间，典型调度时间接近减半。

同路径写入测试确认：两个智能体使用同一修改前哈希时，仅第一个写入成功，第二个返回 `PatchError::Conflict`。取消和超时测试确认 Provider 流实际收到取消信号。

## 默认策略

多智能体工具可发现，但创建、跟进、恢复和关闭按外部风险请求审批，不允许静默自动委派。最大深度保持一层、并发上限保持 4。只有后续真实编程任务评估同时证明完成率和成本收益后，才考虑减少创建审批或提高限制。
