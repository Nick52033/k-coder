# 工具组手动展开保持验证

日期：2026-09-18。路线图任务：`P10-198`。

## 问题与修复

用户手动展开“执行了多个操作”后，后续调用会让它自动收起。存在两个原因：工具组的 React key 拼接了全部调用 ID，追加操作会重新挂载组件；`details.open` 只由活动状态控制，`onToggle` 保存的状态仅用于箭头，无法覆盖自动开合。

`ConversationActivity.tsx` 现在用组内首个调用 ID 维持组件身份，并使用“未选择 / 展开 / 收起”三种展示状态。鼠标和原生 summary 的 Enter/Space 激活显式记录选择；`open` 与箭头读取同一个最终状态。用户没有操作时维持现有自动开合，操作后同组新增调用、执行结束与失败都不会覆盖选择。新分组独立初始化。

状态仅存在当前组件生命周期中，切换后重新挂载或刷新不会保存手动选择。外层 Turn 执行过程继续按既有规则在终态收起；重新展开外层时，未卸载的工具组保留选择。工具执行、分组边界、领域事件、JSONL 与 Provider 历史没有改变。

## 隔离原生验收

脚本：`scripts/validate-tool-disclosure-native.cjs`。本地 SSE Provider 在真实文件工具批次之间暂停，以便在真实 WebView2 中点击展开，再继续追加成功及失败操作；最后检查 Turn 完成后工具组自身仍保留选择。脚本使用虚拟本地凭据，结束后删除测试 Provider 与凭据。

独立配置 `.tmp-ui/tool-disclosure/tauri.conf.json`：

```json
{
  "identifier": "com.kcoder.validation.disclosure",
  "build": {
    "beforeDevCommand": "pnpm dev --host 127.0.0.1 --port 1499",
    "devUrl": "http://127.0.0.1:1499"
  }
}
```

```powershell
$env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS = '--remote-debugging-port=9499'
$env:CARGO_INCREMENTAL = '0'
pnpm tauri dev --no-watch --config .tmp-ui/tool-disclosure/tauri.conf.json
# 原生客户端就绪后，另一个终端：
node scripts/validate-tool-disclosure-native.cjs
```

原生验收通过：4 次 Provider 请求、4 个真实文件操作，依次确认默认收起、手动展开、追加成功操作仍展开、追加失败操作仍展开、Enter/Space 开合，以及整轮完成后重新打开外层执行过程时工具组仍展开。原生验收使用正常动画设置。

首次启动遇到 Rust 增量缓存 `dep-graph.part.bin` / `query-cache.bin` 的路径不存在错误，禁用该次构建的增量缓存后成功启动。脚本首次执行还发现旧会话自动恢复工作区与测试切换发生竞争，导致新线程绑定错误目录；脚本改为先释放旧会话选择，再切换目录，并显式断言新线程绑定隔离目录及首批读取成功。修正后完整重跑通过，这些中间失败未计入验收通过。
