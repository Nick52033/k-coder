日期：2026-09-18。路线图任务：`P10-199`。原始证据见 [permission-fe 最新对话排查](permission-fe最新对话报错排查-2026-09-18.md)。

## 修复范围

1. 模型 `run_command` 经同一执行链路使用空设备 stdin，解决不带路径的 rg 等待宿主输入管道直至 120 秒超时。宿主 `start_command/write_stdin` 保持交互语义，PTY 不变。
2. 为 PowerShell 简单 rg 及单一 `Select-Object -First/-Last N` 输出限制增加保守的 `metadata.resultKind = no_matches`。仅完整输出为空、退出码 1 时分类；串联、动态语法、重定向、quiet/no-messages/pre、输出截断均不分类。界面显示中性「未匹配」，不计入工具组「包含失败」。原始退出码、`success=false`、审计与 Provider 历史保留。
3. 失败摘要优先显示超时、真实 stderr 解析错误及错误行。仅有 stdout 的失败展示退出码和「已有部分输出」，避免把成功段文件名当失败原因。stdout 中的 `ParserError` 字样也不会触发语法诊断。引号解析错误优先于通配符恢复提示；通配符提示须有 stderr 的 `os error 123` 证据。部分 pwsh 宿主不输出解析错误详情，此时不猜测原因。
4. 工具说明与系统指引要求搜索显式指定目录、单次搜索、PowerShell 字面量正则使用单引号、不隐藏 stderr、根据真实路径调整查询。

旧记录没有 `resultKind` 时不追溯推断「未匹配」，不会改写已存储事件；已有 stderr 元数据的旧记录可使用新的错误摘要。越界读取、缺失文件、命令语法错误、无效补丁和业务测试失败继续保留错误事实。没有修改 permission-fe 业务代码、文件权限策略或模型审批权限。
